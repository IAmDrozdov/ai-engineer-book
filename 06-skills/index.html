Глава 6 из 17, часть «Протоколы»

Agent Skills

В январе 2026 года Vercel положил документацию Next.js 16 в скилл и прогнал агента по своим evals. В 56% случаев агент скилл так и не открыл, и результат совпал с прогоном вовсе без документации: 53%. Тот же текст, ужатый до индекса на 8 КБ и вписанный в AGENTS.md, дал 100%1. Скилл — папка с markdown-файлом, которую агент открывает сам, когда сочтёт нужным.

Папка с одним обязательным файлом

Это скилл целиком, пример из документации Claude Code2. Файл кладётся по указанному пути, и больше ничего не нужно: ни регистрации, ни сервера, ни схемы аргументов. Спросишь в сессии «What did I change?» — модель увидит в списке доступных скиллов описание про незакоммиченные изменения и сама загрузит тело. Наберёшь /summarize-changes — загрузится то же самое, только решение примешь ты. Строку с git diff HEAD модель не увидит вообще: Claude Code выполнит команду раньше и подставит на её место вывод.

Скилл (Agent Skill, в русской речи чаще «скилл», реже «навык») — каталог, в котором обязателен один файл, SKILL.md: YAML-фронтматтер между маркерами --- и markdown-тело с инструкциями. Спецификация на agentskills.io предлагает три необязательных подкаталога и разрешает класть рядом что угодно ещё3:

Своего рантайма у скилла нет. Он не открывает соединений и не объявляет функций. Всё, что он «делает», делает модель обычными инструментами агента: читает файлы, запускает команды в шелле. Поэтому скиллы работают только там, где у агента есть файловая система и выполнение кода. В Claude Code это твоя машина, в Claude API — контейнер code execution, и без этого инструмента API скиллы не подключает4. У той же простоты есть цена: скрипт из скилла выполняется с правами агента, то есть с твоими (подробнее в разделе о безопасности).

I think skills are mainly just a formalization of the markdown plus CLI patterns that people have been using already. The only material difference with skills is that Claude knows to scan them for YAML descriptions on startup.
— Simon Willison (simonw), Hacker News, 17 октября 2025

За год это описание не устарело. Новое в скиллах не формат файла, а договорённость: харнесс сам сканирует папки, складывает описания в контекст, а тело подгружает по требованию.

Команды стали скиллами

Если у тебя в репозитории есть .claude/commands/, ты уже пишешь скиллы. В Claude Code v2.1.3 от 9 января 2026 года в changelog появилась строка «Merged slash commands and skills, simplifying the mental model with no change in behavior»5. Файл .claude/commands/deploy.md и каталог .claude/skills/deploy/SKILL.md оба создают /deploy и работают одинаково. Командный файл понимает тот же фронтматтер, кроме name и paths, но у него нет каталога для вспомогательных файлов, поэтому для новой команды документация советует сразу делать скилл. При совпадении имён побеждает скилл2.

Аргументы работают как раньше в командах. /fix-issue 123 подставит 123 на место $ARGUMENTS; $0, $1 берут отдельные аргументы с шелловыми кавычками; если плейсхолдера в теле нет, Claude Code допишет в конец ARGUMENTS: 123. Знак доллара перед цифрой в прозе экранируют: \$1.00. С v2.1.199 скиллы можно ставить цепочкой, /write-tests /fix-issue 123 загрузит оба и передаст 123 каждому2.

Куда класть свой скилл, решает, кто его увидит. ~/.claude/skills/ — во всех твоих проектах на этой машине, но не в облачных сессиях и не в Cowork. .claude/skills/ в репозитории — у всех, кто работает с репозиторием, после коммита. Каталог .claude/skills/ внутри подпапки монорепозитория подхватится, только когда агент прочитает или изменит файл в этой подпапке. Ещё есть плагины и управляемые настройки организации, о них в разделе о распространении.

Три уровня загрузки и их цена

17 августа 2026 года в changelog Claude Code v2.1.234 появилась строка: «Reduced the context cost of loading the built-in claude-api skill from ~200k+ tokens to ~25k by loading reference docs on demand»5. Скилл остался тем же, знания в нём тоже. Поменялось одно: справочные документы перестали ехать в контекст вместе с телом и стали читаться, когда понадобятся. Вызов подешевел в восемь раз.

Этот приём называется progressive disclosure — поэтапное раскрытие, и на нём держится вся идея скиллов. В инженерном блоге Anthropic, где скиллы описали в день анонса, 16 октября 2025 года, их сравнивают с руководством, «that starts with a table of contents, then specific chapters, and finally a detailed appendix»6. Оглавление лежит в контексте всегда. Главу открывают, когда она нужна. В приложение заглядывают, только если глава на него сослалась.

Цифры на рисунке — ориентиры из спецификации и документации Claude37. Руководство agentskills.io для авторов клиентов оценивает первый уровень в 50–100 токенов на скилл8, OpenClaw — примерно в 24 токена служебной разметки плюс имя, описание и путь9. Порядок один: тридцать установленных скиллов — это несколько тысяч токенов в каждом запросе. С кешированием промпта они дешёвые в деньгах, но место в окне и внимание модели занимают всё равно.

Со вторым уровнем важно другое. Спецификация говорит, что агент «will load this entire file once it's decided to activate a skill»3. Частичного чтения тела не бывает, поэтому всё, что нужно не в каждом вызове, из SKILL.md надо выносить. В Claude Code тело после загрузки остаётся в истории до конца сессии, и документация называет каждую его строку «a recurring token cost»2.

Самый недооценённый уровень — третий, точнее его половина со скриптами. Документация Claude описывает это так: «When Claude runs validate_form.py, the script's code never loads into the context window. Only its output … consumes tokens»7. Валидатор на четыреста строк обходится в контексте ровно в столько, сколько весит его JSON на выходе. Инженерный блог добавляет довод про надёжность: сортировать список генерацией токенов «far more expensive than simply running a sorting algorithm»6. Всё детерминированное — разбор файлов, проверки, преобразования форматов — стоит держать в скриптах, а в теле оставить, когда и как их вызывать.

В Claude API отдельного инструмента для активации нет: там, где на схеме стоит вызов Skill, модель читает SKILL.md тем же bash-инструментом code execution. Пример из блога Anthropic так и выглядит: в контексте системный промпт, метаданные скиллов и сообщение пользователя; Claude вызывает bash, чтобы прочитать pdf/SKILL.md; потом решает прочитать ещё и forms.md; потом делает работу6. Разница между «прочитать файл» и «вызвать специальный инструмент» важна для харнесса (права, подсчёт использования, защита от компакции), но не для автора скилла.

За экономию токенов платишь ходами

Каждый уровень — это ещё один вызов инструмента и ещё один круг через модель, то есть задержка и шанс, что модель на этом шаге решит обойтись без чтения. Если скилл нужен в каждой второй задаче и тело у него короткое, три шага вместо нуля — плохой обмен. Внешний замер это подтверждает: в отчёте Workday о продовых агентах поэтапное раскрытие «improves skill-retrieval quality but marginally degrades overall latency»10. Это же показала история Vercel из вводки, она разобрана в разделе о выборе механизма.

Второй подвох — вложенность. Если тело ссылается на файл, а тот на другой, Claude, по словам руководства Anthropic для авторов, «might use commands like head -100 to preview content rather than reading entire files»11. Модель честно «прочитала» справочник и не увидела ничего ниже сотой строки. Отсюда правило из спецификации: ссылки из SKILL.md идут на один уровень вглубь, не больше3. Длинному справочному файлу ставь оглавление в начало: даже при чтении первых ста строк модель узнает, что ещё в нём есть.

В Claude API список скиллов рендерится в системный промпт в фиксированном порядке. Один и тот же набор container.skills даёт попадание в кеш, другой набор — промах4. Если в разных запросах одного диалога ты подставляешь разные скиллы «по ситуации», ты каждый раз платишь за префикс заново.

Почему скилл не срабатывает

Через два дня после анонса пользователь Hacker News под ником rane пожаловался, что его скилл для bash не вызывается даже на прямую просьбу написать bash-скрипт. Приписка «CRITICAL:» в начале описания тоже не помогла.

So far not impressed with CC's ability to invoke skills automatically. I made a skill with the unambiguous description: "Use when creating or editing bash scripts" Yet, Claude does not invoke the skill when asked to write a bash script.
— rane, Hacker News, 18 октября 2025

Уиллисон ответил в том же треде догадкой: писать bash — ядро работы Claude Code, про инструмент Bash написана большая часть системного промпта, и модель, видимо, считает, что справится без подсказок. Догадка не проверена, но правило из неё выходит рабочее: чем ближе задача к тому, что модель умеет и так, тем реже она потянется к скиллу.

Через год Anthropic пишет то же самое о своей модели прямым текстом. В инструкции скилла skill-creator, которым Anthropic предлагает писать другие скиллы, есть абзац: «currently Claude has a tendency to „undertrigger“ skills — to not use them when they'd be useful. To combat this, please make the skill descriptions a little bit „pushy“»12.

Решает модель, а не классификатор

Между запросом и скиллом нет ни эмбеддингов, ни поиска по ключевым словам. Харнесс кладёт в контекст каталог: имя, описание, иногда путь. Дальше модель решает, вызвать ли инструмент, ровно так же, как решает, звать ли grep. Руководство agentskills.io для авторов клиентов приводит каталог в таком виде8:

Отдельный инструмент есть у Claude Code (Skill), у Gemini CLI (activate_skill, и перед активацией там ещё спрашивают согласия пользователя) и у OpenCode (skill({ name }))21314. Точный формат листинга в Claude Code не документирован и меняется от версии к версии; документированы инструмент Skill, правила доступа к нему (Skill(commit), Skill(deploy *)) и бюджет листинга.

Бюджет листинга

Описания всех скиллов Claude Code держит в одном листинге, и у листинга есть потолок: 1% контекстного окна модели. Каждая запись (description плюс when_to_use) дополнительно обрезается до 1 536 символов. Когда скиллов становится много и листинг не влезает, Claude Code выбрасывает описания, начиная со скиллов, которые ты вызываешь реже всего. Имена остаются, описания пропадают2.

Из этого правила следует неприятная петля. Редкий скилл теряет описание, без описания модель его почти не находит, и он становится ещё реже. Хуже всего приходится узким скиллам, которые нужны раз в неделю, то есть как раз тем, ради которых знания и держат на диске, а не в контексте. У Codex похожий механизм: 2% контекста или 8 000 символов, и при переполнении сначала укорачиваются описания15.

Что с этим делать в Claude Code:

  • строка Skills в /context показывает размер листинга уже после обрезки, то есть ровно то, что получает модель (до v2.1.196 там был полный размер всех описаний, в разы больше реального);
  • /doctor оценивает стоимость листинга и называет самых крупных участников, а при переполнении Claude Code пишет предупреждение в лог --debug;
  • skillListingBudgetFraction поднимает потолок (0.02 — 2%), skillListingMaxDescChars меняет лимит на запись;
  • в skillOverrides второстепенные скиллы переводятся в "name-only", чтобы их описания не отъедали место у важных2.

Молчаливые провалы

Самые неприятные случаи — когда скилл вроде бы на месте, но не может сработать никогда. Claude Code читает фронтматтер, только если открывающий --- стоит первой строкой файла; иначе весь файл, маркеры включительно, становится телом. Если YAML между маркерами не разбирается, скилл загружается с пустыми полями. В обоих случаях /name работает, а автоматический вызов — нет, потому что модели нечего сопоставлять с запросом. Ошибку разбора видно только с --debug, а битые файлы разом находит claude plugin validate .claude/skills (с v2.1.233)2.

Типичный способ сломать YAML — двоеточие в описании. Строка description: Use this skill when: the user asks… для парсера YAML — ошибка. Руководство agentskills.io советует авторам клиентов на такой случай запасной разбор с автоматическим закавычиванием8, но полагаться на то, что конкретный клиент это делает, не стоит. Бери описание в кавычки. Весь порядок проверки собран на схеме диагностики.

Обратный сбой: скилл срабатывает не там

Описание работает в обе стороны. Слишком широкое срабатывает на посторонних запросах и отбирает вызовы у соседнего скилла. Руководство Anthropic для компаний выделяет это в класс проблем Coexistence и требует проверять новый скилл и в одиночку, и вместе с уже установленными16. Лечится сужением: описание конкретнее, paths для скилла, привязанного к части репозитория, disable-model-invocation: true для того, что нужно только по команде2. Отрицательные запросы для проверки вызова (о них в разделе об авторстве) гоняй по всем установленным скиллам сразу: near-miss, который твой скилл правильно пропустил, мог перехватить соседний.

Сколько скиллов не срабатывает на самом деле

Прямых замеров мало. Самый чистый — у Vercel: в их наборе задач по Next.js 16 скилл с документацией не вызывался в 56% прогонов1. Отчёт Skill Crossroads от 10 сентября 2026 года прогнал 216 публичных скиллов для Claude Code из 18 репозиториев через линтер и насчитал 69% описаний, которые «won't reliably trigger», из них 40% (87 скиллов) не прошли проверку совсем17. Это оценка по рубрике, а не измеренная доля вызовов, но направление с Vercel и с признанием в skill-creator совпадает.

Сколько скиллов ставить, Anthropic не говорит. Руководство для компаний советует ограничивать число одновременно загруженных скиллов, чтобы модель их надёжно находила, и прекратить добавлять, «when performance degrades», замерив это своими evals16. Скептики говорили об этом с первого дня.

Anything the model chooses to use is going to waste context and get utilized poorly. Also, the more skills you have, the worse they're going to be. It's subagents v2. Just use slash commands, they work a lot better.
— CuriouslyC, Hacker News, 16 октября 2025

Позиция крайняя, но в ней есть рабочая часть. Скилл, который ты всё равно вызываешь руками, честнее пометить disable-model-invocation: true: он перестанет занимать листинг и не будет вызываться невпопад.

С сентября 2026 года для уборки есть /skill-doctor (changelog v2.1.261, 4 сентября): он показывает, во что обходится каждый скилл в листинге и как часто его вызывают, и отмечает те, что не вызывались ни разу5. Встроенные и корпоративные скиллы в отчёт не попадают.

Открой /skill-doctor, отключи через skillOverrides всё, что ни разу не вызывалось, и сравни строку Skills в /context до и после. Для скиллов, которые должны срабатывать сами, заведи пять-шесть запросов, на которых они обязаны вызваться, и прогоняй их после каждой правки описания.

Что происходит после вызова

В документации Claude Code есть абзац для тех, кому кажется, что скилл «отвалился» посреди задачи: «If a skill seems to stop influencing behavior after the first response, the content is usually still present and the model is choosing other tools or approaches»2. Модель просто перестала следовать тексту, потому что рядом накопились другие сигналы.

Механика такая. Отрендеренное тело SKILL.md входит в разговор одним сообщением и остаётся там на последующих ходах. Файл Claude Code больше не перечитывает. Отсюда совет документации писать в теле «standing instructions rather than one-time steps»: «перед каждым коммитом в этой задаче гоняй тесты», а не «сначала прогони тесты». Второй вариант модель выполнит один раз и будет считать исполненным.

Если ты поправил файл скилла посреди сессии, листинг обновится сам: Claude Code следит за каталогами скиллов. Тело в истории — нет. Оно останется старым, пока скилл не вызовут снова. При повторном вызове Claude Code сравнивает рендер с тем, что уже в контексте. Если текст тот же, модель получает короткую пометку, что скилл уже загружен. Если другой (поменялись аргументы, вывод !-команды или сам файл), в историю ложится ещё одна полная копия2. Скилл, который подставляет свежий git diff, при каждом вызове добавляет себя целиком.

Права живут меньше текста. Разрешения из allowed-tools действуют только в тот ход, в котором скилл вызвали, и снимаются, как только ты отправишь следующее сообщение. disallowed-tools и model из фронтматтера тоже действуют до конца хода. Инструкции остаются, а разрешение на git commit без вопроса — нет; чтобы вернуть его, скилл вызывают снова. Дольше всех живут hooks: хук из скилла работает до конца сессии2.

Компакция оставляет пять скиллов

Когда окно заполняется, Claude Code сжимает историю в сводку (как устроена компакция в целом, разобрано в главе 2). Скиллы при этом не пропадают, но переживают её по жёстким правилам: после сводки заново прикрепляется последний вызов каждого скилла, от него берутся первые 5 000 токенов, а на все прикреплённые скиллы вместе отведено 25 000. Бюджет заполняется начиная с последнего вызванного скилла, поэтому более ранние «can be dropped entirely»2.

Из правил и рисунка следуют два вывода для автора. Всё важное ставь в начало SKILL.md: у длинного скилла после компакции останется только голова. И если задача длинная, а скиллов за сессию вызывалось много, после компакции нужный скилл стоит вызвать повторно. Когда поведение должно соблюдаться всегда, независимо от того, помнит ли модель текст, документация советует не скилл, а хук: его выполняет харнесс, а не модель2.

Команды, которые выполняются до модели

Строка вида !`команда` в начале строки или после пробела и блок, открытый как ```!, выполняются при рендере скилла, до того как текст увидит модель. Вывод встаёт на место плейсхолдера и повторно не сканируется. Выполнение идёт тем же инструментом Bash, что и у модели, с теми же правилами2:

  • рабочий каталог — текущий каталог сессии, и он сдвигается, если модель сделала cd, поэтому пути к своим файлам строят от ${CLAUDE_SKILL_DIR} или ${CLAUDE_PROJECT_DIR};
  • stderr смешивается со stdout и тоже попадает в текст;
  • таймаут две минуты;
  • ненулевой код выхода отменяет весь вызов с ошибкой Shell command failed for pattern "...", и модель не видит скилл вообще; исключение — код 1 у команд поиска и сравнения вроде grep и diff;
  • каждая команда проходит проверку по правилам доступа; запрет или правило «спросить» (вне auto mode) тоже отменяют вызов, с ошибкой Shell command permission check failed for pattern "...". Спросить разрешения при рендере Claude Code не может, поэтому команды заранее одобряют через allowed-tools.

В наброске важна строка с alembic check. Эта команда нарочно завершается с ошибкой, если нашла изменения моделей без миграции: так её встраивают в CI18. Без || true скилл отменялся бы ровно тогда, когда он нужнее всего, и ты видел бы ошибку рендера вместо предупреждения про миграцию. Строка allowed-tools здесь не для удобства: без неё проверка прав при рендере оборвала бы вызов на первой же команде, если git diff не разрешён у тебя глобально.

Документация советует дописывать || true к любой команде, которая может законно вернуть ненулевой код, например к проверке, которая выходит с 1, когда нашла проблемы. Для организаций есть рубильник "disableSkillShellExecution": true в управляемых настройках: вместо каждой команды в текст подставится [shell command execution disabled by policy]. Встроенные и корпоративные скиллы он не трогает.

Скилл в отдельном сабагенте

Поле context: fork меняет всё выше. Скилл больше не встаёт в твой разговор: Claude Code запускает новый сабагент типа из поля agent (по умолчанию general-purpose, можно Explore, Plan или свой из .claude/agents/), и тело скилла становится его промптом. Документация специально предупреждает о названии: это не форк текущего разговора, историю сабагент не видит2. Отличия от обычного вызова сведены на рисунке. Как устроены сабагенты сами по себе, разобрано в главе 12.

С v2.1.218 от 22 июля 2026 года форк по умолчанию работает в фоне, и результат приходит, когда готов. background: false возвращает ожидание в том же ходе. В неинтерактивном режиме (-p, Agent SDK) и в запланированных задачах Claude Code ждёт в любом случае52. Встроенные Explore и Plan не читают CLAUDE.md и git status, так что скилл с agent: Explore видит только свой текст и системный промпт агента. А скилл, в котором одни правила без задачи («используй такие-то соглашения API»), в форке бессмыслен: документация предупреждает, что сабагент получит правила, не получит задания и вернётся ни с чем.

Есть и обратное направление. В определении своего сабагента можно перечислить скиллы в поле skills, и тогда их тела целиком загрузятся при его старте, как справочный материал, без всякого листинга и выбора2. Задача с понятным результатом, которую не жалко отдать без контекста, — форк; знания, которые нужны специализированному агенту всегда, — предзагрузка.

Скиллы вне терминала: API, SDK, Managed Agents

От обычного запроса этот отличается двумя местами. В container.skills перечислены скиллы, до 20 штук на запрос. В tools стоит инструмент code execution, без которого скиллу негде жить: его файлы копируются в песочницу по пути /skills/{имя}/, и модель читает их тем же bash, которым потом выполняет скрипты4. Каталог называется по name из SKILL.md, а не по идентификатору skill_01…, так что пути внутри скилла от способа загрузки не зависят. Весь путь от загрузки до готового файла — на схеме ниже.

Скиллы бывают двух типов. anthropic — готовые pptx, xlsx, docx и pdf с версией-датой вроде 20251013 или latest. custom — твои, с идентификаторами skill_01… и версиями skver_01…. Схема запроса у них одна.

Актуальных версий code execution на сентябрь 2026 года три: code_execution_20250825 (bash и файловые операции), code_execution_20260120 (плюс сохранение состояния REPL и programmatic tool calling) и code_execution_20260521 — тот же рантайм, но описание инструмента сообщает Claude о лимите в 90 секунд на одну Python-ячейку. Все три принимаются без beta-заголовка. Примеры в документации по скиллам используют первую, а свежим web_search_20260209 и web_fetch_20260209 нужна как минимум вторая19.

Песочница без сети

Контейнер code execution — Python 3.11 на Linux x86_64, 5 ГиБ памяти, 5 ГиБ диска, один CPU и никакого интернета. Ставить пакеты во время работы нельзя, доступны только предустановленные194. Контейнер живёт 30 дней с момента создания, после пяти минут простоя его замораживают, и запрос с тем же container.id его поднимает. Первые 1 550 часов в месяц на организацию бесплатны, дальше $0,05 за час на контейнер.

Для автора скилла это главное расхождение с Claude Code. Локально скилл ходит в сеть и ставит пакеты, в API тот же SKILL.md не сможет ни того ни другого. Том Макрайт описал это через четыре дня после анонса: в облаке у скиллов «a minimal environment with Python, a few packages, and no ability to install extra dependencies», и скиллу трудно быть переиспользуемым, если он должен работать в двух настолько разных средах20. Если скилл нужен и там и там, укажи требования в compatibility и проверь его в контейнере отдельно.

В третьей среде, приложении claude.ai, сеть у скилла, по документации, «full, partial, or no network access» в зависимости от настроек пользователя и администратора7:

Загрузка и версии

Загрузка — multipart-запрос POST /v1/skills с файлами каталога, не больше 30 МБ в распакованном виде. Каждая новая версия — полный снимок, а не дельта: файл, который ты не приложил, в новую версию не попадёт4. Если собираешь загрузку в CI из списка изменённых файлов, получишь скилл без половины скриптов. CLI ant apply financial_skill загружает каталог целиком, и в CI надёжнее звать его4.

Открытый стандарт и его швы

Положи скилл deploy в ~/.claude/skills/ и одноимённый в .claude/skills/ репозитория. Claude Code на /deploy запустит твой личный: у него корпоративный уровень выше личного, а личный выше проектного2. Руководство agentskills.io для авторов клиентов считает правильным обратный порядок и называет «project-level skills override user-level skills» «the universal convention»8. Gemini CLI и OpenClaw так и делают139. Codex одноимённые скиллы вообще не сливает и показывает в выборе оба15. Три порядка рядом — на рисунке.

Сам стандарт устроен проще, чем можно подумать по слову «стандарт». 18 декабря 2025 года Anthropic объявила: «We've published Agent Skills as an open standard for cross-platform portability»23. Спецификация на agentskills.io — одна страница без номера версии: шесть полей, свободное тело, три рекомендованных каталога, поэтапное раскрытие, ссылки в один уровень и валидатор skills-ref3.

Что переносится, а что нет

Гарантированно переносятся имя, описание, тело и файлы по относительным путям, остальное у каждого клиента своё. VS Code понимает часть полей Claude Code: argument-hint, user-invocable, disable-model-invocation и экспериментально context: fork. Cursor — paths, disable-model-invocation, а ещё свои icon и color2526. OpenCode признаёт только name, description, license, compatibility и metadata, а прочее молча пропускает, allowed-tools тоже14. В VS Code, по его документации, имена со слешем, двоеточием или префиксом пространства имён «cause the skill to silently fail to load»25.

Codex выносит свои расширения в отдельный файл рядом с SKILL.md, и это самый аккуратный вариант из существующих: спецификацию он не трогает15.

allow_implicit_invocation: false — аналог disable-model-invocation, а блок dependencies отвечает на вопрос, которого спецификация не задаёт: какие MCP-серверы нужны скиллу для работы. OpenClaw решает ту же задачу через metadata.openclaw.requires и попутно нарушает спецификацию: там metadata — вложенный объект, а не словарь строк9. Версий, подписи и зависимостей в спецификации нет, и каждый клиент дописывает их по-своему.

Насколько это стандарт? В репозитории agentskills/agentskills нет документа об управлении, предложения принимаются через GitHub Discussions, в README сказано «Logo requests are reviewed by the Anthropic team», а больше всех коммитов в спецификацию (91) у одного человека24. Стандарт Agent Plugins, который упаковывает скиллы вместе с MCP-серверами, управляется техническим комитетом из Amazon, Cursor, Microsoft, OpenAI и Vercel, без Anthropic, и требует plugin.json в корне и mcp.json27. Плагин Claude Code держит манифест в .claude-plugin/plugin.json, а серверы в .mcp.json2, так что между двумя форматами переносится только каталог skills/. Пиши на шести полях спецификации всё, что должно работать везде, а расширения конкретного клиента держи там, где их можно выбросить без потери смысла. Как устроено управление MCP для сравнения, разобрано в главе 5.

Скилл, MCP, сабагент, команда, CLAUDE.md

«This is coming late as skills have largely replaced MCP. Now your site can just host a SKILL.md to tell agents how to use the site», — написал на Hacker News пользователь charcircuit 16 февраля 2026 года (комментарий). Семь месяцев спустя, 11 сентября, у MCP появилось официальное расширение, через которое MCP-серверы раздают скиллы. Утверждение «скиллы заменили MCP» к осени 2026 года устарело в самой неожиданной форме: MCP стал одним из способов доставки скиллов.

Откуда взялось «скиллы заменят MCP»

Источник — пост Саймона Уиллисона в день анонса, «Claude Skills are awesome, maybe a bigger deal than MCP». Довод там про токены. Официальный MCP-сервер GitHub «famously consumes tens of thousands of tokens of context», а скилл в листинге «only takes up a few dozen extra tokens». И второй довод: «LLMs know how to call cli-tool --help», так что инструмент, который у агента уже есть в шелле, не нужно описывать схемой заранее28. На HN он предлагал вместо MCP-сервера скилл, который ходит в api.github.com через curl с токеном из GITHUB_API_KEY (17 октября 2025).

Правда в этом доводе такая. Если агент уже умеет делать что-то через шелл и CLI, скилл с процедурой дешевле MCP-сервера, чьи схемы висят в контексте на каждом ходе (как с этим борются на стороне MCP, разобрано в главе 5). Для бэкендера это частый случай: gh, psql, kubectl, alembic модель знает, и ей нужна не схема, а твои правила работы с ними.

Неправда начинается там, где у агента нет шелла или где нужен доступ с авторизацией. Возражения прозвучали в том же треде, и одно — от самого Уиллисона:

Yeah, the biggest advantages MCP has over terminal tooling is that MCP works without needing a full blown sandboxed Linux style environment - and MCP can also work with much less capable models.
— Simon Willison, Hacker News, 17 октября 2025
MCP is also about consuming external services handling oauth and all of that. Skills are effectively cli tools + prompts.
— _pdp_, Hacker News, 17 октября 2025

Скилл с curl и токеном в переменной окружения означает, что токен лежит в шелле агента и доступен любой команде, которую модель решит выполнить. MCP-сервер держит авторизацию у себя, и хост видит каждый вызов как отдельную операцию с понятными аргументами. А в песочнице Claude API сети нет совсем, и скилл при всём желании не достучится до твоей системы.

Точнее всех сказал samdjstephens: «MCP is about integration of external systems and services. Skills are about context management - providing context on demand» (HN, 17 октября 2025). Эти механизмы складываются. Скилл может описывать процедуру поверх MCP-инструментов, и руководство Anthropic требует называть их полностью, в формате ServerName:tool_name: «Use the BigQuery:bigquery_schema tool to retrieve table schemas». Без префикса сервера Claude может не найти инструмент, когда подключено несколько серверов11.

Скиллы поверх MCP

Расширение io.modelcontextprotocol/skills (SEP-2640) написано для базовой ревизии MCP 2026-07-28 и получило статус Final 11 сентября 2026 года, а PR с ним влили 13-го2953. Формат скилла оно целиком берёт из спецификации Agent Skills и добавляет только транспорт. Каждый файл скилла становится MCP-ресурсом с адресом вида skill://pdf-processing/SKILL.md. Сервер объявляет расширение в capabilities и обязан поддержать два метода: skills/list и skills/get. Ответ на листинг — не краткая сводка, а полный манифест, у каждого файла SHA-256 и размер:

Хосту запрещено заранее скачивать файлы: SKILL.md читается обычным resources/read при активации, остальное — когда модель к нему обратится. Каждое чтение сверяется с размером и дайджестом из манифеста, а фронтматтер — с тем, что пришёл в листинге. Лимиты — 512 файлов и 16 МиБ на скилл. Чтение SKILL.md через resources/read спецификация называет транспортом, а не активацией: активирует только штатный механизм хоста29.

Самая содержательная часть расширения — раздел безопасности, и он многое говорит о скиллах вообще. Хост обязан считать скиллы из MCP «a higher-risk surface than remote tool invocation»: инструмент на сервере выполняет код на сервере, а скилл приносит текст, который велит модели выполнить код у тебя. Поэтому исполнение кода на хосте разрешено только после явного одобрения конкретного скилла, allowed-tools из такого скилла игнорируется, пока пользователь не одобрил именно это расширение прав, а скилл с сервера A не может заставить хост читать ресурсы сервера B. Скилл из MCP не имеет права молча перекрыть одноимённый локальный, и модель должна видеть, откуда он пришёл. Спецификация отдельно предупреждает: «Digests are not a trust anchor»29.

Поддержка пока ранняя. По таблице реализаций на 29 сентября 2026 года сервер сделали Hugging Face и прототип в github-mcp-server, частичная поддержка у хостов MCP Inspector, fast-agent, MCPJam и плагинов ChatGPT, официальные SDK — «in progress»30. Claude в этой таблице нет. При этом справка Anthropic по сканированию упоминает «skills shared through a connected MCP server», так что какой-то путь существует, но публично не описан.

В посте о плагинах от 25 сентября 2026 года Anthropic раскладывает роли так: плагины упаковывают «MCP connectors, Agent Skills, or both», а сами «Skills and MCP connectors stay as building blocks»31.

Документация Claude Code говорит то же своими словами: делай скилл, когда раз за разом вставляешь в чат одну и ту же инструкцию или чеклист, или когда раздел CLAUDE.md «has grown into a procedure rather than a fact»2. Факты о проекте — в CLAUDE.md, процедуры — в скиллы. Рабочая связка из двух: короткая строка в CLAUDE.md вида «миграции делай через скилл alembic-migration» и сама процедура в скилле. Строка стоит пару десятков токенов на ходу и снимает проблему недовызова, процедура не занимает контекст, пока не нужна.

Сабагент и команда

С сабагентами путаница меньше. Лучшая короткая формулировка — «Subagents have their own context. Skills do not» (rahimnathwani, HN, 16 октября 2025). Скилл — это данные, которые попадают в чей-то контекст. Сабагент — отдельный исполнитель со своим контекстом, моделью и инструментами. Соединяются они через context: fork и через поле skills в определении сабагента, как описано выше.

С командами путаницы в Claude Code больше нет совсем: команда — это скилл, который вызываешь ты. Хочешь, чтобы его вызывал только ты, — ставь disable-model-invocation: true. Все механизмы сведены в таблицу, а порядок выбора — в схему под ней.

Спор о MCP не утих и к осени 2026 года. «MCP isn't going anywhere… Skills, etc do not replace MCP», — пишет MitziMoto (HN, 1 января 2026). «MCP is the wrong abstraction for all of that. Skills are better as pluggable interfaces», — отвечает kaoD 21 сентября (HN) и сам оговаривается, что его «predict» значит «hope». Для своего сервиса сделай так: если у агента есть шелл и нужный CLI, начни со скилла; если доступ нужен из среды без шелла, с OAuth от имени пользователя или с аудитом каждого вызова, делай MCP-сервер и положи рядом скилл с процедурой. Оценка изменится, когда хосты начнут поддерживать SEP-2640 целиком: тогда сервер будет раздавать и инструменты, и процедуры к ним одним подключением.

Как написать скилл, который помогает

13 февраля 2026 года 78 авторов выложили на arXiv SkillsBench: 86 задач в 11 доменах, детерминированные проверки результата, прогоны одних и тех же задач со скиллами и без. Главный вывод первой версии уложился в одну фразу: «Self-generated Skills provide no benefit on average». Скиллы, которые модель написала себе сама, в среднем не дали ничего. Написанные людьми дали +16,2 п.п., но с огромным разбросом по доменам, и в 16 задачах из 84 со скиллом стало хуже32.

Четвёртая версия от 14 июня (обе версии на графике) расширила замер до 18 конфигураций «модель плюс харнесс»: 33,9% без скиллов против 50,5% со скиллами, от +4,1 до +25,7 п.п. в зависимости от конфигурации. И добавила вывод: «Focused Skills with at most three modules outperform larger or exhaustive bundles, and smaller models with Skills can match larger models without them»32. Узкий скилл лучше энциклопедии.

Контролируемое исследование Сюй и У на 30 задачах SkillsBench, по пять прогонов на ячейку, развело два фактора. Само наличие скилла дало +26,7…36,0 п.п. для GPT-5.5 и +18,0…26,0 п.п. для DeepSeek V4-Flash. А подача влияла слабо: разница между абстрактной и приземлённой инструкцией и эффект одного добавленного примера укладываются в несколько пунктов, и доверительные интервалы пересекают ноль33. Важнее, чтобы скилл был и вызывался, чем то, в каком стиле он написан.

Скилл «как писать хороший FastAPI-код» почти ничего не добавит, а скилл про то, как в вашей команде оформляют миграции и чем тестовая база отличается от боевой, добавит много: этого модель знать не может. В посте о skill-creator Anthropic делит скиллы на два вида. Скиллы «capability uplift» дотягивают модель до того, чего она пока не умеет, и с новыми моделями могут стать ненужными; понять это помогают evals, а с v2.1.283 ещё и /doctor prompt-audit, который ищет в скиллах, CLAUDE.md и агентах приёмы, написанные для старых моделей5. Скиллы «encoded preference» записывают принятый у вас процесс, и живут столько, сколько процесс, а ценность их определяется тем, насколько точно они ему следуют34.

Большинство скиллов в открытом доступе написаны плохо, и это измерено. Авторы исследования 138 133 публичных файлов SKILL.md из 20 556 репозиториев (9 августа 2026) нашли хотя бы один дефект в 91,8% из них: слабое описание для маршрутизации, раздутое тело, беспорядок во вспомогательных файлах. Скиллы, написанные с оглядкой на спецификацию, дефектны реже35.

Описание

Описание — единственное, что модель видит, когда решает, звать ли скилл. Руководство Anthropic требует писать его в третьем лице («Processes Excel files…», а не «I can help you…»), потому что оно подставляется в системный промпт, и смена лица мешает поиску. Оно должно говорить и что скилл делает, и когда его применять. Плохие примеры оттуда же — description: Helps with documents, Processes data, Does stuff with files. Имя там же советуют давать в форме герундия, processing-pdfs, а не расплывчатое helper или utils11. В skill-creator Anthropic приводит пример «напористого» описания. Было «How to build a simple fast dashboard to display internal Anthropic data», стало с хвостом: «Make sure to use this skill whenever the user mentions dashboards, data visualization, internal metrics, or wants to display any kind of company data, even if they don't explicitly ask for a „dashboard.“»12.

Хвост «even if they don't explicitly ask» — главное. Пользователь редко называет задачу так, как её назвал автор скилла. Он пишет «добавь поле tier в пользователя», а не «сделай миграцию». Описание должно перечислять формулировки, которыми задачу ставят, а не только её официальное имя. В Claude Code первым ставь главный сценарий: запись режется на 1 536 символах, а при нехватке бюджета описание может пропасть целиком.

В этом наброске собраны почти все правила раздела. Описание в третьем лице, с формулировками пользователя. Тело короткое: модель знает Alembic, ей нужны только ваши правила. Шаг 1 задан точной командой, шаг 4 — проверка, которую модель выполнит сама. Раздел про подводные камни — самое ценное: autogenerate действительно не видит переименований столбцов и выдаёт вместо них удаление и добавление18. Справочник вынесен в отдельный файл на один уровень вглубь. ${CLAUDE_SKILL_DIR} — подстановка Claude Code, она работает и в allowed-tools, поэтому в ходе вызова свой скрипт скилл запускает без запроса разрешения2. В других клиентах путь к скрипту придётся писать иначе.

Проверка вызова

Проверку описания подробно расписывает руководство agentskills.io. Около 20 запросов: 8–10 должны вызывать скилл, 8–10 не должны. Самые ценные отрицательные примеры — «near-misses»: запросы с теми же словами, которым на самом деле нужен другой скилл или никакой. Каждый запрос гоняй трижды, потому что модель недетерминирована, и считай долю вызовов. Запросы раздели примерно 60 на 40: по первой части правь описание, по второй проверяй, что правка обобщается, а не подогнана под конкретные фразы36. Краткость и степени свободы

Первое правило руководства Anthropic: «Claude is already very smart», добавляй только то, чего модель не знает. Пример оттуда: фрагмент про извлечение текста из PDF с объяснением, что такое PDF и зачем библиотеки, стоит около 150 токенов, а тот же фрагмент одним вызовом pdfplumber — около 5011. Проверка на каждую строку: ошибётся ли модель без неё. Руководство agentskills.io уточняет, что самое ценное содержимое многих скиллов — список подводных камней, «environment-specific facts that defy reasonable assumptions». Пример оттуда просится в любой бэкенд: эндпоинт /health отвечает 200, пока жив веб-сервер, даже если соединения с базой нет, и полное здоровье сервиса показывает /ready37. Такие вещи держи прямо в SKILL.md: в отдельном файле модель может не понять, что его пора открыть. А условий с датами вроде «до августа 2025 года используй старый API» в теле быть не должно: устаревшее руководство Anthropic советует уносить в свёрнутый раздел «old patterns»11.

С хрупкими операциями правило другое: чем легче всё сломать, тем точнее инструкция. Anthropic называет это степенями свободы. Для ревью кода достаточно списка того, на что смотреть; для шаблона отчёта — псевдокода с параметрами; для миграции базы — точной команды:

Anthropic объясняет выбор картинкой: узкий мост с обрывами по обе стороны против открытого поля без препятствий. На мосту нужны перила и точные указания, в поле хватит направления. И ещё одно правило оттуда же, которое легко пропустить: «What works perfectly for Opus might need more detail for Haiku»11. Если скилл будет работать в сабагенте на дешёвой модели, проверяй его на этой модели. Руководство для компаний делает это условием выкладки: 3–5 запросов на скилл (должен сработать, не должен, пограничный случай) на всех моделях, которыми пользуется организация16.

Скрипты, которые пишут для агента

Скрипт в скилле запускает не человек, и это меняет требования. Руководство agentskills.io их перечисляет38. Никаких интерактивных вопросов: агент работает в неинтерактивном шелле, и скрипт, ждущий ввода, «will hang indefinitely». Интерфейс описывается в --help, потому что оттуда агент его и узнаёт. Данные идут в stdout в структурированном виде, диагностика — в stderr. Разные ошибки — разные коды выхода. Для разрушительных операций нужен --dry-run. Размер вывода предсказуемый: многие харнессы обрезают вывод инструмента после 10–30 тыс. символов. Руководство Anthropic добавляет «solve, don't defer»: ошибку, которую можно обработать в скрипте, обрабатывай в скрипте, а не оставляй модели на импровизацию. И никаких «voodoo constants»: TIMEOUT = 47 без объяснения, откуда 47, модель не сможет ни проверить, ни поправить11.

Проверки в наброске грубые, по строкам, и многострочный вызов op.add_column они пропустят. Но интерфейс сделан для агента: без вопросов, JSON с номерами строк на выходе, 1 при находках и 2 при неверном пути. Сколько бы строк ни было в таком скрипте, в контекст они не попадут: модель увидит одну строку JSON. Для пакетных и разрушительных операций Anthropic советует тот же приём в более общей форме: сначала модель пишет план изменений в файл вроде changes.json, скрипт его проверяет, и только потом план выполняется.

Живые образцы этих приёмов лежат в репозитории anthropics/skills, 19 скиллов на 30 сентября 2026 года. В pdf напористое описание («Use this skill whenever the user wants to do anything with PDF files») и условная ссылка вместо лишнего текста в теле: «If you need to fill out a PDF form, read FORMS.md». В webapp-testing скрипты работают как чёрный ящик: тело велит сначала звать --help и «DO NOT read the source», потому что большие скрипты «pollute your context window». README предупреждает, что это учебные образцы: поведение Claude в продукте может отличаться от показанного39.

Evals до документации

Anthropic советует начинать не с текста, а с замера: «Create evaluations BEFORE writing extensive documentation». Порядок такой: реши задачи без скилла и запиши, где модель ошибается; напиши три-пять сценариев на эти ошибки; сними базовую линию; напиши минимальные инструкции, которые закрывают пробелы; повторяй11. Там же описан цикл «Claude A / Claude B». Один экземпляр помогает писать скилл, второй, в чистой сессии, его использует, а наблюдения за вторым ты приносишь первому. Документация Claude Code оговаривает: «Seeing a skill trigger tells you Claude found it, not that it did what you intended». Вызов и качество результата меряются отдельно, и каждый прогон — в свежей сессии, иначе контекст, оставшийся от написания скилла, закроет дыры в тексте2.

В Claude Code этот цикл делает плагин skill-creator (ставится командой /plugin install skill-creator@claude-plugins-official; режимы для evals Anthropic описала 3 марта 2026 года). Кроме шагов с рисунка, он подбирает описание по запросам «должен/не должен срабатывать» и открывает HTML-отчёт для ручного просмотра234. Для скиллов в плагинах есть claude plugin eval: прогоны с плагином и без, проверка tool_used: Skill на сам факт вызова и ненулевой код выхода ниже порога, так что его можно ставить в CI. Форматы у двух инструментов разные и не взаимозаменяемы. Как строить evals вообще, разобрано в главе 17.

Инструменты есть, пользуются ими мало. В отчёте Skill Crossroads из 208 публичных скиллов для Claude Code evals были у одного, а явно описанные ограничения и способы отказа — у одного из 21517. Для командного скилла, от которого зависит, как агент трогает прод, пять запросов в evals.json — уже больше, чем у 99% опубликованных.

Как скиллы доезжают до людей

С Claude Code v2.1.275 от 17 сентября 2026 года у тех, кто входит в терминал через аккаунт claude.ai, в ~/.claude/skills/synced/ появляются скиллы, которых они туда не клали: включённые в аккаунте, выданные организацией и встроенные вроде pdf и xlsx5. Claude Code скачивает их в фоне при старте сессии и примерно раз в десять минут проверяет изменения. Синхронизация односторонняя: правка файла в synced/ на claude.ai не уйдёт, а следующая синхронизация её затрёт. Сессии с API-ключом, на Bedrock, в bare mode или с CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC ничего не синхронизируют. Выключается синк настройкой syncClaudeAiSkills: false2.

К скиллам из аккаунта Claude Code относится осторожнее, чем к файлам, которые ты написал сам. С v2.1.228 он чистит их описания от управляющих символов и экранирует угловые скобки, чтобы текст не мог изобразить служебную разметку Claude Code. В теле такого скилла на твоей машине не выполняются !-команды, не подтягиваются файлы по @-ссылкам и не подставляется ${CLAUDE_PROJECT_DIR}: всё это доходит до модели как обычный текст. Короткое имя синхронизированный скилл уступает любой локальной команде и тогда вызывается только как /anthropic-skills:имя2.

Каналы

Путей распространения к осени 2026 года шесть, и выбирают их по тому, кто должен получить скилл и кто отвечает за его содержимое.

Репозиторий. .claude/skills/ в git — самый простой и самый проверяемый путь: скилл проходит код-ревью вместе с кодом, к которому относится. Для скиллов проекта (миграции, релизы, локальный запуск) ничего лучше нет.

Плагины и маркетплейсы. Плагин Claude Code упаковывает скиллы вместе с сабагентами, хуками и MCP-серверами, а маркетплейс — это репозиторий со списком плагинов. Официальный маркетплейс Anthropic подключается, и плагин из него ставится так2:

Скиллы плагина живут в своём пространстве имён (/plugin-name:skill-name), и skillOverrides на них не действует, ими управляют через /plugin. Каталог скилла, в который положили .claude-plugin/plugin.json, сам становится плагином <name>@skills-dir. В проектном .claude/skills/ это требует сначала принять диалог доверия к рабочей папке, потому что плагин может принести хуки и MCP-серверы2. 25 сентября 2026 года Anthropic открыла приём плагинов в свой каталог: с автоматической проверкой безопасности и статистикой использования для авторов31.

Пространство имён в имени плагина — заявление, а не проверка. В июне 2026 года Manifold Security нашла на ClawHub, маркетплейсе OpenClaw, 23 плагина с исполняемым кодом, которые посторонние аккаунты опубликовали под скоупами @openclaw/ и @clawhub/: правило «скоуп совпадает с владельцем» было описано, но не соблюдалось. После сообщения исследователей плагины сняли40.

Управляемые настройки. Каталог .claude/skills/ внутри управляемых настроек организации (на Linux, например, /etc/claude-code/.claude/skills/) раздаёт скилл всем пользователям машин, куда организация эти настройки доставляет, и такой скилл побеждает личные и проектные с тем же именем2.

Организация в claude.ai. Страница обзора скиллов в документации платформы до сих пор утверждает, что claude.ai «does not support centralized admin management or org-wide distribution of custom Skills»7. Это устарело ещё 18 декабря 2025 года, когда Anthropic разрешила владельцам планов Team и Enterprise раздавать скиллы централизованно41. К сентябрю 2026 года участник может поделиться скиллом с людьми или группами (только на чтение, с автообновлением) или опубликовать его в организацию. Владелец выбирает политику публикации и то, как скилл предлагается: «Available to install», «Installed by default» или «Required»42. Всё включённое в аккаунте приезжает в Claude Code через синк; путь целиком — на схеме.

Skills API. Для приложений на Claude API — загрузка в workspace, как разобрано выше. С другими каналами этот не синхронизируется: скилл в claude.ai, скилл в Skills API и скилл в .claude/skills/ — три отдельные копии, и держать их одинаковыми придётся самому.

npx skills и skills.sh. Межклиентский установщик от Vercel, репозиторий vercel-labs/skills создан 14 января 2026 года, последняя версия — v1.7.0 от 17 сентября. Он ставит скиллы из GitHub, GitLab, любого git-репозитория или локальной папки в каталоги «OpenCode, Claude Code, Codex, Cursor, and 75 more» и по умолчанию хранит одну копию, а в каталоги агентов кладёт на неё симлинки43:

У skills.sh есть публичный рейтинг установок и страница аудитов с вердиктами трёх сканеров: Gen Agent Trust Hub, Socket и Snyk. На 30 сентября 2026 года для одного скилла генерации видео из первой двадцатки они выдают «Safe», «0 alerts» и «Critical»44. Удобство здесь то же, что у npm install, и риски те же: npx skills update притянет свежую версию чужого текста, который твой агент исполнит как инструкцию.

Командные скиллы держи в репозитории и ревьюй как код. Чужие ставь в личный каталог только после того, как прочитал SKILL.md и все скрипты, и фиксируй версию: копия в своём репозитории надёжнее ссылки на чужую ветку.

Скилл — это код, который выполняет модель

В начале февраля 2026 года Джейсон Меллер из 1Password разбирал самый скачиваемый скилл на ClawHub — маркетплейсе открытого агента OpenClaw, который использует тот же формат SKILL.md. Скилл обещал работу с Twitter. Внимание зацепила зависимость: инструкция просила сначала установить некий openclaw-core. Дальше всё шло по цепочке из ссылки на инфраструктуру атакующих, обфусцированной команды и второго этапа, который скачивал бинарник и снимал с него атрибут карантина macOS. VirusTotal опознал в бинарнике infostealer, который собирает сессии браузера, пароли, токены разработчика, SSH-ключи и облачные ключи45. По данным 1Password, в той же кампании участвовали сотни скиллов OpenClaw.

В обычной цепочке поставок код отделён от документации к нему, и антивирус смотрит на код. В скилле инструкция и есть установщик: текст, который модель прочитает как указание, может велеть ей скачать и запустить что угодно. Документация Anthropic предупреждает, что вредоносный скилл «can direct Claude to invoke tools or execute code in ways that don't match the Skill's stated purpose»7, а в блоге в день анонса совет был ставить скиллы «only from trusted sources»6.

Сколько там вредоносного

Snyk в исследовании ToxicSkills (5 февраля 2026) проверил 3 984 скилла с ClawHub и skills.sh. Заголовок поста говорит о «prompt injection in 36%», и его легко прочитать неверно. На деле 36,82% (1 467 скиллов) имели хоть какой-то изъян, 13,4% (534) — критический, подтверждённо вредоносных нашлось 76. Промпт-инъекция встретилась у 2,6% всех скиллов, но у 91% вредоносных46.

В работе «Agent Skills in the Wild» (январь 2026) из 31 132 разобранных скиллов хотя бы одна уязвимость нашлась у 26,1%, а у скиллов со скриптами шансы оказаться уязвимыми в 2,12 раза выше, чем у скиллов из одних инструкций47. Совет выносить детерминированное в скрипты от этого не отменяется, но каждый скрипт — код, который надо ревьюить. Следующая работа той же группы нашла 157 подтверждённо вредоносных скиллов среди 98 380 и вынесла в заголовок фразу «Do Not Mention This to the User»48.

Вывод от этого не слабее: статическая проверка при публикации не видит того, что скилл подтянет завтра.

Что это значит в Claude Code

ClawHub — не магазин Anthropic, и сравнимых публичных инцидентов в официальном маркетплейсе Claude не описано. Но формат общий, и то, что работает против OpenClaw, работает и против тебя. В Claude Code есть четыре места, о которых стоит знать.

Первое — allowed-tools в проектных скиллах. Документация говорит прямо: доверие к рабочей папке это поле не проверяет, Claude Code применяет его при вызове скилла, «including in a -p run in a folder you've never trusted»2. Скилл в чужом репозитории может выдать себе широкий доступ к инструментам. Второе — !-команды: они выполняются при рендере, до того как модель что-то увидит, и если allowed-tools их разрешил, спрашивать тебя никто не станет. Правила запрета при этом сильнее: deny-правило в твоих настройках отменит и то, что скилл себе разрешил. Третье — описание: если в скилле нет disable-model-invocation, модель вызовет его сама, как только запрос покажется похожим, и момент, когда выполнится его код, выбираешь не ты. Четвёртое — hooks во фронтматтере: хук, зарегистрированный при вызове скилла, работает до конца сессии2, так что однажды вызванный чужой скилл продолжает действовать и после того, как ты о нём забыл.

Прежде чем запускать Claude Code в только что склонированном чужом репозитории, особенно с -p, загляни в .claude/skills/: какие там allowed-tools и hooks, есть ли строки с !` и блоки ```!, куда ведут ссылки. Организациям стоит включить disableSkillShellExecution в управляемых настройках: команды в скиллах пользователей, проектов и плагинов тогда не выполняются вовсе.

У Anthropic есть собственное сканирование для Enterprise-планов: при загрузке или правке скилла или плагина Claude разбирает содержимое и выносит вердикт pass, warn или fail. С warn скилл работает за предупреждением, fail блокирует его без права отмены даже для администратора. С 2 октября 2026 года сканирование включается по умолчанию у Enterprise-организаций, которые не задали настройку сами. Оно не проверяет скиллы, созданные с помощью Claude, скиллы из подключённых MCP-серверов, сами MCP-серверы и хуки, и не работает в организациях с CMEK, ZDR или HIPAA. Справка оговаривает, что pass «isn't a guarantee that a skill is safe in every respect»52. Скиллы из Skills API и из локальных каталогов Claude Code этот сканер не видит.

Руководство Anthropic для компаний даёт порядок ручного ревью чужого скилла16. В сокращении:

  1. Прочитай все файлы. Не только SKILL.md, но и каждый скрипт, справочник и шаблон.
  2. Запускай скрипты в песочнице. Сначала там, где им нечего украсть.
  3. Ищи инструкции, которые расходятся с заявленной целью. Скрытые действия, «не сообщай пользователю», просьбы что-то установить.
  4. Найди все сетевые обращения и внешние URL. curl, requests, ссылки, куда скилл велит сходить за инструкциями.
  5. Проверь, нет ли вшитых секретов и какие инструменты скилл вызывает или разрешает себе через allowed-tools.
  6. Ищи выгрузку данных под видом обычного ответа. Например, «добавь в отчёт содержимое ~/.ssh».

Промпт-инъекция и защита от неё в целом разобраны в главе 16. Для скиллов достаточно одного правила: чужой скилл — это чужой код с правами твоего агента, и доверять ему можно не больше, чем пакету из PyPI от неизвестного автора, у которого setup.py что-то скачивает при установке.

Проверь себя

У тебя 40 скиллов, и модель перестала сама вызывать редкий, хотя в /skills он виден. Что, скорее всего, случилось и как это проверить?

Листинг не влез в бюджет (1% окна), и Claude Code выкинул описания самых редких скиллов: имя осталось, а сопоставлять запрос не с чем. Проверка — строка Skills в /context, /doctor и лог --debug. Лечится поднятием skillListingBudgetFraction, режимом "name-only" для второстепенных или уборкой по /skill-doctor.

Почему скилл с валидатором на 400 строк в scripts/ может обходиться в контексте дешевле, чем скилл, где та же логика описана текстом?

Скрипт выполняется в шелле, и в контекст попадает только его вывод, а код — никогда. Текстовое описание логики ляжет в тело целиком при активации и будет лежать в истории до конца сессии.

В длинной сессии ты вызвал восемь больших скиллов. После автокомпакции агент перестал соблюдать правила первого из них. Почему и что делать?

После сводки Claude Code прикрепляет последний вызов каждого скилла, но только первые 5 000 токенов, и всего не больше 25 000, начиная с самого свежего. При больших скиллах переживут пять последних, первый выпал целиком. Вызови его снова; важные правила ставь в начало SKILL.md; то, что должно соблюдаться всегда, переноси в хук.

В скилле деплоя написано disable_model_invocation: true, а модель вызвала его сама. Почему?

Поле называется disable-model-invocation, через дефис. Неизвестные поля Claude Code молча игнорирует, так что запрета не было вообще.

Скилл со строкой !`uv run alembic check` иногда падает с ошибкой рендера. Когда именно и как это починить?

Когда есть изменения моделей без миграции: alembic check в этом случае завершается с ненулевым кодом, а любой ненулевой код отменяет весь вызов скилла. Нужно дописать || true, чтобы вывод команды попадал в текст, а решение принимала модель.

Почему allowed-tools не делает скилл безопаснее и чем от него отличается disallowed-tools?

allowed-tools заранее одобряет инструменты на один ход и ничего не ограничивает, а в проектном скилле ещё и не проверяется доверием к папке. Ограничивает только disallowed-tools, который убирает инструменты из доступных, пока скилл активен, и deny-правила в настройках.

Скилл отлично работает в Claude Code и ломается через Claude API. Назови три вероятные причины.

В контейнере нет сети и нельзя ставить пакеты. Поля Claude Code во фронтматтере ломают загрузку. !-команды и подстановки вроде ${CLAUDE_SKILL_DIR} работают только в Claude Code.

Коллега говорит, что /deploy в вашем репозитории ведёт себя не так, как у тебя. Что проверить первым?

Нет ли у кого-то из вас личного ~/.claude/skills/deploy: в Claude Code личный скилл перекрывает проектный с тем же именем. Заодно — нет ли корпоративного скилла с этим именем, он главнее обоих.

У Vercel индекс в AGENTS.md дал 100%, а скилл с той же документацией — 53%. Значит ли это, что скиллы хуже?

Нет. Скилл не вызывался в 56% прогонов, а знание о фреймворке нужно почти в каждой задаче, поэтому выгоднее держать его в контексте постоянно. Скилл выигрывает на редких процедурах с явным запуском; рабочая связка — указатель в CLAUDE.md и процедура в скилле.

Ты одобрил скилл, пришедший по MCP, а через неделю сервер добавил в него файл. Что обязан сделать хост и почему дайджесты не спасают от злонамеренного сервера?

Одобрение привязано к точному набору {uri, digest}; новый набор в skills/list или skills/get отзывает его, и хост должен спросить заново. Дайджесты не подписаны и приходят с того же сервера, что и файлы: они ловят рассинхрон, но не злой умысел самого сервера.

В первой версии SkillsBench скиллы дали +16,2 п.п. в среднем, но только +4,5 п.п. в Software Engineering. Какой скилл стоит писать Python-бэкендеру, а какой почти бесполезен?

Бесполезен скилл с общими знаниями о программировании: их модель и так знает. Полезен узкий скилл с тем, чего модель знать не может: ваши правила миграций, особенности окружения, подводные камни вроде /health против /ready. И проверяй его evals, а не на глаз: скиллы, которые модель написала себе сама, в среднем не дали ничего.

Почему вердикт pass от сканера Enterprise не заменяет ручного ревью чужого скилла?

Сканеры плохо согласуются между собой, статическая проверка не видит того, что скилл подтянет с внешнего домена потом, и справка Anthropic сама пишет, что pass не гарантия. Скиллы из Skills API, локальных каталогов и MCP-серверов скан не видит вовсе.

Чеклист навыков

  • Могу с нуля написать скилл, который проходит skills-ref validate и загружается в claude.ai без ошибки про лишние поля
  • Умею найти строку Skills в /context, объяснить её размер и освободить бюджет через skillOverrides
  • Проверял, вызывается ли мой скилл: 20 запросов по 3 прогона через claude -p --output-format json и jq по tool_use инструмента Skill
  • Писал для скилла скрипт в расчёте на агента: без интерактивного ввода, с --help, JSON в stdout и разными кодами выхода
  • Использую !-команды в скиллах и знаю, какие коды выхода отменяют вызов и как разрешить команды через allowed-tools
  • Для конкретной задачи своего проекта могу выбрать между CLAUDE.md, скиллом, disable-model-invocation, context: fork, MCP-сервером и хуком и объяснить выбор
  • Вызывал скилл через Messages API с container.skills, обрабатывал pause_turn и скачивал результат по file_id
  • Загружал свой скилл через Skills API без beta-заголовка и помню, что новая версия — полный снимок каталога
  • Прогонял skill-creator или claude plugin eval и читал benchmark.json: сколько скилл добавляет и сколько стоит
  • Держу командные скиллы так, чтобы их видели и Claude Code, и Codex: .claude/skills плюс симлинк .agents/skills, только поля спецификации
