## Discourse pass (§1–3)

- **QUD.** Разделы не идут анкетой «что → зачем → как → вывод». Почти каждый открывается конкретной вещью:
  вводка — замер Vercel; «Три уровня загрузки» — строка changelog v2.1.234 (200k → 25k); «Почему скилл не
  срабатывает» — жалоба rane на HN; «Что происходит после вызова» — цитата документации про «отвалившийся» скилл;
  «Открытый стандарт» — конфликт приоритетов личного и проектного скилла; «Скилл, MCP…» — устаревший тезис
  charcircuit; «Как написать скилл» — SkillsBench; «Безопасность» — разбор 1Password. Ходы сравнения и проверки
  есть: Claude Code против руководства agentskills.io по порядку приоритетов, страница документации против
  анонса 18 декабря (устаревшее утверждение об org-wide distribution), заголовок Snyk «36%» против реальных цифр,
  «26 000 пользователей» CSO Online против охвата рекламы, три сканера друг против друга. Флагов нет.
- **Тест первых предложений.** В списке много предложений, непонятных без контекста («Со вторым уровнем важно
  другое.», «Дальше клиенты расходятся.», «Второй подвох — вложенность.», «Позиция крайняя, но в ней есть
  рабочая часть.», «Теперь история из вводки целиком.»). Аккуратного конспекта не получается — pass.
- **Середина.** Средние разделы («Что происходит после вызова», «Скиллы вне терминала», «Открытый стандарт»)
  несут события, которых начало не предсказывает: компакция выбрасывает ранние скиллы целиком, `alembic check`
  отменяет рендер скилла, удаление через API стало молчаливым, Claude Code перекрывает проектный скилл личным.
  Фактура чередуется: таблица, код, схема, цитата, спор. Pass.
- **Позиции.** Абзацы разной длины, цитаты стоят и в начале, и в середине, и в конце абзацев, тройки в основном
  настоящие, акценты собраны в warn-блоках. Pass. Кандидаты «список в прозе» — абзац о скриптах для агента
  («Никаких интерактивных вопросов… Разные ошибки — разные коды выхода. Для разрушительных операций нужен
  --dry-run.») и «Первое — … Второе — … Третье — … Четвёртое —» в разделе о Claude Code: перечисления
  настоящие, читаются как проза, единичные — не трогались.

## Этап 2: правки (от глубокого слоя к поверхностному)

Структура и порядок разделов не менялись: по диагностике дефектов на этом уровне нет.

Структура страницы (#6):

1. Вводка: удалено «Ниже о том, как он это решает, во что это обходится и когда такая упаковка знаний выигрывает у
   остальных.» — анонс структуры (AUTHORING §3, правило 2). Вводка теперь кончается определением скилла.

Связность (#8):

2. «Правило простое: задача с понятным результатом…» → «Задача с понятным результатом…» (удаление ярлыка).
3. «Для автора скилла вывод практический: пиши на шести полях…» → «Пиши на шести полях…» (удаление рамки).
4. «Для Python-бэкендера вывод простой. Скилл „как писать хороший FastAPI-код“…» → «Скилл „как писать…“» (удаление
   рамки; адресат и так ясен из FastAPI).
5. «И добавила вывод, который стоит выписать себе: «Focused…» → «И добавила вывод: «Focused…» (удаление).
6. «Здесь же предупреждение, которое стоит перечитать: всякий…» → «Здесь же предупреждение: всякий…» (удаление).
7. «Это и есть главное про безопасность скиллов. В обычной цепочке поставок…» → «В обычной цепочке поставок…»
   (удаление ярлыка, повторявшего заголовок раздела «Скилл — это код, который выполняет модель»).

Слова (#10):

8. «поэтому для нового документация советует» → «поэтому для новой команды документация советует» (починка эллипсиса).
9. «Шаг 1 дан с низкой степенью свободы» → «Шаг 1 задан точной командой» (термин вводится на три абзаца позже;
   замена той же длины).

логотипы» — короткие образы в регистре книги; перечисления в прозе о скриптах и о четырёх местах в Claude Code.
