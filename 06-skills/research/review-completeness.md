# Глава 06 «Agent Skills»: рецензия на полноту

Рецензент: критик полноты. Дата: 30 сентября 2026.
Что прочитано: `index.html` целиком (текст, 22 блока кода, 6 mermaid, 3 графика); `gaps.md`, `spec.md`, `practice.md`, `field.md`, `outline.md`.
Что перепроверено в первоисточниках: code.claude.com/docs/en/skills.md (скачан 30.09), platform.claude.com agent-skills/overview.md, GitHub API (anthropics/skills, obra/superpowers, cloudflare/security-audit-skill), arXiv API (2609.35692, 2605.31408, 2601.10338, 2602.06547), manifold.security, skills.sh/audits, agent-plugins.org/specification.md, API reference для skill analytics.

## Общая оценка

Глава очень плотная и в основном свежая. Почти все противоречия, которые разобраны в `gaps.md` (C1–C16), в ней уже решены правильно:
- Skills API вышел из беты;
- три версии code execution;
- распространение скиллов на уровне организации в claude.ai;
- приоритет enterprise > personal > project;
- AIR PoC описан как демонстрация, а не как «26 тыс. жертв»;
- правильно прочитаны 36% у Snyk;
- слияние команд и скиллов в v2.1.3;
- фон для `context: fork` с v2.1.218;
- из компакции сохраняются первые 5 000 токенов, а не последние.

Устаревших утверждений относительно заметок я не нашёл. Ошибок уровня critical тоже нет. Python-примеры с отступом в 2 пробела не сломаны: `assets/book.js` (`dedent`, строки 157–162) снимает общий отступ.

Основные дыры другого рода. В главе перечислены поля и механики, которые потом нигде не объясняются. Сбой «срабатывает слишком часто» не рассмотрен. Нет обзора реальных хорошо сделанных скиллов, хотя он есть в ОХВАТЕ. Не описано, как скиллы работают в приложениях Claude. Из заметок не попали несколько проверенных замеров.

## Находки (по убыванию пользы)

### 1. [major] Поля Claude Code перечислены, но не разобраны: аргументы, хуки, effort, shell
**Где:** «Шесть полей и строгие валидаторы» (там обещано: «что делают важные из них, разобрано ниже»), «Команды стали скиллами», «Что происходит после вызова».
**Проблема.** `arguments`, `argument-hint`, `hooks`, `effort` и `shell` названы только в списке. Раздел «Команды стали скиллами» говорит читателю с `.claude/commands/`, что он «уже пишет скиллы». При этом механика `$ARGUMENTS`, на которой держатся почти все командные файлы, в главе не описана.
**Что добавить.** Таблицу «поле → что делает → сколько живёт» и два коротких примера:
- `$ARGUMENTS`, `$ARGUMENTS[N]`, `$N`; кавычки работают как в шелле. Если в теле нет ни одного плейсхолдера, Claude Code дописывает `ARGUMENTS: <value>` в конец. Знак `$` экранируется как `\$1.00`.
- Составной вызов: `/write-tests /fix-issue 123` загружает оба скилла, после первого можно добавить ещё до пяти (v2.1.199). Форк-скилл, например `/code-review` с v2.1.218, обрывает цепочку.
- `hooks` во фронтматтере. Хук регистрируется при вызове скилла и работает до конца сессии. Документация прямо советует держать так правило рядом со скиллом: «To keep the rule with the skill, define the hook in the skill's hooks frontmatter». Сейчас глава советует «хук вместо скилла» и не упоминает, что хук можно положить в сам скилл. Есть и контраст со строкой «Права живут меньше текста»: `allowed-tools` действует один ход, а хук из скилла живёт всю сессию. Это стоит одной фразы в разделе о безопасности: проектный скилл может оставить после себя хук.
- `effort` (low…max) и `model` (до конца хода; с `context: fork` задаёт модель сабагента). Связать с тезисом «What works for Opus might need more detail for Haiku».
- `shell: powershell`.
- Идиому `allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/check_migration.py *)` применить к наброску alembic-migration. Сейчас он вызывает скрипт без предодобрения и будет спрашивать разрешение на каждом запуске.

**Источник:** code.claude.com/docs/en/skills.md, строки 380–387 (model, effort, hooks, shell), 439–441 и 466–472 (подстановки), 603–607 (составной вызов), 1138 (хук в скилле); gaps.md §7 (строки 477–480).

### 2. [major] Не рассмотрен обратный сбой: скилл срабатывает слишком часто или перехватывает чужие запросы
**Где:** «Почему скилл не срабатывает» / «Молчаливые провалы». Уместен подраздел «Когда скилл срабатывает не там» и ветка на рисунке fig-trigger-debug.
**Проблема.** Глава почти целиком про недовызов. Сейчас скилл ставят в команду пачками, и для этого важен и обратный режим. Слишком широкое описание срабатывает на посторонних запросах и отбирает вызовы у соседнего скилла. В руководстве Anthropic для компаний это отдельный класс проблем, Coexistence, который нужно проверять до выкладки. В troubleshooting Claude Code есть раздел «Skill triggers too often»: сузить описание или поставить `disable-model-invocation: true`. В главе есть только полфразы («не будет вызываться невпопад») и near-miss в разделе про evals.
**Что добавить.**
- Абзац о том, что near-miss запросы надо гонять по всему набору установленных скиллов сразу, а не по одному скиллу.
- Способы сузить срабатывание: `paths`, `disable-model-invocation`, короткий `when_to_use`.
- Строку «вызвался не тот скилл» в диагностике.

**Источник:** code.claude.com/docs/en/skills.md, строки 1127–1132; spec.md, раздел Pitfalls, первый пункт (Skills for enterprise, [S12], «Coexistence»); practice.md [S19] (3–5 запросов, включая should-not-trigger, до одобрения в прод, на Haiku/Sonnet/Opus).

### 3. [major] Нет обзора реальных хорошо сделанных скиллов, хотя ОХВАТ его требует
**Где:** в конце «Как написать скилл, который помогает». Лучше всего подойдёт таблица «что подсмотреть и в каком скилле».
**Проблема.** Сейчас примеры — это `summarize-changes` из документации и два собственных наброска. ОХВАТ прямо называет «real examples of well-made skills». Читатель, который открывает главу как справочник, не узнает, где лежат образцы и какой приём у кого брать.
**Что добавить.** Все пункты проверены через GitHub API 30.09.2026.
- **anthropics/skills** — 19 скиллов:
  - `pdf`: напористое описание «Use this skill whenever the user wants to do anything with PDF files…» и условные ссылки «If you need to fill out a PDF form, read FORMS.md».
  - `webapp-testing`: образец скрипта как чёрного ящика. В теле написано «Always run scripts with `--help` first… DO NOT read the source… These scripts can be very large and thus pollute your context window».
  - `mcp-builder`: скилл, который учит строить MCP-серверы; это живая иллюстрация связки скилла и MCP.
  - `skill-creator`.
  - Оговорку из README стоит привести дословно: docx/pdf/pptx/xlsx «source-available, not open source», и «the implementations and behaviors you receive from Claude may differ from what is shown in these skills».
- **obra/superpowers** — около 293 тыс. звёзд, репозиторий создан 9.10.2025, до анонса. Это методология разработки, собранная из скиллов; в треде HN о запуске её называли prior art.
- **cloudflare/security-audit-skill** — около 23 тыс. звёзд, создан 18.06.2026, «multi-phase security audits with independently verified, machine-readable findings». На HN 17.09.2026 набрал 213 баллов.

**Источник:** api.github.com/repos/anthropics/skills/contents/skills; raw README и SKILL.md для `pdf` и `webapp-testing`; api.github.com/repos/obra/superpowers; api.github.com/repos/cloudflare/security-audit-skill; field.md (строки 33, 237); gaps.md [G50]; practice.md [S23].

### 4. [major] Не описано, как скиллы работают в приложениях Claude (claude.ai, Desktop, Cowork, Office)
**Где:** «Скиллы вне терминала: API, SDK, Managed Agents». Нужен подраздел или таблица «три поверхности — три среды выполнения».
**Проблема.** ОХВАТ называет «Claude Code, Claude apps and the Claude API». Для приложений в главе есть только распространение в организации и одна строка «при включённом выполнении кода». Рантайм не описан. В разделе «Песочница без сети» сравниваются только Claude Code и API. Из-за этого у читателя складывается ложная дихотомия «локально есть сеть, в облаке сети нет».
**Что добавить.** Таблицу из обзора Anthropic:

| Поверхность | Сеть | Пакеты |
|---|---|---|
| claude.ai | «full, partial, or no network access» в зависимости от настроек пользователя и админа | — |
| API | нет | только предустановленные |
| Claude Code | полная | ставить только локально |

К таблице добавить:
- как подключить: включить выполнение кода, загрузить zip в настройках;
- встроенные скиллы;
- скиллы в надстройках Excel, PowerPoint, Word и Outlook с вызовом через `/` (gaps.md [G8]);
- на каких облаках есть Skills API. Обзор называет только Claude API, Claude Platform on AWS и Microsoft Foundry, причём на Foundry нужен развёртывание «Hosted on Anthropic». Bedrock и Vertex там не упомянуты. Бэкендеру, который ходит к Claude через Bedrock, стоит знать это до того, как проектировать решение на скиллах. Формулировать осторожно: «в документации не заявлено».

**Источник:** platform.claude.com/docs/en/agents-and-tools/agent-skills/overview.md, строки 29–31, 170–176, 296–315; practice.md, таблица Runtime constraints (строки 259–265); gaps.md [G8].

### 5. [major] В разделе «За экономию токенов платишь ходами» нет данных, хотя в заметках они есть
**Где:** «За экономию токенов платишь ходами»; второе исследование также пригодится в «Как написать скилл, который помогает».
**Проблема.** Тезис о задержке и лишних шагах подкреплён только рассуждением и историей Vercel. В gaps.md (§8, Numbers) есть два проверяемых замера, и в главу не попал ни один.
**Что добавить.**
- Workday, «Report: Progressive Disclosure of Agent Skills», arXiv 2609.35692, 28.09.2026. На продовых агентах поэтапное раскрытие «improves skill-retrieval quality but marginally degrades overall latency». Это прямое подтверждение заголовка раздела, и замерено оно вне Anthropic.
- Xu & Wu, arXiv 2605.31408, 29.05.2026: контролируемое исследование на SkillsBench, 30 задач, 5 прогонов на ячейку, 1 800 строк. Наличие скилла даёт +26,7…36,0 п.п. для GPT-5.5 и +18,0…26,0 п.п. для DeepSeek V4-Flash, а влияние гранулярности подачи маленькое и неустойчивое (95% ДИ пересекают ноль). Отсюда вывод для автора: важнее, чтобы скилл был и вызывался, чем то, как нарезано его тело.

Лучше всего одной-двумя фразами или строкой в графике fig-skillsbench.
**Источник:** arXiv API, аннотации проверены 30.09.2026; gaps.md [G35], [G42].

### 6. [major] Безопасность: нет замеров, важных для автора, и выпал запланированный сквоттинг неймспейсов
**Где:** «Сколько там вредоносного» и «Каналы» (пункт про плагины и маркетплейсы).
**Проблема.** В outline.md, раздел 10, обещан «сквоттинг неймспейсов», а в главе нет ни слова. Нет и самой полезной для автора цифры: насколько скрипты повышают риск. Как раз это связывает безопасность с правилом «детерминированное — в скрипты».
**Что добавить.** Один абзац и одну фразу; подробности оставить главе 16.
- «Agent Skills in the Wild», arXiv 2601.10338, 15.01.2026: проанализирован 31 132 скилл из 42 447. У 26,1% есть хотя бы одна уязвимость, у 5,2% паттерны высокой тяжести. Скиллы со скриптами уязвимы в 2,12 раза чаще, чем скиллы из одних инструкций (OR=2.12, p<0.001).
- «"Do Not Mention This to the User"», arXiv 2602.06547: 157 подтверждённо вредоносных скиллов среди 98 380, в среднем 4,03 уязвимости на скилл. Название статьи совпадает с пунктом чеклиста ревью в главе, так что его можно процитировать.
- Manifold Security, 19.06.2026: 23 плагина с исполняемым кодом были опубликованы на ClawHub в скоупах `@openclaw/` и `@clawhub/` чужими аккаунтами. ClawHub «had documented the rule but did not» проверять его. После сообщения от 17.06 добавили процедуру оспаривания. Вывод для раздела «Каналы»: пространство имён плагина, как в `/plugin:skill`, и значок «официальный» — это заявление, а не проверка.

**Источник:** arXiv API (аннотации); manifold.security/blog/scope-squatting-clawhub-plugins (проверено curl, статус 200, цитаты найдены); gaps.md [G37], [G38]; practice.md [S14].

### 7. [minor] У skills.sh описан только рейтинг установок, страница аудитов пропущена
**Где:** «Каналы», абзац про `npx skills` и skills.sh.

На том же топе они расходятся: у `find-skills` (vercel-labs/skills) Gen даёт «Safe», Socket «0 alerts», Snyk «Med Risk». **Источник:** https://skills.sh/audits (проверено 30.09.2026); gaps.md [G46]; practice.md [S17].

### 8. [minor] Для организации нет наблюдаемости: не упомянут API аналитики по скиллам
**Где:** «Каналы», пункт «Организация в claude.ai», или рядом с `/skill-doctor`.
**Проблема.** `/skill-doctor` работает только локально, и встроенные и корпоративные скиллы в его отчёт не попадают (это в главе сказано). Для администратора есть свой инструмент: `GET /v1/organizations/analytics/skills`. Он в бете, только для Enterprise, со скоупом `read:analytics`, данные с 2026-01-01. Умеет `group_by` по `user_id`, `rbac_group_id` и `product`, а `product` принимает `chat`, `claude_code`, `cowork`, `office_agent`. Им можно найти корпоративные скиллы, которые никто не вызывает.
**Источник:** platform.claude.com/docs/en/api/beta/organization/analytics/skills/list.md (проверено); gaps.md [G31].

### 9. [minor] В «Как написать скилл» не хватает трёх правил из руководства Anthropic
**Где:** подразделы «Описание» и «Краткость и степени свободы».
**Что добавить.**
- Имена: форма герундия (`processing-pdfs`), без расплывчатых `helper` и `utils`.
- Не писать в теле условия, привязанные к дате («если раньше августа 2025…»). Устаревшее переносить в свёрнутый блок «old patterns».
- Руководство для компаний требует до выкладки 3–5 запросов в evals (should, should-not, ambiguous) и прогон на Haiku, Sonnet и Opus. Это усиливает уже имеющуюся в главе фразу про Haiku.

**Источник:** field.md [S6] (строка 212); practice.md [S11] (строки 342–349), [S19].

### 10. [minor] Плагин Claude Code не является пакетом Agent Plugins, и читатель может решить обратное
**Где:** «Насколько это стандарт?» или «Каналы», пункт про плагины.
**Проблема.** Глава рассказывает про Agent Plugins, про то, что у Anthropic нет места в комитете, и про плагины Claude. Но нигде не сказано, что форматы несовместимы:

| | Манифест | MCP-серверы |
|---|---|---|
| Agent Plugins | корневой `plugin.json` (MUST; другие места «MUST reject») | `mcp.json` |
| Claude Code | `.claude-plugin/plugin.json` | `.mcp.json` |

Каталог `skills/` у них общий. Хватит одной фразы: переносится папка `skills/`, манифест не переносится.
**Источник:** agent-plugins.org/specification.md, строки 69, 108, 120–128, 255–256; code.claude.com/docs/en/skills.md, строки 150 и 294; gaps.md, раздел Unverified, пункт «Anthropic's position on Agent Plugins».

### 11. [minor] В вопросе «Проверь себя» смешаны версии SkillsBench
**Где:** «Проверь себя», вопрос «SkillsBench: +16,6 п.п. в среднем, но +4,5 п.п. в Software Engineering».
**Проблема.** +16,6 — среднее по v4 (18 конфигураций), +4,5 — домен из v1, где среднее было +16,2, и в тексте главы оно так и указано. На графике версии подписаны, в вопросе нет. Вопрос учит сравнивать несравнимые числа.
**Исправление:** «+16,2 п.п. в среднем и +4,5 п.п. в Software Engineering (v1)» или явно подписать версии.
**Источник:** gaps.md §8 и Numbers (строки 487–491, 507–508); текст главы, раздел «Как написать скилл, который помогает».

### 12. [minor] Несколько новинок Claude Code и платформы из заметок, которые стоит упомянуть одной строкой
**Где:** по месту.
- `/doctor prompt-audit` (v2.1.283) проверяет CLAUDE.md, скиллы, агентов и команды на приёмы, рассчитанные на старые модели. Это прямой инструмент для «capability uplift» скиллов, которые устаревают с новыми моделями (абзац про skill-creator).
- `disableBundledSkills` отключает встроенные скиллы. Пригодится в «Бюджете листинга».
- CLI `ant apply` загружает каталог скилла и пишет идентификаторы в `claude-lock.json` (Managed Agents и Skills API). Это ответ на предупреждение в «Загрузке и версиях» о CI и полном снимке.
- Claude Marketplace, 23.09.2026, 2 000+ коннекторов и плагинов. Стоит одной строкой рядом с каталогом плагинов от 25.09.

**Источник:** gaps.md §7 (строки 481–483), §6 (строка 465), Timeline (2026-09-23), [G5], [G12], [G30].

## Границы с соседними главами

Нарушений, которые требуют правки, нет. У каждой пограничной темы есть ссылка: компакция → гл. 2, сабагенты → гл. 12, управление MCP → гл. 5, промпт-инъекции → гл. 16, методика evals → гл. 17.

Одно пограничное место: раздел «Скиллы поверх MCP». Там полный JSON ответа `skills/list`, лимиты 512 файлов и 16 МиБ, а также правила MCP-хоста. Для главы о скиллах хватит сути: скиллы как ресурсы `skill://`, одобрение, привязанное к дайджестам, «Digests are not a trust anchor». JSON и нормативные MUST можно сократить и сослаться на главу 5, если там разобрана ревизия 2026-07-28. Это вопрос объёма, а не ошибка, поэтому в находки не включено.
