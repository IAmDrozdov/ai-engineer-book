## Найденные проблемы

### 1. (minor) Расхождение `id` в примере ответа SEP-2640 `skills/list`

**Цитата из главы** (блок `data-title="Ответ на skills/list (пример из спецификации SEP-2640,
сокращён)"`, раздел «Скиллы поверх MCP»):
```json
{
  "jsonrpc": "2.0",
  "id": 2,
  ...
```
**В чём ошибка:** блок подан как пример из спецификации («сокращён», то есть подразумевается
дословность). В действительности пример с этим же скиллом (`pdf-processing`, тот же дайджест
`sha256:99b737495721155ece826d57521e2d66141ebdc1344a400487481ea2642ab19e`, тот же `size: 151`)
в тексте спецификации использует `"id": 4`, а не `2`. Остальное тело блока (uri, frontmatter,
resources, дайджесты, размеры) — дословно верно.
**Как правильно:** `"id": 4`.
**Доказательство:** https://github.com/modelcontextprotocol/ext-skills/blob/main/specification/stable/skills.mdx
(проверено прямым чтением файла 30 сентября 2026; идентичный пример с `pdf-processing` и тем же
дайджестом `99b737...` содержит `"id": 4`).

### 2. (minor) Непроверяемое утверждение о смене формата поля `source` в Skills API

**Цитата из главы** (раздел «Скиллы вне терминала», таблица миграции с беты):
> `source` | строка `"custom"` | объект `{"type": "custom"}`

**В чём проблема:** ни один из четырёх файлов заметок (`gaps.md`, `spec.md`, `practice.md`,
`field.md`) не фиксирует, что поле `source` в бета-версии Skills API было простой строкой — все три
описывают миграцию только для `display_title→display_name`, `latest_version→latest_version_id` и
поведения удаления. `practice.md` приводит VERBATIM-пример ответа API, где `source` уже объект
(`{"type": "custom"}`) — но это текущее (GA) состояние, не свидетельство о прежнем формате.
Прямой запрос к живой странице `platform.claude.com/docs/en/build-with-claude/skills-guide`
раздела с историей миграции с беты не выявил вовсе (страница либо была переработана, либо раздел
находится по другому URL). Утверждение не опровергнуто, но и не подтверждено — источника для него
в приложенных материалах нет.
**Рекомендация:** либо найти и указать прямой источник этой конкретной строки таблицы (архивная
версия страницы миграции, объявление о выходе Skills API из беты), либо убрать эту строку из
таблицы, оставив только три подтверждённые перемены.

### 3. (minor, не фактическая ошибка) Ни один из 15 рисунков не имеет ссылки из текста

Инструкция автора (`_meta/AUTHORING.md`, раздел 6) явно требует: «В тексте ссылайся:
`<a href="#fig-handshake">на схеме рукопожатия</a>»`. Проверка регулярным поиском по всему файлу
показывает: паттерн `href="#fig-` не встречается в `index.html` ни разу — при том что в главе
15 рисунков (`fig-disclosure`, `fig-activation`, `fig-compaction`, `fig-fork`, `fig-api-flow`,
`fig-precedence`, `fig-mcp-skills`, `fig-vercel`, `fig-skillsbench`, `fig-trigger-debug`,
`fig-org`, `fig-decision`, `fig-eval-loop`, `fig-scanners`, `fig-clawhub`). Все они просто стоят
рядом с текстом, к которому относятся, но ни на один нет явной ссылки-якоря. Это не фактическая
ошибка (тест `qa.mjs` тоже не считает молчаливое расположение рисунка «битой ссылкой» — битая
ссылка это обратный случай), но прямое нарушение явного правила вёрстки главы; стоит поправить
перед сдачей.

## Утверждения без ссылки, которым она нужна

Отдельных нетривиальных фактов, чисел, дат или цитат без цитатной ссылки `<a class="cite">` в тексте

источников (проверено программно, разрывов нумерации нет). Единственное узкое место — сама
строка о смене формата `source` (см. находку 2): она стоит в таблице, помеченной ссылкой на
src‑4/src‑14 в целом, но именно эта клетка таблицы, в отличие от соседних, не имеет independent
подтверждения в заметках.
