# Отзыв читателя — глава 07 «A2A: Agent2Agent»

Рецензент читал главу подряд вечером, снял разделы через `tools/qa.mjs --sections`, посмотрел
скриншоты (`_qa/07-a2a-reader/sec-01..14.png`), сверил факты и числа с `research/gaps.md`,
`spec.md`, `field.md`, `practice.md` и с кодом в `research/code/`. Автоматическая проверка:
`ISSUES none` (14 секций, 16 рисунков, 10 927 слов прозы, 41 источник, 124 цитаты — всё в рамках
норм из `AUTHORING.md`).

Общее впечатление: глава очень плотная и необычно тщательно проверена фактически — почти каждое
нетривиальное утверждение, дата и цифра совпадает с `gaps.md` (который сам явно фиксирует, что
именно проверено и как). Структурных нарушений §3 (анонсы, итоговые пересказы, анкетный порядок,
канцелярит, гроздья шаблонных оборотов) при выборочном грепе по всему списку слов из таблицы §3 не
найдено ни одного попадания — это стоит явно зафиксировать как «проверено, нарушений нет», а не
только находки. Самопроверка (11 вопросов) и чеклист (12 пунктов) построены правильно: все вопросы
— «что случится, если…», а не на память; все пункты чеклиста проверяются делом. Ниже — то немногое,
что реально мешало чтению.

## Находки

### 1. [major] Термин `tenant` использован в рисунке и в proto-врезке за два раздела до определения

**Место:** id="bindings" («Одна модель, три провода»), рисунок `#fig-bindings` и следующая за ним
proto-врезка.

**Цитата.** В mermaid-схеме: `rest -.-> ten["/{tenant}/tasks/{id}<br/>если в карточке есть
tenant"]:::mute`, подпись рисунка: «У каждого REST-пути есть двойник с префиксом тенанта». Дальше
в proto: `additional_bindings: { post: "/{tenant}/message:send" body: "*" }`. Ни разу не сказано,
что такое тенант в терминах A2A. Определение появляется только в разделе id="agent-card", двумя
разделами позже: «...упорядоченный список пар «URL плюс биндинг плюс версия протокола», иногда с
`tenant`, когда за одним адресом живёт несколько агентов».

**Проблема.** Это ровно тот случай «термин раньше определения» из задания на ревью: рисунок,
который должен объяснять механизм биндингов, показывает узел `tenant`, о котором читатель ничего
не знает — ни что это (мультиарендность за одним хостом), ни зачем в proto есть его двойник у
каждого маршрута. Догадаться по слову «tenant» можно приблизительно (общий SaaS-паттерн), но
именно A2A-специфика (тенант берётся из карточки агента) не следует из контекста, а рисунок как раз
про механизм провода.

**Что с этим сделать.** Либо дать однострочную глоссу прямо на месте первого появления (в тексте
перед рисунком: «...иногда с префиксом tenant — так агент-хостинг с несколькими агентами за одним
адресом различает их в URL»), либо переставить фразу-определение тенанта из раздела про Agent Card
на первое появление в разделе про биндинги, а в разделе про карточку сослаться на неё анкором.

### 2. [minor] Кросс-репликовый `SubscribeToTask` собран в голове читателя из одного плотного абзаца, без рисунка

**Место:** id="production", подраздел «Задачи, которые живут дольше процесса».

**Цитата:** «...хранилище задач с версиями и compare-and-swap, чтобы две реплики не затёрли одну
задачу, и общая таблица `task_events`, которую опрашивают подписчики на любой реплике. Так
`SubscribeToTask`, попавший на одну реплику, видит события задачи, которая выполняется на другой».

**Проблема.** Это именно тот случай, для которого в главе есть 16 рисунков на другие механизмы: три
движущиеся части (реплика A пишет задачу, реплика B получает подписку, общая таблица событий их
соединяет) нужно собрать по одному предложению без опоры на картинку. Само `AUTHORING.md`
формулирует критерий для рисунка как «читателю иначе пришлось бы собирать механизм в голове из трёх
абзацев» — здесь даже один абзац, но с тремя движущимися частями и без единого визуального якоря.

**Что с этим сделать.** Небольшая HTML-схема `.layers` или flowchart на 4 узла (Реплика A —
TaskStore — task_events — Реплика B) с одной стрелкой «подписка идёт на B, событие пришло от A»
закрыла бы это без больших затрат места.

### 3. [minor] Сквозная трассировка через `contextId` — сложный по факту механизм без схемы, хотя в исследовательских заметках она предложена

**Место:** id="production", подраздел «Одна трасса через несколько агентов».

**Наблюдение.** Абзац описывает трёхагентную цепочку: первый агент чеканит `contextId`, передаёт
его двум другим, каждый агент кладёт его в метаданные своего OTel-спана — и только тогда трасса
видна одной нитью в интерфейсе LangSmith. Само `research/gaps.md` в разделе «Diagram candidates»
(пункт 10) прямо предлагает для этого схему: «Agent 1 mints contextId → propagated... → Agents 2
and 3 → each maps it to thread_id / OTel span metadata → one LangSmith thread». В итоговом тексте
главы рисунка для этого места нет.

**Что с этим сделать.** Не обязательно, но раз собственные заметки автора уже наметили эту схему —
стоит либо добавить простую sequence-диаграмму на 3–4 участника, либо явно решить, что текста
достаточно (абзац действительно один и не самый сложный в главе), и не переносить пункт из заметок
в план бездумно. Оставляю как находку низкой важности, а не как обязательное требование.

### 4. [minor] `CDI` использовано без пояснения для читателя-питониста

**Место:** id="security», абзац про `InMemoryTaskStore` в a2a-java.

**Цитата:** «Проверка владельца включалась, только если приложение само подключало провайдер
авторизации и декоратор через CDI». `CDI` (Contexts and Dependency Injection, спецификация Java
EE/Jakarta) нигде не расшифрован и не знаком целевому читателю (опытный Python-бэкендер). Деталь
периферийная — сам урок абзаца («настройки SDK по умолчанию годятся только для демо») понятен и без
знания CDI, поэтому не критично, но конкретно это слово повисает.

**Что с этим сделать.** Добавить три слова в скобках: «...через CDI (Java-аналог DI-контейнера)» —
и абзац перестаёт требовать знания Java-экосистемы.

## Проверено отдельно — нарушений не найдено

- **Слова и обороты §3.** Полный греп по таблице (стоит отметить/является/данный/осуществляет/
  позволяет/в рамках/мощный/гибкий/бесшовный/экосистема/ландшафт/погрузимся/не просто X а Y/
  деепричастные хвосты «обеспечивая»/«позволяя»/риторический вопрос «Почему? Потому что») —
  ноль реальных попаданий (два case-insensitive совпадения оказались подстроками нормальных слов:
  «появляется», «выданный» — ложные срабатывания).
- **Анонсы структуры и итоговые пересказы.** Ни «в этой главе», ни «подведём итог», ни «таким
  образом» в тексте нет; главы 7.1–7.11 открываются конкретным обменом/фактом/датой, а не темой.
- **Самопроверка.** Все 11 вопросов — сценарные («что произойдёт, если…», «что докажет...», «чем
  это грозит»), ни одного вопроса на голую память термина.
- **Чеклист.** Все 12 пунктов проверяются делом (curl-сценарий, поднятый агент, настроенный вебхук,
  прогон TCK) — абстрактных «знаю про X» нет.
- **Код помечен корректно.** Примеры, которые действительно гонялись (`server.py`, `client.py`,
  `sign_card.py`, вывод `subscribe_probe.py`), совпадают построчно с файлами в `research/code/` —
  подписи «снято с живого сервера» не выдуманы. Ненаписанные/непроверенные фрагменты помечены как
  «Набросок» (запрос на вебхук по шаблону §4.3.3, `a2a server --exec` для Claude Code).
- **Фактчек по числам и датам.** Выборочно сверено с `gaps.md`: версии SDK и даты релизов, цифры
  скачиваний PyPI (таблица в `#fig-downloads` совпадает с `Numbers` в `gaps.md` по всем шести
  месяцам), состав TSC из восьми компаний, даты вступления в AAIF/LF, статус TLS 1.3 (SHOULD, не
  MUST), CVSS 7.5 для GHSA-qw47, обе даты 26/28 мая для v1.0.1 — расхождений не найдено. Proto-
  врезки (`Part`, `Message`) в главе совпадают дословно с выдержкой в `spec.md`.
- **Рисунки.** Из 16 рисунков 15 действительно объясняют механизм (проверено по скриншотам секций
  1–11 и 13); QA не нашёл ни одной схлопнутой mermaid-схемы, наложения подписей или превышения
  лимита узлов/участников.

## Итог для автора

Главных проблем для чтения две: термин `tenant`, который выскакивает в схеме раньше объяснения, и
два места (кросс-репликовая подписка, сквозная трассировка), где плотный абзац without рисунка
держит на себе больше механизма, чем читатель может собрать с одного захода. Всё остальное —
шероховатость на одно слово. Для главы такого объёма и фактической плотности это на удивление
короткий список.
