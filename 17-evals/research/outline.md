# Глава 17. Метрики, evals и приёмочные тесты — план

Читатель: Python-бэкендер в Claude Code. Главная линия главы: число из eval'а — это измерение
системы «модель × харнесс × грейдер × окружение», и чаще всего врёт не модель, а грейдер,
выборка или статистика. Поэтому порядок такой: откуда берутся задачи → кто ставит оценку →
как мерить судью → сколько прогонов и задач нужно → что проверять у агента → CI → прод →
чужие лидерборды → как замкнуть цикл.

## Разделы

1. `grader-bugs` «Двенадцать пунктов из починенных тестов». Начало: Terminal-Bench 2.1, Opus 4.6
   в Claude Code 58,0 → 70,1% только от исправления 28 задач; CORE-Bench 42 → 95. Главное: словарь
   Anthropic (task, trial, grader, transcript, outcome, eval harness vs agent harness, suite),
   outcome ≠ transcript, YAML задачи с пятью грейдерами. Рис.: hbar TB 2.0/2.1; flowchart прогона.
2. `error-analysis` «Сто трейсов и карандаш». Начало: Хамел и Шрейя тратят 60–80% времени на
   анализ ошибок. Open coding → axial coding → счёт, первый сбой, насыщение, агент-помощник только
   после 30 своих трейсов, NurtureBoss, матрица переходов, синтетика кортежами. Спор про
   eval-driven development (Anthropic/OpenAI против Хамела) с выбором. Рис.: pipeline.
3. `graders` «Кто ставит оценку». Начало: CORE-Bench отвергал «96.12» при эталоне «96.124991…».
   Код / LLM-судья / человек + классификаторы 2026 (Jev, SemIf). Бинарно против Лайкерта,
   pass-all против частичного зачёта. Рис.: flowchart выбора грейдера.
4. `llm-judge` «Судья — тоже классификатор». Начало: Дэн Луу, 23% вердиктов переворачиваются при
   повторной оценке тем же судьёй. TPR/TNR, почему не «согласие в %», разбиение 10–20/40–45/40–45,
   промпт судьи (бинарно, Unknown, одно измерение, рассуждение до вердикта), код калибровки,
   отказы судей (невалидный JSON, GroundEval 0,85 против 0,000), ансамбли Composo.
   Рис.: SVG матрицы ошибок на числах Хамела.
5. `trials` «Один прогон ничего не доказывает». Начало: таблица τ-bench Airline pass^1…pass^4.
   pass@k и pass^k, несмещённые оценки Inspect, ловушка mean(p^k) ≠ (mean p)^k, что брать когда.
   Рис.: line pass^k.
6. `statistics` «Два пункта на пятидесяти задачах». Начало: цитата statgate. SEM и 95% CI,
   кластерные ошибки (в 3 раза шире), парные разности, мощность (~2800 на плечо), шум инфраструктуры
   (6 п.п.), код парного бутстрэпа, SHIP/BLOCK/INCONCLUSIVE. Рис.: hbar шума инфраструктуры;
   flowchart вердикта гейта.
7. `trajectory` «Путь или результат». Начало: τ³ banking_knowledge, одно осторожное чтение обнуляло
   награду, после фикса +9 п.п. Режимы strict/unordered/subset/superset, мутирующие и читающие
   шаги (SABER), четыре примитива, код pydantic-evals, невидимые нативные тулы, стоимость (imec),
   groundedness и RAG-метрики коротко (детали — глава 14). Рис.: versus; hbar imec.
8. `simulated-users` «Собеседник из модели». Начало: Opus 4.5 «провалил» задачу τ²-bench, найдя
   лазейку в политике. Dual control, τ³, ошибки симулятора, τ-Voice, код openevals, YAML
   Anthropic для поддержки. Рис.: sequenceDiagram.
9. `ci-gates` «Приёмочные тесты в CI». Начало: скрипт promptfoo с порогом 95%. Capability против
   regression, выпуск задач, 0% pass@100, кэш промптфу, pytest-гейт на pydantic-evals, таблица
   фреймворков с выбором, закат OpenAI Evals (timeline). Рис.: stateDiagram жизни задачи.
10. `production` «После релиза». Начало: онлайн-оценщик LangSmith переводит трейс на расширенное
    хранение и меняет счёт. Сэмплинг, согласованный сэмплинг, бэкфилл, лимиты; CI против онлайна
    (Хамел); ритм разбора; A/B; OTel GenAI (Development, свой репозиторий, gen_ai.evaluation.result),
    телеметрия Claude Code, платформы и выбор, инцидент Braintrust. Рис.: flowchart петли
    офлайн/онлайн; flowchart дерева спанов.
11. `benchmarks` «Как читать чужой лидерборд». Начало: OpenAI о SWE-bench Verified (~16% задач с
    битыми тестами). METR, бенчмарки как софт (semver TB, SWE-bench Pro V2, τ³ 1.0.1),
    OSWorld 2.0 против OSWorld-Pro, жульничество на лидерборде, eval awareness, чеклист чтения
    чужой цифры. Рис.: hbar TB 2.1 против 3.0.
12. `closing-loop` «Eval как функция потерь». Начало: Anthropic склеивает транскрипты и отдаёт их
    Claude Code переписать инструменты. Held-out, GEPA и ASI, оговорка Хамела. Рис.: flowchart цикла.

## Проверка плана по §3

- Анкета: разделы не идут «что → зачем → как → итог»; есть сравнение (путь/результат, TB 2.1/3.0),
  проверка расхожего утверждения (EDD, «95% порог», pass^k = p^k), и сбой перед механизмом
  (1, 4, 7, 10, 11).
- Первые фразы разделов — события и цифры, а не определения.
- Провал: самый глубокий раздел — судья и статистика; установка фреймворков сжата до таблицы.
