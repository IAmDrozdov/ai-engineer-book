# Сверка семейства фактов «Anthropic» по главам книги «Чеклист AI-инженера»

Дата сверки: 30 сентября 2026. Проверялись все 17 глав (`tools/prose.py` → связный текст по
абзацам, `/usr/bin/grep -n` по ключевым словам семейства: линейка моделей Anthropic и их точные
имена/даты (Opus 5.5, Sonnet 5.5, Fable 5.1, Mythos 5.1, Haiku 4.5, поколения 4.6 и 4.7),
thinking/effort и коды 400, множители цены кеша, окна контекста и цены за 1M токенов, бета-заголовки
(compaction, context editing, tool search, programmatic tool calling, task budgets, inline tools),
Claude Code (версии, команды, порог автокомпакции, `/context`, hooks, agent teams), Claude Agent SDK,
Skills API, memory tool. Спорные места дополнительно сверены по первоисточникам: через `WebFetch`
живой документации `platform.claude.com/docs/...` (context windows, thinking, tool search tool,
memory tool, prompt caching) и через полный `CHANGELOG.md` Claude Code, скачанный напрямую с
`raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md` (грепан по версиям, которые
главы датируют конкретными номерами).

Проверенные и **не** попавшие в отчёт кандидаты (для протокола): дефолты effort по моделям
(Opus 5.5 — `medium`, остальные — `high`) и правила отключения thinking (Opus 5 — до `high`
включительно, Opus 5.5 — никогда, Sonnet 5.5 — только до `between_tools` и тоже до `high`) — совпадают
между главами 1 и 4 и с живой документацией `build-with-claude/thinking`; список моделей с отказом
`reasoning_extraction` (Fable 5.1, Fable 5, Opus 5.5, Sonnet 5.5) — совпадает между главами 1 и 4 и с
источником; минимальные пороги кеширования по моделям (512/1024/2048/4096 токенов) и множители
записи/чтения кеша (1,25×/2× запись, 0,1× чтение с исключениями 0,05× Opus 5.5 и 0,025× Fable 5.1) в
главе 2 — совпадают с живой документацией `prompt-caching` день в день; правило «1M — дефолт с версий
4.6, без бета-заголовка» в изначальной формулировке главы 2 (строка 81) и главы 14 (строка 302) —
подтверждено первоисточником; факт, что research preview agent teams и auto memory вышли в одной и
той же версии Claude Code 2.1.32 (5 февраля 2026) — подтверждено `CHANGELOG.md`, это не ошибка, хотя
главы 11 и 12 описывают его как «дату для своей фичи» по отдельности; история версий auto memory в
главе 11 (v2.1.32, 59, 63, 74, 83, 210, 214, 277, 284) — построчно сверена с `CHANGELOG.md` и везде
совпадает дословно или по смыслу; числа 72K→8,7K описаний MCP-тулов и рост точности Opus 4/4.5 —
сверены по посту Anthropic «Advanced tool use»; в главе 3 (строка 628) они ошибочно названы
стоимостью одних описаний вместо общего потребления контекста, но эта находка уже зафиксирована в
`_meta/consistency/numbers.md` (находка 2), поэтому здесь не дублируется.

## Находки

### 1. Глава 02: собственное же утверждение об окне в 1M опровергнуто двумя абзацами ниже

- **Файл**: `02-context-engineering/index.html`, строка 895
- **Цитата**: «Модели с собственным окном в миллион (Sonnet 5, Fable, Opus 4.7 и новее через API
  Anthropic) компактируются примерно на 967 тыс. токенов. Sonnet 4.6 и Opus 4.6 без расширенного
  контекста, а также модели с миллионным окном при `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` — на границе
  200 тыс.»
- **Проблема**: это прямо противоречит тому, что та же глава пишет двумя разделами раньше (строка
  81): «На всех моделях Anthropic начиная с 4.6 окно по умолчанию 1 млн токенов (Sonnet 4.5 и Haiku
  остались на 200 тыс.)». Здесь же Opus 4.6 и Sonnet 4.6 внезапно вынесены за скобки как модели «без
  расширенного контекста», как будто им для 1M нужен отдельный опт-ин. Проверка по первоисточнику
  подтверждает версию строки 81, а не строки 895: «For every model with a 1M-token context window,
  1M is the default: you don't need a beta header», и Claude Opus 4.6 и Claude Sonnet 4.6 прямо
  входят в перечисленный список моделей с 1M-окном.
- **Как исправить**: убрать формулировку «Sonnet 4.6 и Opus 4.6 без расширенного контекста»; у этих
  моделей 1M — тоже дефолт без беты. Компактируются на границе 200 тыс. только модели без
  собственного 1M-окна (Sonnet 4.5, Haiku) и любые модели при явном
  `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`.
- **Источник**: https://platform.claude.com/docs/en/build-with-claude/context-windows («Context
  window sizes by model» + «For every model with a 1M-token context window, 1M is the default»);
  глава 2, строка 81 (та же книга).

### 2. Глава 12: тот же список моделей с 1M-окном ошибочно исключает Opus 4.6 и Sonnet 4.6

- **Файл**: `12-deep-agents/index.html`, строка 367
- **Цитата**: «Claude Code на моделях с родным окном в миллион токенов (Sonnet 5, Fable, Opus 4.7 и
  новее через API Anthropic) сжимает историю «at about 967K tokens by default».»
- **Проблема**: формулировка «Opus 4.7 и новее» по смыслу исключает Opus 4.6 (и явно не называет
  Sonnet 4.6) из числа моделей с «родным» 1M-окном — то есть повторяет ту же ошибку, что и глава 2
  (находка 1), только без явного противоречащего абзаца рядом. По документации Anthropic 1M —
  дефолт без беты уже с Opus 4.6 и Sonnet 4.6 включительно.
- **Как исправить**: заменить на «Sonnet 5.5, Sonnet 5, Sonnet 4.6, Fable, Opus 4.6 и новее», как в
  живой документации и как должно быть в главе 2, строка 81.
- **Источник**: https://platform.claude.com/docs/en/build-with-claude/context-windows; глава 2,
  строка 81.

### 3. Глава 06: таблица форматов скиллов занижает бюджет листинга Claude Code вдвое

- **Файл**: `06-skills/index.html`, строка 623
- **Цитата**: (строка таблицы «Claude Code» в сравнении форматов скиллов) «`.claude/skills` (и
  родители до корня репо), `~/.claude/skills`, managed, плагины, синк claude.ai … 1% окна, 1 536
  символов на запись»
- **Проблема**: глава называет бюджет листинга скиллов в Claude Code «1% окна», хотя по CHANGELOG
  Claude Code (версия 2.1.32) этот бюджет — 2% окна: «Skill character budget now scales with context
  window (2% of context), so users with larger context windows can see more skill descriptions
  without truncation». Более того, сама глава 6 в другом месте (строка 220) явно приводит то же
  значение 0,02 = 2% как параметр `skillListingBudgetFraction`, то есть противоречит себе же.
- **Как исправить**: заменить «1% окна» на «2% окна» в строке таблицы для Claude Code (число 8 000
  символов у Codex/ChatGPT в соседней строке никак не связано с ошибкой и трогать не нужно).
- **Источник**: `CHANGELOG.md`, `github.com/anthropics/claude-code`, запись версии `2.1.32`; глава 6,
  строка 220 (та же книга).

### 4. Глава 06: тот же неверный «1% окна» повторён в разборе самопроверки

  в Claude Code — 2% окна (CHANGELOG, версия 2.1.32), и это тот же 0,02, который сама глава называет
  в строке 220.
- **Как исправить**: заменить «1% окна» на «2% окна».
- **Источник**: `CHANGELOG.md`, `github.com/anthropics/claude-code`, запись версии `2.1.32`; глава 6,
