## Находки

### Minor: JSON-фрагмент в сравнении API не разбирается и не похож на соседние вкладки

**Блок:** `<div class="tabs">` в разделе «Messages API и Gemini: тот же цикл другими словами»,
вкладка «Anthropic», `data-title="messages после одного вызова (документация Anthropic)"`,
строки 771–782 в `index.html`.

**Что не так:** Блок обёрнут как `"messages": [ ... ]` — то есть JSON-объект без внешних фигурных
скобок, просто пара ключ-значение. `json.loads()` падает с `Extra data: line 2 column 13`. Соседние
вкладки той же группы («Chat Completions», «Responses») показывают тот же диалог как самостоятельный
массив `[ ... ]`, который валиден сам по себе. Только вкладка Anthropic ломает эту симметрию —
читатель, копирующий блок для эксперимента (в главе есть отдельный практический совет «сломай
нарочно» с похожим сценарием), получит `SyntaxError`.

**Доказательство:**
```
$ python3 -c "import json; json.loads(open('block_771.json').read())"
json.decoder.JSONDecodeError: Extra data: line 2 column 13 (char 13)
```
(Блок 771 — единственный из четырёх, который не проходит `json.loads`; блоки 750 и 761 из тех же
соседних вкладок парсятся без ошибок.)

**Как исправить:** либо убрать префикс `"messages": ` и оставить чистый массив (как в двух других
вкладках), либо обернуть весь фрагмент в `{ "messages": [...] }`. Первый вариант ближе к остальным
вкладкам и не потребует правки текста подписи.

### Minor: два JSON-фрагмента в разделе про schemas — синтаксически невалидны, но это копии реального вида документации

**Блоки:** `data-title="Structured outputs в Responses (гайд Structured Outputs)"` (строки 339–348)
и `data-title="allowed_tools (гайд по function calling)"` (строки 370–379).

Оба начинаются с висящего ключа (`"text": {…}` и `"tool_choice": {…}`) без охватывающих скобок,
`json.loads()` падает на обоих. Формально это нарушает правило AUTHORING.md «для JSON проверь, что
он разбирается». По существу — не ошибка: я сверил оба фрагмента с локальными копиями исходных
гайдов OpenAI (`oai_fc.md` из кеша и структуру `output_config`/`text.format` из документации
Anthropic) и оба воспроизводят фрагмент ровно в том виде, в каком его показывает сама документация
— как вырезку одного параметра внутри большего запроса, а не как самостоятельный документ. Отмечаю
как минорную шероховатость, а не ошибку: если решите придерживаться буквы правила «JSON должен
разбираться», оба можно обернуть в фигурные скобки без потери смысла; если оставить как есть — это
соответствует и стилю первоисточников, и обычной практике технических книг показывать «вот как
выглядит это поле».

## Что проверил и не нашёл ошибок

**Код.** Все 4 Python-блока (`block_975.py` — опрос фонового режима, `agent_responses.py`,
`agent_messages.py`, фрагмент минимального текстового цикла) компилируются
(`python3 -m py_compile`) после применения того же дедента, что и `assets/book.js` — сырое
извлечение без дедента давало `IndentationError` на двух вкладках `agent_*.py`, но это артефакт
моего способа извлечения (блоки вложены в `<div class="tabs"><section>` и поэтому в исходнике HTML
имеют общий отступ в 2 пробела), а не ошибка в самом примере: `dedent()` в `book.js:157` вычисляет
минимальный отступ по непустым строкам и срезает его у всех строк одинаково, так что на странице
код показывается корректно свёрстанным и рабочим Python. Оба агентных наброска помечены как
несобранные и непроверенные («собран по документации, не запускался») — это честно, ровно как
требует AUTHORING.md для кода, который не запускался.

Имена атрибутов и методов в Python-набросках сверены с локальными копиями документации и совпадают:
`resp.output_text`, `resp.status`, `resp.incomplete_details`, `resp.output` / `call.call_id` /
`call.arguments` (строка, требует `json.loads`) для OpenAI; `resp.stop_reason`, `resp.content`,
`block.type`/`block.name`/`block.input` (уже объект, не строка) для Anthropic. Деталь, которая
подтверждает согласованность кода и текста: в OpenAI-варианте аргументы парсятся через
`json.loads(call.arguments)`, в Anthropic-варианте — нет (`**block.input` напрямую), что в точности
соответствует утверждению в тексте раздела «Messages API и Gemini», что у Anthropic и Gemini
аргументы уже объект, а не JSON-строка.

Все 15 полноценных (не фрагментных) JSON-блоков разбираются `json.loads()` без ошибок, включая оба
графика (`application/json class="chart"`). Числа в обоих графиках сверены с источником:
- `fig-overhead` (накладные расходы Claude на факт наличия инструментов по версиям Opus) — точное

  спецификация Anthropic tool-use — подтверждённый источник, не выдумка.

  чисел (1370/0/17, 0/1370/303, 1370/0/747) с `research/spec.md:438-443`, «Manual-thinking cache
  invalidation experiment».
