## Critical

### 1. Подсвеченные (`data-hl`) строки в 6 блоках кода не видны читателю — ровно в тех местах, на которые текст указывает

**Место:** `index.html`, разделы `tokens` (строка 405, Harmony), `streaming` (строки 498, 511, 525,
все три потока), `minimal` (строки 1026 и 1072, оба варианта цикла на 50 строк).

**Доказательство:** скриншоты `_qa/01-llm-api-agent-loop-reader/sec-05.png`,
`sec-06.png`, `sec-13.png` — на закрашенной жёлтым/синим строке текст отсутствует, виден только
кусок в комментарии справа. Проверено дампом реального DOM headless Chrome
(`--dump-dom`): текст в разметке присутствует полностью (например, строка `Reasoning: high` есть
в исходнике дважды пройденного парсера), значит пропадает он не из-за ошибки автора в контенте, а
из-за CSS. Причина — `assets/book.css:277`, `.code .hl-line { position:absolute; …; z-index:0 }`
вместе с правилом `.code pre code > * { position:relative; z-index:1 }` (строка 278): второе
правило поднимает над подсветкой только те фрагменты строки, которые `highlight.js` обернул в
`<span>` (ключевые слова, строки, числа). Для `data-lang="text"` и `data-lang="sse"` — оба
официально разрешены в `AUTHORING.md` §5 как «языки без подсветки» — `highlight.js` вообще не
токенизирует строку, и весь текст остаётся «голым» текстовым узлом без `z-index`, поэтому
непрозрачная подсветка перекрывает его целиком. В Python то же самое происходит частично:
идентификаторы, операторы и обычная пунктуация не обёрнуты `hljs`, видны только зарезервированные
слова, строки и комментарии.

Что именно теряет читатель:
- Harmony-пример (`data-hl="5,7-8,13-21"`) — исчезают ровно `Reasoning: high`, правило про канал
  `commentary`, и весь блок `namespace functions { … }` с объявлениями типов, то есть то самое, из-за
  чего пример вообще приведён («JSON Schema исчезла: инструменты стали объявлениями типов
  TypeScript…»). Из трёх абзацев текста, ссылающихся на этот блок, читатель не видит ни одного
  подтверждения в коде.
- Поток Chat Completions (`data-hl="7,9"`) — исчезают финальный чанк с `finish_reason:"stop"` и
  строка `data: [DONE]`, то есть именно то, что текст называет «поток заканчивается буквальной
  строкой».
- Поток Responses (`data-hl="9-10"`) — исчезают `response.function_call_arguments.done` и
  `response.output_item.done`, то есть события, про которые текст говорит «из последнего и надо
  брать элементы для истории».
- Поток Anthropic (`data-hl="7-8"`) — исчезают `content_block_stop` и его `data:`-строка, то есть
  «закрывающее событие», после которого, по тексту, только и можно парсить `partial_json`.
- Оба варианта цикла на 50 строк (`data-hl` на 8–9 строк каждый) — исчезают ровно `store=False`,
  `if resp.status != "completed":`, `raise RuntimeError(...)`, `items += resp.output`, вся строка
  `calls = [it for it in resp.output if it.type == "function_call"]`, `if not calls:` — то есть
  почти все «ловушки», которые следующий абзац разбирает по пунктам («Условие выхода — отсутствие
  вызовов, а не поле причины. Результат ссылается на `call_id`, а не на `id`» и т. д.). Это
  флагманский пример главы («Весь механизм главы помещается в сорок с небольшим строк»), и именно
  в нём подсветка ломает код визуально.

**Что с этим сделать:** это баг общей инфраструктуры (`assets/book.css`/`assets/book.js`), а не
текста главы, но проявляется он только здесь, и `qa.mjs` его не ловит (`ISSUES none` — проверка не
сравнивает видимый текст строки с исходным). Два независимых пути: (а) сообщить о баге на уровне
`assets/`, чтобы `.hl-line` не перекрывал нетокенизированный текст (например, понизить `z-index`
подсветки ниже любого текстового узла через `z-index: -1` и `isolation`, или оборачивать весь
текст блока в `<span>` до простановки подсветки); (b) до починки — в этой главе не ставить
`data-hl` на блоки с `data-lang="text"`/`"sse"` (все три потоковых примера и Harmony) и не
рассчитывать на `data-hl` в Python-примерах теми же строками — либо перенести акцент в текст рядом
с блоком, либо использовать `data-lang="json"`-дружественный формат там, где это возможно.
Учитывая, что ровно те же 6 блоков — самые цитируемые в разделах, это стоит починить до публикации,
а не откладывать как общий баг платформы.
