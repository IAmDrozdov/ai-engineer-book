LLM API и цикл агента

25 февраля 2026 года в трекере opencode появилась жалоба: агент выполняет инструмент и молча останавливается, но только на Gemini и на провайдерах за LiteLLM. На OpenAI тот же код работал. Причина уместилась в одну строку условия выхода из цикла, а чтобы её увидеть, надо знать, какими словами разные API сообщают «модель хочет вызвать инструмент».

Цикл, который крутит любой агент

Вот строка, из-за которой агент бросал работу1:

Условие верит полю причины остановки: если модель закончила ход не ради вызова инструментов, значит, работа сделана. OpenAI в такой ситуации возвращает finish_reason: "tool_calls". Gemini через свой OpenAI-совместимый слой и часть провайдеров за LiteLLM возвращали "stop", хотя массив tool_calls в том же ответе был заполнен. Инструмент выполнялся, цикл выходил, результат до модели не доходил, и со стороны это выглядело как агент, который сдался после первого шага. Исправление вошло в PR #14973, а правило из него стоит перенести в любой свой код: продолжать цикл или нет, решает наличие вызовов инструментов в ответе. Причина остановки только уточняет, что делать, когда вызовов нет.

Откуда у Gemini такой ответ, видно по его родному API. В перечислении finishReason значения «модель хочет вызвать инструмент» нет вовсе: STOP описан как «Natural stop point of the model or provided stop sequence», и ответ с вызовом функции кончается им же2. Совместимый слой переводит его в "stop", а цикл, написанный под OpenAI, принимает это за конец работы. Это не ошибка Google, у разных API просто разные словари.

Харнесс (harness, обвязка) — код вокруг модели: собирает запрос, выполняет инструменты, решает, когда остановиться. Claude Code, Codex, opencode — харнессы.

Сам цикл одинаков у всех, от Claude Code до скрипта на полсотни строк. Саймон Уиллисон описывает агента как «инструменты в цикле»3. Харнесс отправляет модели описания инструментов и всю историю разговора. Модель отвечает либо текстом, либо просьбой вызвать один или несколько инструментов с конкретными аргументами. Харнесс выполняет эти вызовы сам, дописывает результаты в историю и отправляет всё заново. Так продолжается, пока модель не ответит без вызовов.

Из этой схемы следуют две вещи, о которых потом забывают. Первая: модель ничего не выполняет. Вызов инструмента в ответе — это JSON с именем и аргументами, заявка на действие. Запустит ли харнесс команду, спросит ли у тебя разрешения, подменит ли результат, модель узнает только из следующего запроса. Всё, что в Claude Code выглядит как «агент прочитал файл», на проводе выглядит как блок tool_use от модели и блок tool_result, который Claude Code собрал и отправил обратно.

Вторая: модель ничего не помнит между запросами. У Chat Completions и Messages API нет состояния на сервере, разговор существует только в массиве, который харнесс присылает каждый раз. У Responses API состояние бывает серверным, но это меняет лишь то, кто собирает контекст: модель всё равно читает его полностью, и платишь ты за весь (подробности в разделе про Responses).

Отсюда цена. Команда Codex в разборе своего цикла (январь 2026) сама задаёт неудобный вопрос: «isn't the agent loop quadratic in terms of the amount of JSON sent…? And you would be right»4. Каждый виток отправляет всю историю, и суммарный объём растёт квадратично от числа шагов. Они это принимают и следят за одним: старый промпт должен быть точным префиксом нового, тогда срабатывает кеш префикса, и, по их словам, «sampling the model is linear rather than quadratic». Правило на всю главу: историю только дописывают. Пересортированный список инструментов, метка времени в системном промпте, смена модели или уровня рассуждений посреди разговора ломают префикс и возвращают квадратичную цену. Про устройство кеша и то, сколько он экономит, — глава 2.

Армин Ронахер в июне 2026 года предложил различать два цикла5. Внутренний нарисован выше: модель вызывает инструменты и видит результаты, пока не решит, что закончила. Внешний крутит код вокруг: решает, выполнена ли задача целиком, подкладывает свежий контекст, перезапускает выдохшийся внутренний цикл, передаёт работу другой системе. Когда уровни путают, от модели ждут, что она сама поймёт, что задача сделана, хотя ответ без вызовов значит только конец хода. Здесь речь о внутреннем цикле, внешний появится в главе 12.

Claude Code пишет каждую сессию в ~/.claude/projects/<путь-проекта>/<id-сессии>.jsonl. В версии 2.1.285 строки с "type": "assistant" и "type": "user" несут в поле message объекты Messages API: блоки tool_use, tool_result, thinking, поле stop_reason, usage с cache_read_input_tokens. Формат внутренний и не документирован, но лучшего учебного материала не найти: это твои собственные сессии. Команда ниже покажет, сколько витков заняла задача. Число tool_use должно совпасть с числом tool_result, иначе цикл где-то оборвался.

В массиве messages пять рабочих ролей: developer, system, user, assistant и tool. Шестая, function, осталась от 2023 года и помечена устаревшей6. Роль developer появилась 17 декабря 2024 года вместе с o1, и спецификация описывает её так: «Developer-provided instructions that the model should follow, regardless of messages sent by the user. With o1 models and newer, developer messages replace the previous system messages». Роль system по-прежнему принимается, но на рассуждающих моделях инструкции разработчика кладут в developer.

Разница не косметическая. В разборе цикла Codex OpenAI перечисляет приоритет ролей по убыванию, «system, developer, user, assistant», и уточняет, что порядок первых элементов промпта определяет сервер, а не клиент4. Там же видно, из чего состоит запрос настоящего агента. После instructions и tools Codex кладёт в input developer-сообщение с песочницей и правами, developer-инструкции из конфига, user-сообщение с собранными AGENTS.md (по умолчанию до 32 КиБ) и навыками, user-сообщение с описанием окружения, и только потом идёт запрос пользователя. Верхняя ступень принадлежит платформе, твои инструкции стоят ниже, пользовательские ещё ниже, а текст из результатов инструментов собственного веса не имеет. Что писать в сами инструкции, разбирает глава 4.

Ответ модели, которая решила воспользоваться инструментом, в примерах спецификации выглядит так:

Текста нет, content равен null. Вместо него массив tool_calls, и у каждого вызова свой id. Аргументы приходят строкой, внутри которой JSON: их надо распарсить и проверить, прежде чем что-то запускать (почему проверять обязательно, в следующем разделе). Поле finish_reason принимает значения stop, length, tool_calls, content_filter и устаревшее function_call.

Харнесс дописывает в историю сообщение ассистента как есть, вместе с tool_calls, а за ним по одному сообщению с ролью tool на каждый вызов. Связь держится на идентификаторе: tool_call_id в ответе инструмента должен совпасть с id вызова.

Если модель попросила два инструмента сразу, в tool_calls будет два элемента, а в истории после ответа ассистента появятся два сообщения tool. С parallel_tool_calls: false модель вызывает не больше одного инструмента за ход. Поле tool_choice спецификация описывает так: «none means the model will not call any tool and instead generates a message. auto means the model can pick between generating a message or calling one or more tools. required means the model must call one or more tools», а объект с именем функции заставляет вызвать именно её. Без инструментов по умолчанию действует none, с инструментами — auto.

Этот формат живёт с 2023 года почти без изменений, и именно его повторили все остальные: vLLM, Ollama, LiteLLM, OpenRouter, OpenAI-совместимый эндпоинт Gemini /v1beta/openai/2. Для сторонних серверов он и в сентябре 2026 года остаётся общим знаменателем.

Для самой OpenAI уже нет. В гайде по GPT-6 сказано: «GPT-6 Astra and GPT-6.1 Sol support Chat Completions, but tool calling requires Responses»; GPT-6 Sol и GPT-6 Luna вызывают инструменты через Chat Completions только с reasoning_effort: "none"7. Поэтому в наброске выше стоит gpt-6-luna без рассуждений. Цикл, который год работал на GPT-5.x, на двух новейших моделях OpenAI не запустится вовсе. Пример ответа из спецификации с моделью gpt-6-astra этому гайду противоречит; когда документы расходятся, верь странице конкретной модели, а не примеру. Сам Chat Completions OpenAI закрывать не собирается, даты отключения нет, но новые агентные возможности (встроенные инструменты, фоновый режим, рассуждения между ходами) появляются только в Responses8.

Под модели OpenAI новый код пиши на Responses API. Под всё остальное, включая локальные модели и шлюзы, Chat Completions остаётся самым переносимым форматом, и так будет, пока сторонние серверы не догонят Responses со всеми его полями.

Responses API: разговор из элементов

При переезде на Responses API часто рассчитывают, что previous_response_id сократит счёт: историю больше не нужно пересылать, сервер помнит её сам. Руководство по миграции отвечает одной фразой: «Even when using previous_response_id, all previous input tokens for responses in the chain are billed as input tokens»8. Параметр экономит байты в запросе и код на клиенте, но не токены. Модель по-прежнему читает весь контекст, а дешевле становится только та часть, что попала в кеш префикса. Там же вторая ловушка: previous_response_id не переносит поле instructions, его надо присылать в каждом запросе.

Responses API вышел 11 марта 2025 года вместе со встроенными инструментами и Agents SDK9. Главное отличие от Chat Completions не в именах полей, а в единице разговора. Вместо сообщений здесь элементы (items), и руководство формулирует это так: «A message is a type of Item, as is a function_call or function_call_output». Ответ модели — плоский массив output, где рядом лежат рассуждения reasoning, текстовое message и вызовы function_call. Вызов инструмента больше не вложен в сообщение ассистента, это отдельный элемент:

У вызова два идентификатора, и их путают. id с префиксом fc_ — имя самого элемента. call_id с префиксом call_ — то, на что должен сослаться function_call_output10. Роли tool в Responses нет, результат инструмента тоже элемент. Его поле output принимает строку до 10 МБ или массив частей с текстом, картинками и файлами6; картинки и файлы в результатах функций разрешили 26 сентября 2025 года.

Сотрудник OpenAI в обсуждении на Hacker News в мае 2025 года описал разницу короче: Chat Completions делает один вызов модели на один вызов API и ничего не хранит, а Responses со встроенными инструментами способен внутри одного вызова сделать несколько ходов модели и несколько вызовов инструментов11. Для встроенных инструментов вроде веб-поиска цикл крутит OpenAI. Для твоих функций его по-прежнему крутишь ты.

Только граница проходит не между встроенными инструментами и функциями, а внутри встроенных. В объединении Tool шестнадцать типов. Часть из них OpenAI выполняет сама и кладёт в output готовый результат. Другая часть только описывает действие и ждёт ответа от харнесса, как обычная функция6:

У Anthropic разделение видно по типу блока: server_tool_use выполнила сама Anthropic, его результат приходит рядом, в том же ответе, и отвечать на него не нужно12. Как выбирать между такими инструментами и своими функциями, разбирает глава 3, одобрение вызовов MCP — глава 5.

Где живёт история

Состояние между ходами держат тремя способами. Можно сослаться на прошлый ответ через previous_response_id и прислать только новые элементы: сервер хранит цепочку, сохранённые ответы по умолчанию живут 30 дней. Можно хранить всё самому: store: false и каждый раз полный массив элементов. И можно завести беседу через Conversations API (он вышел 20 августа 2025 года9): в запросе передаётся conversation, и, по спецификации, «Items from this conversation are prepended to input_items»; у бесед 30-дневного срока хранения нет6.

ZDR (Zero Data Retention) — режим, в котором OpenAI не хранит данные запросов. Для таких организаций store принудительно false.

Собственный агент OpenAI обходится без previous_response_id. Codex шлёт каждый запрос целиком, «to keep requests fully stateless and to support ZDR», а непрерывность рассуждений для клиентов с нулевым хранением обеспечена шифрованием: «OpenAI persists a ZDR customer's decryption key, but not their data»4.

Речь о рассуждениях модели. Они приходят элементом reasoning, и текста мысли там нет: есть краткое изложение, если его попросить, и encrypted_content, зашифрованный блоб, который надо вернуть в следующем запросе. По текущей спецификации блоб заполняется по умолчанию, а форма include: ["reasoning.encrypted_content"] из кукбуков 2025 года осталась от прошлого6. Если при сборке истории выбросить элементы reasoning и оставить только текст, модель на следующем ходе потеряет нить. OpenAI оценивает выигрыш Responses для рассуждающих моделей в 3% на SWE-bench «with same prompt and setup» и в 40–80% лучшую утилизацию кеша во внутренних тестах; модель и дату замера руководство не называет8.

У сообщений ассистента с 24 февраля 2026 года есть поле phase со значениями commentary и final_answer. Спецификация требует: «For models like gpt-5.3-codex and beyond, when sending follow-up requests, preserve and resend phase on all assistant messages — dropping it can degrade performance». Практическое правило для всего Responses API: историю собирай из элементов output как есть, а не пересобирай сообщения ассистента из output_text. Пересобранное сообщение теряет и phase, и рассуждения. Какие из прошлых рассуждений модель вообще увидит, решает отдельный параметр, о нём в разделе про рассуждения.

С 10 февраля 2026 года Responses умеет сжимать длинную историю на сервере: в цепочке появляется непрозрачный элемент компакции, и выбрасывать его нельзя, он теперь часть истории9. Как компакция устроена у OpenAI и у Anthropic и чем она опасна — в главе 2.

Assistants API: чем кончился прошлый API с состоянием

Предыдущая попытка OpenAI сделать API с серверным состоянием закончилась 26 августа 2026 года. Assistants API объявили устаревшим ровно за год до этого, 26 августа 2025, и в назначенный день выключили без переходного периода: вызовы /v1/assistants, /v1/threads и /v1/threads/runs возвращают ошибку14. В посте об отключении есть фраза, которая объясняет выбор: «The Responses API has already overtaken Chat Completions in token activity». Переезжать предлагали на Responses плюс Conversations, автоматического переноса тредов в беседы не было. А сохранённые в дашборде промпты, которые должны были заменить объекты ассистентов, 3 июня 2026 года сами получили дату отключения, 30 ноября 20269.

Схема инструмента, strict и structured outputs

В OpenAPI-спецификации OpenAI у поля arguments есть описание, которое полезно прочитать полностью: «The arguments to call the function with, as generated by the model in JSON format. Note that the model does not always generate valid JSON, and may hallucinate parameters not defined by your function schema. Validate the arguments in your code before calling your function»6. Без дополнительных флагов JSON Schema в описании инструмента — подсказка модели, а не контракт. Модель читает её как текст и старается ей соответствовать.

Контрактом схема становится с strict: true. Сервер компилирует её в грамматику и на каждом шаге генерации отсекает токены, которые из грамматики выводят: написать лишнее поле или строку вместо числа модель не может физически. Это constrained decoding (ограниченное декодирование), и оба крупных вендора реализуют strict именно так. Anthropic пишет: «Structured outputs guarantee schema-compliant responses through constrained decoding», а строгие инструменты у неё работают через «grammar-constrained sampling» по входу инструмента15. Первый запрос с новой схемой платит задержкой на компиляцию, следующие идут с обычной скоростью16.

Цена — ограничения на саму схему. strict поддерживает подмножество JSON Schema, и OpenAI объясняет это соображениями «performance or technical reasons». У каждого объекта, включая вложенные, должно стоять additionalProperties: false, и каждое свойство должно быть перечислено в required. Необязательное поле объявляют через null в типе:

Дефолты у двух API OpenAI разные, и на этом спотыкаются при переезде. В Chat Completions strict по умолчанию выключен. В Responses, если флаг не указан, сервер, по словам гайда, «will attempt to normalize your schema into strict mode when possible, and will fall back to non-strict», и при откате в ответе у инструмента появится strict: false. Явный strict: true на несовместимой схеме запрос отклоняет10. Поэтому пиши strict: true явно и держи схему совместимой: тогда несовместимость всплывёт ошибкой на твоём тесте, а не тихим откатом в продакшене.

Тот же механизм работает для финального ответа, когда нужен не вызов инструмента, а JSON вместо текста. В Chat Completions это response_format с типом json_schema, в Responses — text.format. У Anthropic structured outputs вышли из беты: схема передаётся в output_config.format. Гарантия формы не отменяет отказа: вместо JSON модель может вернуть отказ, и схеме он не подчиняется (как его ловить, в разделе про остановку).

Гайд так и объясняет: список оставляют прежним, «so you can maximize savings from prompt caching». В Open Responses короче: «This is primarily a cache-preserving control surface»17. Трюк с фиктивным инструментом больше не работает

Структурированные данные из Claude долго извлекали так: объявляли фиктивный инструмент со схемой нужного ответа и заставляли его вызвать через tool_choice: {"type": "tool", "name": ...}. На моделях, вышедших в сентябре 2026 года, трюк ломается. Fable 5.1, Mythos 5.1, Opus 5.5 и Sonnet 5.5 на принудительный выбор отвечают 400 с текстом tool_choice: type "tool" and "any" are not supported for this model.18 Замена — structured outputs через output_config.format либо auto плюс strict: true на инструментах19.

Ограничение формата не бесплатно для качества. В статье «Let Me Speak Freely?» (Tam и соавторы, 2024) модели, которых заставляли отвечать в JSON или XML, заметно хуже рассуждали, чем при свободном ответе, и чем строже был формат, тем сильнее падало качество47. Практичный компромисс: strict везде, где выход разбирает машина (аргументы инструментов, данные для кода), потому что ошибка формата там дороже любой потери качества. Для свободного ответа на трудную задачу сначала сравни на своих примерах (глава 17) текстовый ответ и ответ по схеме, и только потом навязывай схему.

Во что превращаются сообщения и инструменты

В гайде OpenAI по function calling есть фраза, которая объясняет, почему описания инструментов стоят денег: «Under the hood, functions are injected into the system message in a syntax the model has been trained on. This means callable function definitions count against the model's context limit and are billed as input tokens»10. JSON из запроса модель не видит. Сервер превращает роли, сообщения и схемы в одну последовательность токенов в синтаксисе, на котором модель обучали, а из токенов её ответа потом собирает JSON с вызовами. У закрытых моделей этот синтаксис спрятан. У открытых он лежит рядом с весами, в шаблоне чата.

Стриминг: три формы одного потока

28 сентября 2026 года вышла Claude Sonnet 5.5, и в описании изменений есть поведение, которое не выдаёт себя ни одной ошибкой. «Text between tool calls comes back in thinking blocks»: текст между вызовами инструментов теперь приходит блоками рассуждений. При значении по умолчанию display: "omitted" их содержимое не передаётся. Интерфейс, который стримит текст, «goes quiet between tool calls, with no error»24. Лечится одним полем, thinking.display: "summarized", и платишь за мышление столько же. Но заметить такое можно, только если понимаешь, из каких событий состоит поток.

SSE (Server-Sent Events) — HTTP-ответ, который не закрывается и построчно присылает события вида data: {…}.

У трёх API три разные формы стрима. Chat Completions шлёт чанки chat.completion.chunk с полем delta, в которых прирастает сообщение. У Responses события типизированы и пронумерованы полем sequence_number. Anthropic группирует события по блокам контента, у каждого блока свой индекс. Отличаются они и именами событий, и моментом, когда аргументы вызова можно разбирать.

В Chat Completions каждый кусок вызова несёт обязательное поле index, а id и name есть только в первом куске6. Склеивать аргументы нужно по index: при параллельных вызовах куски разных вызовов приходят вперемешку, и без индекса их не разделить. Поток заканчивается буквальной строкой data: [DONE], это не JSON. usage в потоке Chat Completions приходит, только если попросить stream_options: {"include_usage": true}, иначе клиент не узнает расход вовсе. С этим флагом перед [DONE] будет лишний чанк с расходом за весь запрос и пустым массивом choices.

В Responses аргументы тоже приходят кусками, но с именованными событиями: response.function_call_arguments.delta по item_id, затем .done с полной строкой, затем response.output_item.done с полным элементом. Из последнего и надо брать элементы для истории. Спецификация прямо предупреждает, что encrypted_content рассуждений в событии .added «may be incomplete», и сохранять его нужно из .done. Поток кончается событием response.completed, response.incomplete или response.failed. Строки [DONE] OpenAI для Responses не документирует, а спецификация Open Responses, наоборот, требует: «The terminal event MUST be the literal string [DONE]»17. Клиент, который собирается работать с обоими, принимает оба окончания. Типов событий в Responses несколько десятков, от response.reasoning_summary_text.delta до response.mcp_call_arguments.delta, и незнакомые клиент должен просто пропускать.

Anthropic держит жёсткий порядок: message_start, затем для каждого блока content_block_start, несколько content_block_delta и content_block_stop, затем message_delta с stop_reason и message_stop12. События ping могут появиться где угодно, незнакомые типы по политике версионирования надо игнорировать. Аргументы инструмента приходят как input_json_delta с полем partial_json. У блока рассуждений перед закрытием приходит signature_delta с подписью, без которой блок нельзя вернуть в историю. Две ловушки: usage в message_delta кумулятивный, а не приращение, и ошибка перегрузки может прийти прямо в потоке, событием error с типом overloaded_error, уже после статуса 200.

Посмотри на сырой поток хотя бы раз, без SDK. curl -N отключает буферизацию, и события печатаются по мере прихода. Сравни, где в каждом потоке появляется имя инструмента и где закрываются аргументы.

У Anthropic причин семь, а не четыре, как в старых руководствах: end_turn, max_tokens, stop_sequence, tool_use, pause_turn, refusal и model_context_window_exceeded25. Последняя на Sonnet 4.5 и новее приходит без бета-заголовка и значит, что ответ упёрся в окно контекста раньше, чем в max_tokens. Объект stop_details заполнен только при отказе. В нём категория (одна из cyber, bio, frontier_llm, reasoning_extraction, general_harms, либо null) и объяснение. Отказы классификатором документированы для Fable 5.1, Fable 5, Opus 5.5, Opus 5 и Sonnet 5.5. Можно поручить запасной ход серверу: с параметром fallbacks: "default" (бета server-side-fallback-2026-07-01) отказанный запрос повторяется на другой модели внутри того же вызова.

pause_turn путают с концом хода чаще остальных. Он относится к серверным инструментам, которые выполняет сама Anthropic, вроде веб-поиска: их внутренний цикл упёрся в лимит, 10 итераций на запрос. Документация велит «continue the conversation by sending the response back as-is». Ответ, который ждёт твоего, клиентского инструмента, никогда не приходит с pause_turn. Если цикл считает эту причину концом хода, пользователь получает недоделанный ответ поиска, и ошибки нигде нет.

У max_tokens в цикле с инструментами есть неочевидная сторона: «max_tokens is a hard cap on total output for the request, thinking and response text combined… In a tool-use loop, each request in the turn has its own max_tokens, so it doesn't bound the whole turn's spend»26. Лимит на запрос не ограничивает стоимость задачи. Для этого нужен счётчик в самом цикле, о нём в разделе про продакшен.

В Responses API поля finish_reason нет вовсе. У ответа есть status (completed, failed, in_progress, cancelled, queued, incomplete) и при неполном ответе incomplete_details.reason: max_output_tokens, max_messages, content_filter или steered6. Условие цикла — есть ли в output элементы, которые ждут ответа клиента: function_call, custom_tool_call и вызовы клиентских встроенных инструментов из таблицы в разделе про Responses. Codex формулирует его так: повторять, пока модель «stops emitting tool calls and instead produces a message for the user»4. С рассуждающими моделями max_output_tokens делится между мыслями и ответом, и маленький лимит кончается на рассуждениях раньше, чем модель дойдёт до текста. OpenAI советует для начала резервировать не меньше 25 тыс. токенов на рассуждения и вывод27.

Три строки таблицы у OpenAI легко пропустить, потому что они приходят не причиной остановки. Отказ модели в Chat Completions лежит в отдельном поле message.refusal, в Responses — частью {"type": "refusal"} внутри сообщения. С structured outputs это опаснее всего: гайд предупреждает, что отказ «does not necessarily follow the schema you have supplied», так что проверяй refusal раньше, чем зовёшь json.loads16. Блокировка политикой приходит ответом со status: "failed" и кодом в error.code. У misalignment_policy_violation есть объект misalignment с публичным объяснением и необязательным steer, инструкцией, как продолжить6. Про GPT-6 Astra гайд пишет: «Our systems asynchronously monitor for misalignment and trigger alerts when necessary»7; как тревога превращается в заблокированный ответ, он не уточняет. А переполнение окна до генерации не доходит вовсе. При truncation: "disabled", а это дефолт, запрос, который не влезает в окно, «will fail with a 400 error». Вариант auto молча выбрасывает элементы из начала разговора и помечен устаревшим; в агенте начало истории обычно содержит саму задачу, так что лови 400 и сжимай историю сам.

У Gemini сломанный вызов — отдельная причина MALFORMED_FUNCTION_CALL, «The function call generated by the model is invalid». Рядом стоит TOO_MANY_TOOL_CALLS: модель вызывала инструменты подряд слишком долго, и система прервала выполнение сама2. Обе причины цикл должен различать, а не сводить к общему «вызовов нет, значит, готово».

Ответ без вызовов — не обязательно ответ. OpenAI предупреждает, что GPT-6 Astra «is more likely to ask for clarification where earlier models would make assumptions»7. В автономном цикле это значит, что условие «вызовов нет» сработает на уточняющем вопросе, и задача встанет. OpenAI поставляет для этой модели промпты автономности (о них глава 4). А внешний цикл должен отличать вопрос от результата.

Ручки рассуждающих моделей

Что ещё крутится в Responses

summary решает, вернуть ли читаемое изложение рассуждений. mode: "pro" на GPT-5.6 и GPT-6 заменил отдельные модели с суффиксом -pro; он не зависит от effort и, по документации, «aggregates the model work performed to produce the final answer and bills those tokens at the selected model's standard token rates»27. Отдельной осью идёт verbosity (low, medium, high): она управляет длиной ответа, а не глубиной мысли.

Самое интересное здесь context. Он «controls which reasoning items are rendered back to the model on later turns»: current_turn показывает модели только рассуждения текущего хода, как в Harmony, all_turns — все прошлые. У семейства GPT-5.6 дефолт all_turns, у более ранних моделей current_turn. Работает это, только если прошлые элементы reasoning доступны: через previous_response_id, беседу или полный replay. И только внутри одного семейства: «reasoning does not carry between the GPT-5.6 and GPT-5.5 families». Сменил семейство посреди разговора — прошлые рассуждения новой модели недоступны.

Смена уровня рассуждений посреди разговора сбрасывает кеш. Среди типизированных причин промаха в диагностике кеша OpenAI есть отдельные reasoning_effort_changed и verbosity_changed6. Для семейства GPT-6 появился обходной путь: не трогать reasoning.effort в запросе, а дописать в input элемент, который меняет его для следующих ходов. OpenAI так и советует: «Keep request-level reasoning.effort unchanged to preserve the prompt prefix for caching»7.

Messages API и Gemini: тот же цикл другими словами

Один и тот же круг «вопрос, вызов, результат» в четырёх API. Рассуждения в историях опущены.

У Anthropic и Gemini аргументы вызова — объект (input, args), а не строка с JSON, как у OpenAI, так что парсить их не нужно, а проверять по-прежнему нужно. Результат инструмента у обоих едет в сообщении с ролью user, отдельной роли для него нет. И у Anthropic в одном ходе ассистента спокойно соседствуют текст и вызов, поэтому цикл смотрит на stop_reason или на наличие блоков tool_use, а не на тип первого или последнего блока. Схема инструмента у Anthropic лежит в input_schema, у остальных — в parameters19.

Порядок блоков у Anthropic

Messages API строг к порядку, и документация формулирует правила без оговорок: «Tool result blocks must immediately follow their corresponding tool use blocks in the message history. You cannot include any messages between the assistant's tool use message and the user's tool result message». И второе: «In the user message containing tool results, the tool_result blocks must come FIRST in the content array. Any text must come AFTER all tool results»19. Нарушение возвращает 400 с текстом, который надо узнавать в логах: tool_use ids were found without tool_result blocks immediately after. Если инструмент упал, результат всё равно отправляется, с "is_error": true.

Параллельные вызовы включены по умолчанию. Все их результаты должны уйти одним сообщением user; если разложить их по нескольким, это, по словам документации SDK, «silently trains Claude to stop making parallel calls». Ошибки нет, модель просто начинает вызывать инструменты по одному, и агент становится медленнее. Ограничить модель одним вызовом за ход можно явно: tool_choice: {"type": "auto", "disable_parallel_tool_use": true}.

Gemini: два API сразу

У Gemini роли называются user и model, системный промпт идёт отдельным полем systemInstruction, инструменты описываются в functionDeclarations. Модель отвечает частью functionCall, результат уходит частью functionResponse в сообщении user. Рядом с вызовом приходит thoughtSignature — непрозрачный токен непрерывности рассуждений, аналог signature у Anthropic и encrypted_content у OpenAI; официальные SDK возвращают его сами2. Харнессу, который собирает историю своими руками, этого мало: документация Gemini 3 требует присылать блоки мыслей с подписями в следующих запросах, а потерянная подпись всплывает причиной остановки MISSING_THOUGHT_SIGNATURE.

Ручки вызова у Gemini те же, что у остальных, только под другими именами. Режим задаёт FunctionCallingConfig.mode: AUTO, ANY, NONE и VALIDATED, который «will validate function calls with constrained decoding», то есть работает как strict. Набор сужает allowedFunctionNames. У functionCall есть необязательное поле id, и если оно пришло, клиент повторяет его в functionResponse2. Связь по одному имени функции сломается на двух параллельных вызовах get_weather для разных городов.

Open Responses

Open Responses OpenAI опубликовала 15 января 2026 года: это открытая спецификация формы Responses API, которую может реализовать любой провайдер. В день анонса Саймон Уиллисон перечислил партнёров: OpenRouter, Hugging Face, LM Studio, vLLM, Ollama и Vercel36. Anthropic и Google в списке нет. Иногда среди соавторов называют Nvidia, но ни в одном из прочитанных первоисточников это не подтверждается. У спецификации две датированные ревизии, 2026-01-15 и 2026-04-24, и устав с техническим комитетом из основных мейнтейнеров17. Вторая ревизия добавила транспорт WebSocket с тем же лимитом в 60 минут, что у OpenAI, и правило для сбоев: при неудачном продолжении сервер «MUST evict the referenced previous_response_id from the connection-local cache» и отвечает кодом previous_response_not_found.

Сильнее всего спецификацию продвигает Codex. Он работает с любым сервером, который «implements the Responses API», а с флагом --oss по умолчанию ходит на http://localhost:11434/v1/responses: Ollama не ниже 0.13.4 или LM Studio не ниже 0.3.394. Раз почти все совместимые серверы работают без состояния, переносимый агент хранит историю сам и каждый раз присылает все элементы, как Codex.

Шлюз держит все ключи

24 марта 2026 года на PyPI вышли версии LiteLLM 1.82.7 и 1.82.8 со встроенным похитителем учётных данных37. Файл litellm_init.pth размером 34 628 байт срабатывал при старте интерпретатора, без всякого import litellm: так устроен механизм .pth. Собранное шифровалось AES-256 и RSA-4096 и уходило на https://models.litellm.cloud/. Тред на Hacker News набрал 938 очков и 500 комментариев. Шлюз к моделям по определению держит ключи от всех провайдеров сразу, поэтому его зависимость закрепляй по версии и хешу, а не диапазоном; подробнее о цепочке поставок в главе 16.

Шлюз вроде LiteLLM или OpenRouter бери ради ключей, бюджетов и возможности быстро менять модели. Но вызов инструментов через него проверяй сквозным тестом для каждой модели отдельно: причина остановки, strict, параллельные вызовы. Если моделей две-три и меняются они редко, родной SDK каждого вендора дешевле в сопровождении, чем слой перевода с его молчаливыми потерями.

Цикл 2026 года: сокет, асинхронные инструменты, steering

WebSocket mode

Квадратичный трафик из разбора Codex убирает WebSocket mode (23 февраля 2026)38. Одно постоянное соединение с /v1/responses. Каждый ход — клиентское событие response.create, чей payload повторяет тело HTTP-запроса без stream и background. Продолжение отправляет только новые элементы и previous_response_id, а через stream_id по одному сокету ведут несколько бесед или ответвлений. Работает и с store=false, и с ZDR: состояние живёт в памяти соединения. OpenAI пишет: «For rollouts with 20+ tool calls, we have seen up to roughly 40% faster end-to-end execution», без описания замера. Соединение живёт не дольше часа, после чего приходит Responses websocket connection limit reached (60 minutes). Create a new websocket connection to continue. Модель при этом по-прежнему читает весь контекст на каждом ходе, и платишь ты за весь; экономится только передача по сети.

Steering и фоновый режим

В тот же день, что и асинхронные инструменты, появилось событие response.steer: клиент добавляет ввод, пока ответ ещё генерируется. Модель останавливается «at a safe output boundary», ответ получает incomplete_details.reason: "steered", и сервер, по спецификации, «can then create a successor response automatically with the queued input». Если steering пришёл, пока модель ждёт результата клиентского инструмента, после response.completed придёт response.steer.pending: харнесс подставляет сохранённый результат и сам делает response.create. Предупреждение из спецификации: «Do not resend accepted input while it is still queued»6.

Для долгих запросов, которые не укладываются в таймаут HTTP, есть фоновый режим: background: true, затем опрос, пока статус queued или in_progress38. Оборвавшийся поток продолжают параметром starting_after с последним увиденным sequence_number, отмена идемпотентна. Раньше фоновый режим требовал store: true; сейчас гайд разрешает и store=false, тогда данные ответа хранятся на диске около 10 минут, ровно чтобы их можно было забрать опросом.

Следующий шаг в ту же сторону — отдать цикл целиком. 10 сентября 2026 года OpenAI открыла публичную бету Agents API: управляемый харнесс Codex с долгоживущими сессиями и песочницей на стороне OpenAI или своей; 29 сентября туда добавили computer use9. Это уже хостинг агента, а не API модели, и его устройство разбирает глава 12.

WebSocket окупается, когда агент делает десятки вызовов подряд и время на сеть заметно в сквозной задержке. Асинхронные инструменты нужны, когда инструмент долгий (сборка, тесты, выгрузка), а модели есть чем заняться в это время. Если в цикле три-пять быстрых вызовов, выигрыша не будет. Обычный HTTP к тому же проще отлаживать.

Ретраи, лимиты и стоп-краны

С 22 июля 2026 года у OpenAI есть жёсткие лимиты расходов, и запрос, упёршийся в них, получает 429, тот же статус, что и при превышении частоты9. Коды внутри другие: credit_balance_exhausted, organization_spend_limit_exceeded, project_spend_limit_exceeded, organization_usage_limit_exceeded39. Ожиданием не лечится ни один из них, нужен человек с доступом к биллингу. А openai-python по умолчанию повторяет каждый 429 дважды, с нарастающей паузой, при условии, что тело запроса можно безопасно отправить ещё раз40. Если цикл агента оборачивает вызов ещё и своими ретраями, безнадёжный запрос уйдёт десяток раз, прежде чем кто-то увидит ошибку.

К экспоненте добавляют случайный разброс (jitter), чтобы сотня клиентов не пришла обратно в одну и ту же секунду. Коды slow_down и server_is_overloaded появились 2 сентября 2026 года. Остаток лимитов OpenAI показывает в заголовках x-ratelimit-remaining-requests и x-ratelimit-remaining-tokens, рядом лежат парные x-ratelimit-limit-* и x-ratelimit-reset-*39. SDK Anthropic тоже повторяет дважды и учитывает retry-after, если он есть. У большинства моделей cache_read_input_tokens не входят в лимит входных токенов в минуту12, так что кеш поднимает ещё и пропускную способность.

Второй тип стоп-крана касается самого цикла. Лимит шагов (MAX_STEPS) есть в любом примере, и не зря: модель может вызывать один и тот же инструмент без конца. Дефолты у SDK противоположные. В OpenAI Agents SDK константа DEFAULT_MAX_TURNS = 10, и после десятого хода летит MaxTurnsExceeded41. В Claude Agent SDK и max_turns, и max_budget_usd по умолчанию «No limit»42. Первый остановит длинную законную задачу, второй не остановит зациклившуюся. Выставляй оба лимита явно. И помни про max_tokens из раздела о причинах остановки: он ограничивает один запрос, а не задачу. Бюджет задачи считает только твой цикл, складывая usage каждого ответа. Сколько займёт запрос до отправки, можно узнать заранее: у OpenAI есть POST /v1/responses/input_tokens, у Anthropic /v1/messages/count_tokens.

Отключи или ограничь встроенные ретраи SDK (max_retries), если у тебя свой слой повторов, и ветвись по коду ошибки из тела ответа, а не по статусу. Иначе 429 от исчерпанного бюджета повторят сначала SDK, потом твой код, потом внешний цикл, который перезапустит всю задачу.

Агент на пятьдесят строк

Весь механизм главы помещается в сорок с небольшим строк на каждого вендора. Оба варианта собраны из фактов, проверенных по документации, но не запускались, так что прогони их у себя, прежде чем на них опираться. Рассчитаны они на ветки SDK openai 3.x и anthropic 1.x; на 30 сентября 2026 года последние версии — 3.22.1 и 1.9.045.

В варианте для Responses почти каждая строка закрывает одну из ловушек, разобранных выше. store=False и items += resp.output держат историю на твоей стороне и возвращают модели её рассуждения с encrypted_content и сообщения с phase такими, какими они пришли; так код заработает и на серверах, которые Responses поддерживают только без состояния. instructions уходят в каждом запросе, потому что сами они не переносятся. Проверка status ловит обрезанный ответ до того, как его выдадут за готовый. Условие выхода — отсутствие вызовов, а не поле причины. Результат ссылается на call_id, а не на id. Набросок знает только функции: если подключишь shell с локальным окружением, apply_patch или computer, условие выхода станет «в output нет ни одного элемента, который ждёт ответа клиента». Ошибка инструмента, включая вызов несуществующего, уходит модели обычным результатом: так модель может поправить аргументы, а исключение просто уронило бы цикл.

Вариант для Anthropic отличается там, где отличается API. Решение принимается по stop_reason, и все семь значений куда-то ведут. Ответ модели уходит в историю целиком, вместе с блоками thinking: на Opus 5.5 мышление не выключается, и ни один блок нельзя трогать. Все результаты ложатся в одно сообщение user, без текста перед ними, упавший инструмент помечен is_error. pause_turn просто отправляет историю снова, потому что ответ уже дописан. tool_choice не указан: принудительный выбор на этой модели вернул бы 400. И max_tokens=16_000 выбран с умыслом. Для запроса без стрима SDK Anthropic оценивает время как час на 128 тыс. токенов вывода и, если выходит больше десяти минут, ещё до отправки бросает ValueError «Streaming is required for operations that may take longer than 10 minutes»40. Порог — около 21 тыс. токенов. Запас в 25 тыс., который OpenAI советует под рассуждения, здесь уже потребует stream=True или client.messages.stream(...).

Повторы в набросках отданы SDK, поэтому 429 от исчерпанного бюджета будет повторён четыре раза впустую. Бюджета задачи нет, только лимит шагов. Вызовы выполняются по очереди. Нет компакции, когда история перерастёт окно (глава 2), и нет проверки прав перед запуском инструмента (глава 16). Для игрушечного инструмента погоды это неважно, для инструмента, который пишет в базу, критично.

Есть и совсем другой способ, без JSON-вызовов. На minimal-agent.com цикл строится на тексте: системный промпт просит модель заворачивать команду в блок кода с меткой bash-action, харнесс вытаскивает её регулярным выражением и выполняет46. Автор формулирует идею так: «an AI agent is just a big loop: You start with a prompt, the agent proposes an action, you execute the action, tell the LM the output, and then repeat».

Такой цикл работает с любой моделью, которая умеет следовать формату, и ему не нужен ни tools, ни парсер движка. Платишь за это всем, что дают схемы: нет strict, нет проверки аргументов, нет параллельных вызовов, а ошибка формата видна только по тому, что регулярка ничего не нашла. Для учебного агента или модели без поддержки инструментов это разумный выбор. Для всего остального бери JSON-вызовы.

  1. Запусти набросок и напечатай resp.usage на каждом витке. Смотри, как растёт вход, и какую часть из него составляют кешированные токены.
  2. Направь клиент на локальный сервер. Для Ollama это base_url="http://localhost:11434/v1". Выясни, какие поля сервер принимает, а какие пропускает без ошибки: reasoning, strict, max_output_tokens.
  3. Сломай нарочно. В варианте Anthropic поставь текстовый блок перед tool_result и поймай 400. В варианте OpenAI выбрасывай элементы reasoning из истории и сравни ответы на многошаговой задаче.
  4. Посмотри на сырой поток той же задачи через curl -N и найди момент, когда аргументы вызова закрываются.

Слои поверх цикла: SDK и хостинг

After being burned by the rug-pull of OpenAI retiring the Assistants API in favor of Responses last year, I swore off using heavily stateful APIs for language model access. I could be totally wrong, but at this point I'm more willing to use a proprietary harness headless than to abstract it into an API.
— z2, Hacker News, 10 сентября 2026

Комментарий из обсуждения запуска Agents API. На следующий день появился отдельный тред с заголовком «OpenAI Agents API, here we go, the assistant API again?»28

Цикл из предыдущего раздела можно не писать самому. Над API модели за полтора года выросло три этажа, и путают их постоянно, потому что на каждом есть что-то под названием «агент».

OpenAI Agents SDK вышел 11 марта 2025 года вместе с Responses API, а не в 2026-м, как пишут некоторые обзоры9. Его примитивы: Agent, Runner, инструменты, handoffs (передача управления другому агенту как отдельное поле, а не инструмент-обёртка), guardrails, сессии и трассировка. 15 апреля 2026 года добавились агенты с песочницей для долгой работы в контейнере, 6 мая — полный паритет версии для TypeScript. Цикл раннера описан явно: вызвать модель; если получен финальный вывод нужного типа без вызовов инструментов — вернуть; если handoff — сменить агента; если вызовы — выполнить и повторить. Лимит DEFAULT_MAX_TURNS = 10, отключается через max_turns=None; для превышения лимита, отказа модели и невалидного финального вывода есть отдельные обработчики41. SDK работает и с Responses, и с Chat Completions, и с моделями других провайдеров. Последняя версия пакета openai-agents на PyPI — 0.22.3 от 17 сентября 202645.

Claude Agent SDK — это Claude Code в виде библиотеки: пакет несёт с собой бинарник Claude Code и тот же цикл, те же инструменты (Read, Edit, Write, Glob, Grep, Bash, WebSearch, WebFetch и другие), те же режимы разрешений и ту же автоматическую компакцию42. Документация определяет ход так: «a turn is one round trip: Claude produces tool calls, the SDK executes them, and results feed back automatically … turns continue until Claude produces output with no tool calls». Лимиты max_turns (считает только ходы с инструментами) и max_budget_usd по умолчанию отсутствуют, а причину конца видно по ResultMessage.subtype: success, error_max_turns, error_max_budget_usd, error_during_execution, error_max_structured_output_retries. Свои инструменты выполняются по очереди, если не помечены readOnlyHint; компакция отмечается событием compact_boundary. С 15 июня 2026 года на подписочных планах использование Agent SDK списывается из отдельного месячного кредита. Последняя версия пакета claude-agent-sdk — 0.2.162 от 29 сентября 202645. Цикл, в котором ты работаешь каждый день в Claude Code, — ровно этот.

У Anthropic есть и этаж пониже, который с Agent SDK часто путают: бета-хелпер Tool Runner в обычном SDK (client.beta.messages.tool_runner). Он крутит цикл только по твоим инструментам, без файловой системы и оболочки19. По сути это автоматизированный набросок из прошлого раздела.

Верхний этаж — хостинг агента: у OpenAI это Agents API, у Anthropic — бета Managed Agents. Тред о запуске Agents API на Hacker News за сутки набрал 350 очков и 187 комментариев и разделился почти поровну28. Саймон Уиллисон разобрал в нём три уровня сетевого доступа песочницы и показал, как модель уважает запрет домена и рассуждает о том, чтобы не обходить его через /etc/hosts. Ответ chairhairair уместился в строку: «Perfect for when you want your data to be stolen programmatically». Многие в том же треде пишут свой харнесс поверх сырого API именно потому, что продукты вендоров слишком часто меняют форму.

Армин Ронахер, тот самый, что предложил различать внутренний и внешний цикл, скептичен к циклам без присмотра: модели, по его словам, «avoid strong invariants… add fallbacks instead of making bad states impossible», и в долгих автономных прогонах это усиливается5. Он оставляет такие циклы для кода, который переносят, а не пишут заново, и для короткоживущего: прототипов, разовых проверок. Хостинг агента делает такие прогоны дешёвыми в запуске, и спор этим только обостряется. Что делать на сентябрь 2026 года: напиши сырой цикл один раз, чтобы знать, что делает любой SDK. Для продукта со своими инструментами бери SDK вендора и выставь лимиты ходов и бюджета явно. Хостинг бери, когда песочница и долгие сессии — не твоя специализация, но историю держи так, чтобы её можно было выгрузить: Assistants API дал на переезд ровно год.

Проверь себя

Агент на OpenAI работает, а через LiteLLM к Gemini останавливается сразу после первого вызова инструмента. Где искать причину и как переписать условие?

Скорее всего, цикл выходит по полю причины остановки: провайдер вернул finish_reason: "stop" при непустом tool_calls, как в opencode #14972. Продолжать цикл или нет, решай по наличию вызовов в ответе; причину остановки смотри, только когда вызовов нет.

Харнесс перевели на previous_response_id, а счёт не уменьшился. Почему и что его на самом деле снижает?

Все input-токены цепочки оплачиваются на каждом ходе заново: модель читает весь контекст, параметр только избавляет от пересылки по сети. Снижает счёт кеш префикса, а он работает, пока новый запрос точно продолжает старый. Заодно проверь, что instructions присылаются каждый раз: через цепочку они не переносятся.

Цикл на Chat Completions, работавший на GPT-5.x, переключили на gpt-6-astra. Что произойдёт и какие есть выходы?

Chat Completions не поддерживает вызов функций на GPT-6 Astra и GPT-6.1 Sol. Выходы: перевести цикл на Responses API или взять GPT-6 Sol или Luna с reasoning_effort: "none", где вызов через Chat Completions ещё разрешён.

В потоке Chat Completions пришёл кусок вызова без id и name. Как понять, чей он, и когда можно разбирать аргументы?

По обязательному полю index: id и имя есть только в первом куске каждого вызова. Аргументы — фрагменты строки, разбирать их можно после того, как вызов закрыт, то есть после чанка с finish_reason.

Claude вернул stop_reason: "refusal" и пустой content. Что отдаст цикл, который проверяет только «нет tool_use — вернуть текст», и что должно быть вместо этого?

Пустую строку в роли ответа, причём с 24 сентября 2026 года такой отказ в ряде категорий ещё и оплачен. Нужна отдельная ветка: прочитать stop_details (категорию и объяснение), затем запасная модель, в том числе серверная через fallbacks: "default", или честное сообщение пользователю.

Почему плохо убирать инструмент из tools посреди разговора и что предлагают вместо этого OpenAI и Anthropic?

Массив tools стоит в самом начале префикса, любая правка сбрасывает кеш всего разговора. У OpenAI есть tool_choice с типом allowed_tools, который сужает выбор без правки списка. У Anthropic — системное сообщение в конце истории с блоком tool_removal (бета inline-tools-2026-09-15).

В истории разговора с Sonnet 5.5 исправили опечатку в первом сообщении пользователя и отправили запрос снова. Что будет?

Блоки thinking привязаны к неизменному префиксу: аккаунт, созданный 31 августа 2026 года или позже, получит 400, а с заголовком thinking-binding-controls-2026-08-01 рассуждения молча выбросятся. Кеш в любом случае пересчитается с начала. Исправление нужно дописать в конец, например системным сообщением.

В описаниях инструментов стоит strict: true, а с Claude ты общаешься через его OpenAI-совместимый эндпоинт. Какую гарантию схемы ты получаешь?

Никакой. Этот слой молча игнорирует strict и response_format, генерация идёт без ограничений. Нужна гарантия — работай с родным Messages API и его strict-инструментами или output_config.format.

Пришёл 429 с кодом project_spend_limit_exceeded. Что сделает openai-python по умолчанию и что должен сделать твой цикл?

SDK повторит запрос дважды, впустую: бюджет от ожидания не вырастет. Цикл должен ветвиться по коду ошибки, остановиться и позвать человека, а не передавать ошибку своим ретраям или внешнему циклу.

Почему vLLM просит --tool-call-parser под конкретную модель, а у API OpenAI такого параметра нет?

Формат вызова задаётся при обучении модели: Harmony, DeepSeek и GLM пишут один и тот же вызов разными токенами. У хостинга вендора и шаблон, и парсер спрятаны внутри API. Открытый движок вынужден держать парсер под каждое семейство моделей, отсюда проблема M×N и регулярные поломки парсеров.

Рассуждающая модель вернула status: "incomplete" с причиной max_output_tokens и без текста. Что случилось?

Лимит вывода общий для рассуждений и ответа, и рассуждения съели его весь раньше, чем модель дошла до текста. Подними max_output_tokens; OpenAI советует начинать с резерва не меньше 25 тыс. токенов.

Агент на OpenAI Agents SDK падает с MaxTurnsExceeded на задаче из 15 шагов, а похожий на Claude Agent SDK однажды крутился всю ночь. Какие дефолты виноваты?

В OpenAI Agents SDK DEFAULT_MAX_TURNS = 10. В Claude Agent SDK у max_turns и max_budget_usd лимита по умолчанию нет. Оба значения надо выставлять явно под задачу.
