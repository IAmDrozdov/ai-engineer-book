Deep agents: устройство Claude Code, Cursor и OpenClaw

В июле 2026 года инженеры Systima поставили логирующий прокси между Claude Code и API и посчитали, сколько токенов уходит в модель до того, как она прочтёт вопрос пользователя: около 33 тысяч. OpenCode на той же модели отправил 6,9 тысячи, а автор Pi уверяет, что его агенту хватает меньше тысячи. Всё это разница в харнессе — коде, который решает, что положить в запрос, когда отдать работу сабагенту, что забыть и у кого спросить разрешения.

Что харнесс отправляет вместо тебя

Из примерно 33 тыс. токенов Claude Code 2.1.207 около 24 тыс. приходится на JSON-схемы 27 инструментов. Остальное — системный промпт из трёх блоков на 27 344 символа и 7 997 символов обвязки первого сообщения в тегах <system-reminder>1. У OpenCode 1.17.18 из 6,9 тыс. на десять инструментов уходит 4,8 тыс., а промпт идёт одним блоком на 9 324 символа, без обвязки. Мерили на одной модели, claude-sonnet-4-5, по три прогона на харнесс. Тот же прокси показал и вторую вещь: когда агент раздал работу двум сабагентам, общий расход токенов вырос в 4,2 раза.

Системные напоминания (system reminders) харнесс подкладывает рядом с сообщением пользователя: туда идут CLAUDE.md, правила стиля вывода, уведомления о том, что файл изменился на диске, строки атрибуции2. Отсюда поведение, которое будто берётся ниоткуда, вроде трейлера Co-Authored-By в коммите: его просит не модель, а напоминание.

Эти тысячи — буквальный ответ на вопрос, что такое харнесс (harness, «упряжь»). Документация Claude Code определяет его так: «the tools, context management, and execution environment that turn a language model into a capable coding agent. Claude Code is the harness; Claude is the model inside it»2. В LangChain ту же мысль сжали в формулу Agent = Model + Harness: модель даёт интеллект, а промпты, инструменты, цикл, управление контекстом, песочницу и хуки даёт харнесс3. Цикл из двадцати строк из главы 1 — его сердцевина, и почти всё интересное в современных агентах наросло вокруг неё.

Из замера не следует, что Claude Code расточителен. В справочнике его инструментов на сентябрь 2026 года есть запуск сабагентов, отложенная загрузка других инструментов (ToolSearch), фоновые задачи с потоковым выводом (Monitor), планировщик по cron, git worktree, сообщения другим сессиям4. Каждая схема — возможность, за которую платят местом в окне на каждом ходе. Схемы MCP-инструментов по умолчанию как раз откладываются: в окне лежат только их имена, а полная схема подгружается через ToolSearch2, так что 24 тыс. — цена встроенных инструментов. Кеш префикса делает эти токены дешёвыми (глава 2), но место в окне и внимание модели они занимают всё равно. Марио Цехнер, автор Pi, сделал противоположную ставку: четыре инструмента (read, write, edit, bash) и меньше тысячи токенов на промпт вместе с ними5. Какая ставка выигрывает на бенчмарках, разобрано в разделе о цифрах.

Три окна в закрытый харнесс

Исходники Claude Code закрыты, но заглянуть внутрь можно тремя способами. Первый — документация и Claude Agent SDK. SDK — тот же харнесс в виде библиотеки для Python и TypeScript, «the same tools, agent loop, and context management that power Claude Code»6. Версии идут вровень с CLI: 29 сентября 2026 года вышли Claude Code 2.1.285 и пакет @anthropic-ai/claude-agent-sdk 0.3.285, у Python-пакета claude-agent-sdk своя нумерация, 0.2.1627. Чейнджлог CLI расписан по каждой версии8, и больше десятка решений в этой главе датированы по нему.

Второе окно открылось случайно. 30 марта 2026 года в npm ушла версия 2.1.88 с файлом cli.js.map, внутри которого лежали исходники. Тред на Hacker News набрал 2 095 очков, за утечкой последовали DMCA-запросы к зеркалам, а Борис Черный из команды Claude Code назвал случившееся ошибкой разработчика9. Пересказы утечки до сих пор ходят по блогам с названиями KAIROS, autoDream и coordinator mode.

KAIROS, autoDream и coordinatorMode.ts — код за фича-флагами, который на момент утечки не был выпущен. Не описывай их как возможности Claude Code, пока их нет в документации или чейнджлоге: флаг из марта говорит о планах, а не о том, что работает у тебя в терминале.

Третье окно — постмортем Anthropic от 23 апреля 2026 года10. Весной пользователи массово жаловались, что Claude в Claude Code поглупел и стал забывчивым. Причин нашли три, и все в харнессе. Четвёртого марта уровень рассуждений по умолчанию снизили с high до medium, чтобы не подвисал интерфейс, и вернули только седьмого апреля. Двадцать шестого марта выкатили ошибку кеширования, из-за которой история рассуждений очищалась на каждом ходе, а не один раз: модель теряла нить, лимиты таяли быстрее, и так продолжалось 15 дней, до десятого апреля. Шестнадцатого апреля в системный промпт добавили требование укладываться в 25 слов между вызовами инструментов, и вместе с другими изменениями это стоило 3% качества кода на Opus 4.6 и 4.7; откатили через четыре дня. Веса модели всё это время не менялись. Тред с разбором на Hacker News собрал 942 очка и 732 комментария.

Поведение агента зависит от модели и харнесса вместе. Когда кажется, что модель поглупела, сначала сверь версию харнесса с чейнджлогом, а уже потом ищи подмену модели.

Цикл на уровне сообщений

Agent SDK отдаёт работу харнесса потоком из пяти типов сообщений, и по ним видно, где кончается модель и начинается обвязка6. Минимальный клиент из документации; как и там, обёртка async def main() с asyncio.run(main()) опущена:

Первым приходит SystemMessage с подтипом init: сессия создана, инструменты подключены. Дальше чередуются AssistantMessage, то есть сгенерированное моделью, и UserMessage с результатами инструментов. Роль user здесь формальная: в Messages API результат tool call возвращается от имени пользователя (глава 1). Пара «вызов — результат» называется ходом (turn). Цикл заканчивается, когда модель ответила без единого tool_use, и тогда приходит ResultMessage со стоимостью, расходом токенов, session_id и подтипом: success или причина остановки. Прочие подтипы SystemMessage сообщают о служебных событиях; например, compact_boundary отмечает место, где харнесс сжал историю.

Два ограничителя SDK стоит помнить. max_turns считает только ходы с инструментами. max_budget_usd считает деньги, включая траты сабагентов: когда бюджет кончился, фоновые сабагенты останавливаются, а новые не стартуют с ошибкой Budget limit reached. Порядок выполнения тоже выбирает харнесс. Читающие инструменты (Read, Glob, Grep и MCP-инструменты с аннотацией readOnlyHint) идут параллельно, изменяющие (Edit, Write, Bash) — строго по одному.

Codex: запрос как точный префикс

OpenAI в январе 2026 года расписала цикл Codex CLI до отдельных элементов запроса11. Codex работает поверх Responses API и перед первым сообщением пользователя кладёт в input четыре элемента в фиксированном порядке. Сообщение с ролью developer описывает песочницу и правила одобрения. Касается оно только встроенного инструмента shell; инструменты MCP-серверов, как пишет OpenAI, «are not sandboxed by Codex». Затем идут необязательные developer_instructions из config.toml. Третьим — сообщение с ролью user, где склеены AGENTS.override.md и AGENTS.md из $CODEX_HOME и из каждой папки от корня git-репозитория до текущей, с общим лимитом 32 КиБ по умолчанию, и описания скиллов. Последним идёт <environment_context> с текущей папкой и шеллом.

Codex не пользуется previous_response_id, хотя Responses API умеет хранить историю на сервере: «primarily to keep requests fully stateless and to support Zero Data Retention (ZDR)». Цена такого решения — объём JSON, который клиент отправляет за сессию, растёт квадратично. Семплирование при этом остаётся линейным, потому что каждый новый запрос — старый плюс новые элементы в конце, и общий префикс провайдер берёт из кеша. Отсюда список того, что ломает кеш посреди разговора: смена набора инструментов, модели, режима песочницы или одобрений, текущей папки. Рецепт OpenAI — не править старое сообщение, а дописать новое. Был и настоящий баг: MCP-инструменты перечислялись в нестабильном порядке, и префикс менялся без всякой причины. Подробный разбор таких поломок кеша — в главе 2.

Компакция в Codex устроена в том же духе. Когда контекст превышает auto_compact_limit, харнесс вызывает эндпоинт /responses/compact и получает элементы, среди которых «a special type=compaction item with an opaque encrypted_content… that preserves the model's latent understanding». Это сводка, которую может прочитать только модель; чем такой подход отличается от текстовой сводки Claude Code, видно в разделе о компакции.

Харнесс под конкретную модель

Cursor в декабре 2025 года рассказал, как подстраивал своего агента под модели OpenAI Codex, и первая же фраза поста снимает иллюзию универсального агента: «Every model in Cursor's agent harness has specific instructions and tools made available to optimize that model inside the Cursor environment»12. Инструменты переименовали ближе к привычным командам шелла вроде rg, и прижилось это у всех моделей. Модель попросили вызывать read_lints после каждой правки. Следы рассуждений (reasoning traces) между ходами теперь сохраняют обязательно: когда их убрали, GPT-5-Codex потерял 30% на внутреннем Cursor Bench, а у OpenAI GPT-5 без них терял на SWE-bench всего 3%.

В промпте Cursor была просьба беречь токены, и Codex начал отказываться от больших задач с объяснением «I'm not supposed to waste tokens…». Инструкция, безобидная для одной модели, для другой стала запретом. Летом 2026 года Cursor по похожей причине пропустил GPT-5.6 Sol: модель «appears more sensitive to literal and emphasized wording… we encountered runaway spirals»13. В LangChain отмечают обратную сторону: модель, которую дообучали с конкретным харнессом в цикле, к нему переобучается, и Codex-модели тянутся к shell и apply_patch3.

Сменил модель в своём агенте — прогони eval заново и перечитай системный промпт. Инструкция, написанная под прошлую модель, у новой может сработать буквальнее и превратиться в запрет.

Четыре столпа Чейза и ревизия 2026 года

«It's basically a no-op. It's just context engineering strategy to keep the agent on track» — так Харрисон Чейз из LangChain 30 июля 2025 года описал инструмент TodoWrite в Claude Code14. Пост назывался «Deep Agents» и дал имя целому классу систем. Обычный агент, по Чейзу, мелкий (shallow): LLM в цикле вызывает инструменты и на длинных задачах теряет нить. Глубокий агент (deep agent) добавляет к тому же циклу четыре вещи: подробный системный промпт с примерами использования инструментов, инструмент планирования, сабагентов и файловую систему как общую рабочую память. Образцами служили Claude Code, Manus и Deep Research.

В те же выходные LangChain выложила пакет deepagents. На 29 сентября 2026 года это версия 0.7.20 на PyPI и 1.14.1 для JavaScript, а в README он называется «batteries-included agent harness» поверх LangGraph: сабагенты, подключаемые файловые бэкенды, сжатие длинных тредов с выгрузкой вывода на диск, шелл, постоянная память, одобрение вызовов человеком и скиллы15. Пакет давно перерос четыре пункта из поста, и за год два из этих пунктов сдвинулись.

Планировщик переехал в артефакты

No-op работал из-за устройства внимания. Manus в июле 2025 года описывала тот же приём как декламацию (recitation): агент на каждом шаге переписывает todo.md и тем выталкивает общий план в конец контекста, в зону свежего внимания16. Средняя задача Manus тогда занимала около 50 вызовов инструментов, и без такого повтора цель тонула в середине истории. Инструмент ничего не исполняет, он только заставляет модель пересказать план своими словами.

Новые модели научились держать план сами, и инструмент стал стоить больше, чем давал. Claude Code прошёл этот путь в два шага. 22 января 2026 года, в версии 2.1.16, TodoWrite заменили системой задач с зависимостями (TaskCreate, TaskUpdate и соседи). 14 августа, в 2.1.233, убрали и её: инструменты учёта задач больше не предлагаются Opus 4.8, Sonnet 5, Fable 5, Mythos 5 и более новым моделям8. Объяснение из справочника инструментов: «On newer models, Claude keeps track of multi-step work without a written checklist, and the tools' definitions and reminders take up context»4. В deepagents то же случилось 29 июля 2026 года: с версии 0.7 планирование включается только явно, отдельным middleware15. У Pi инструмента планирования не было никогда: Цехнер сознательно выбросил из своего агента план, todo и сабагентов5.

В Claude Code вместо инструмента теперь режим планирования (EnterPlanMode и ExitPlanMode), где модель исследует код и пишет план, ничего не меняя, и /goal из версии 2.1.139 (11 мая 2026 года): «set a completion condition and Claude keeps working across turns until it's met»8. Команда /goal появилась и в Cursor в августе17, а у Codex цели с автоматическим продолжением включены по умолчанию18. В OpenAI планы выполнения лежат в репозитории как версионируемые файлы19, у Anthropic для многосессионной работы план — JSON-список фич (о нём в разделе про длинные задачи). Общее у всех одно: план проверяется снаружи файлом, тестом или условием и не живёт только в голове модели.

Подробный промпт или карта

Второй спорный столп — подробный системный промпт. Чейз писал, что без длинных промптов агенты «would not be nearly as deep»14. Промпт самого харнесса и правда длинный, это те 27 тыс. символов в трёх блоках из замера Systima. Проблемы начались, когда ту же идею перенесли на пользовательские файлы инструкций.

OpenAI за пять месяцев построила внутренний продукт примерно на миллион строк, где, по её словам, нет ни одной строки кода, набранной руками: около 1 500 смёрженных PR, 3,5 PR на инженера в день19. Первым делом там попробовали «one big AGENTS.md», и подход провалился предсказуемо. «Context is a scarce resource», «Too much guidance becomes non-guidance», файл «rots instantly», и проверить его механически нельзя. Вместо него — «give Codex a map, not a 1,000-page instruction manual». AGENTS.md сократили примерно до ста строк оглавления, а знание разложили по структурированной папке docs/, свежесть которой проверяет CI.

These files load unconditionally, they often contain descriptions irrelevant to the task at hand, and they stack from your working directory upward. The result is wasted tokens and confusion from injecting irrelevant instructions into the session.
— sermakarevich, Show HN: Lessons learned from running Claude Code swarms at scale, июнь 2026

Автор гонял 10–15 агентов Claude Code параллельно и назвал CLAUDE.md «a terrible abstraction»20. Файлы грузятся целиком, всегда и стопкой от текущей папки вверх, так что каждый агент получает инструкции, не имеющие отношения к его задаче.

Чейз считает длинный промпт признаком глубокого агента, OpenAI и полевые отчёты видят в нём источник шума. Противоречие во многом мнимое: длинный промпт харнесса пишут один раз и проверяют evals, а твой CLAUDE.md или AGENTS.md грузится в каждую сессию и стареет вместе с кодом. На твоём месте разумно держать его картой на сотню строк (документация Claude Code советует укладываться в 2002), а подробности уносить в скиллы и docs/, которые грузятся по запросу.

Два других столпа, сабагенты и файловая система, за год только выросли. К ним добавились три вещи, которых у Чейза не было: скиллы с загрузкой по запросу, компакция с выгрузкой вывода на диск и цикл проверки, который не даёт агенту объявить работу сделанной. В «The Anatomy of an Agent Harness» (март 2026 года) LangChain уже перечисляет их как равноправные части харнесса3.

Deep agent в 2026 году определяется не набором инструментов, а тем, как харнесс держит длинную задачу: изолирует контекст сабагентами, выносит состояние в файлы, грузит знания по запросу, сжимает историю и проверяет результат чем-то внешним.

Сабагент — способ выбросить контекст

В документации Claude Code есть пошаговый разбор сессии, где сабагент-исследователь читает файлы на 6 100 токенов и возвращает родителю сводку на 420. Подпись к шагу: «that's the context savings»2. Прочитанное остаётся в чужом окне и умирает вместе с ним, в этом и вся экономия.

Граница проведена жёстко621. Сабагент стартует без истории родителя. Внутрь попадают его собственный системный промпт из описания агента, строка prompt из вызова инструмента Agent, проектный CLAUDE.md (если не выставлен omitClaudeMd: true) и разрешённые инструменты. Результаты инструментов родителя, его системный промпт и скиллы туда не попадают, скиллы — если их не перечислили явно. Наружу уходит одно последнее сообщение сабагента, которое становится результатом вызова Agent. Раньше этот инструмент назывался Task, и SDK советует проверять в своих обработчиках оба имени.

Из полей, появившихся в 2026 году, пригодятся effort, isolation: worktree (сабагент работает в отдельной git-копии), background и memory — постоянная память сабагента в .claude/agent-memory/<name>/, которая подмешивается в его системный промпт (о таких файлах — глава 11). Встроенных сабагентов три: Explore для быстрого поиска только на чтение, Plan для исследования в режиме планирования и универсальный general-purpose. С версии 2.1.198 (1 июля 2026 года) Explore больше не работает на Haiku, а наследует модель основной сессии с потолком Opus8, так что старый совет «Explore дешёвый, пусть ищет» уже неверен.

Сабагенты умеют порождать своих сабагентов, и харнесс это ограничивает. Глубина вложенности по умолчанию равна трём с версии 2.1.219 (24 июля 2026 года; в двух предыдущих версиях была единица), одновременно работают до 20 сабагентов, а бюджет считает расходы всего дерева226. Переменная CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION, которая встречается в старых инструкциях, с версии 2.1.224 ничего не делает.

Изоляция не бесплатна. Сабагент заново читает то, что родитель уже знал, и в замере Systima раздача работы двум сабагентам увеличила расход токенов в 4,2 раза1. Если задача помещается в одно окно без мусора, сабагент её только удорожит.

Есть и цена менее очевидная. Итоговое сообщение сабагента родитель читает как результат инструмента, и сабагент, начитавшийся чужих файлов, может принести в нём инъекцию. С версии 2.1.210 Claude Code перед передачей сканирует этот текст: в поддельные управляющие теги вроде <system-reminder> вставляет обратный слэш, экранирует строки, начинающиеся с Human: или Assistant:, и помечает упоминания настроек разрешений6. В auto mode, где вызовы одобряет классификатор, а не человек (о нём в разделе о разрешениях), к этому добавляются классификаторы на передаче задачи (могут запретить) и на возврате результата (только предупреждают)23.

Форк: сабагент, который помнит всё

С версии 2.1.232 (13 августа 2026 года) в интерактивных сессиях по умолчанию включён другой вид сабагента — форк. Он «inherits the full conversation and prompt cache instead of starting fresh», и все сабагенты, которых запускает Claude, теперь по умолчанию уходят в фон8. Запросить форк можно и руками:

Форк решает другую задачу. Обычный сабагент нужен ради чистого окна, форк — ради параллельной работы без повторного чтения. Он стартует с кешированного префикса родителя и потому дёшев на старте, но всю историю родителя несёт с собой и от шума не спасает. С версии 2.1.285 форки работают в режиме разрешений родителя и не могут выйти из режима планирования8. Выключается фича переменной CLAUDE_CODE_FORK_SUBAGENT=0.

Четыре ступени оркестрации

Над сабагентами в Claude Code надстроены ещё два механизма, и все четыре различаются прежде всего тем, где живёт план21.

Команды агентов (agent teams) появились как research preview в версии 2.1.32 (5 февраля 2026 года) и включаются переменной CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=18. Главная сессия становится лидом и запускает тиммейтов, полноценные независимые сессии Claude Code со своими окнами. Они пишут друг другу через почтовые ящики в ~/.claude/teams/{team}/inboxes/{agent}.json и сами разбирают задачи из общего списка с файловой блокировкой. Документация прямо предупреждает о цене: токенов уходит примерно пропорционально размеру команды, а когда тиммейты работают в режиме планирования, около 7 раз больше, чем в обычной сессии21. Есть и ловушка: «while agent teams are enabled, a subagent that Claude names launches as a teammate». Claude сам даёт сабагенту имя, чтобы потом ему написать, и команда собирается без твоей просьбы.

Dynamic workflows вышли в версии 2.1.154 (28 мая 2026 года)8. Claude пишет на JavaScript скрипт из вызовов agent(), parallel(), pipeline() и phase(), а исполняет его отдельный рантайм. Циклы, ветвления и промежуточные результаты живут в переменных скрипта, в окно Claude приходит только итог21:

Тело скрипта — обычный JavaScript с await и return на верхнем уровне: его исполняет рантайм, и как самостоятельный модуль такой файл не запустится. Рантайм следит и за воспроизводимостью: Date.now(), Math.random() и new Date() без аргументов внутри скрипта бросают исключение, чтобы прерванный и перезапущенный прогон повторил те же вызовы agent(). Пределы жёсткие: до 16 агентов одновременно (с версии 2.1.269 настраивается от 1 до 256), до 1 000 агентов за прогон и до 4 096 элементов на один вызов parallel() или pipeline(). Выше 25 агентов или 1,5 млн прогнозных токенов появляется предупреждение Large workflow21. Ключевое слово для запуска сначала было workflow, с версии 2.1.160 стало ultracode, а с 2.1.284 (28 сентября) Ultracode — отдельный переключатель в /effort, который больше не поднимает effort до xhigh8. В блоге о запуске команда Claude Code назвала три сбоя, против которых всё это придумано: агентная лень (агент останавливается раньше времени), предвзятость агента к собственной работе при проверке и дрейф цели на длинном прогоне24.

У конкурентов лестница короче, но похожа. В Codex сабагенты включены по умолчанию, а между их потоками переключаются командой /agent18. Cursor с августа 2026 года запускает сабагентов на отдельных виртуальных машинах, а 10 сентября выпустил Projects с координатором, который «doesn't write code itself» и раздаёт работу тысячам сабагентов17. Как выбирать топологию для своей системы, разбирает глава 13; внутри Claude Code хватает простого правила.

Нужен ответ без мусора в окне — обычный сабагент. Нужно параллельно сделать что-то, для чего важен весь разговор, — форк. Несколько долгих исполнителей, которые должны спорить друг с другом, — команда, если готов платить. Десятки однотипных задач по списку — workflow: план в коде, а не в чьей-то голове.

Файлы вместо контекста

В январе 2026 года Cursor провёл A/B-тест: описания инструментов MCP-серверов перестали класть в промпт и начали синхронизировать в папку, по одной на сервер, откуда агент читает их сам, когда нужно. В прогонах, где вызывался хотя бы один MCP-инструмент, общий расход токенов упал на 46,9%, хотя разброс между прогонами был большой25. Плоский поиск по инструментам в Cursor тоже рассматривали и выбрали папки.

Этот приём — один из пяти, которые Cursor объединил под названием dynamic context discovery: заранее давать меньше деталей и оставлять агенту возможность самому достать нужное из файлов. Длинный вывод инструмента пишется в файл, агент читает его хвост и при необходимости дочитывает. История чата после суммаризации остаётся файлом, в котором можно искать. Знания уезжают в Agent Skills. Описания MCP-инструментов лежат по папкам. Вывод встроенного терминала синхронизируется в файлы.

В сентябре 2026 года Cursor отчитался, что дала та же линия на длинных прогонах26. Системный промпт урезали примерно на 66%, описания встроенных инструментов вынесли из постоянного контекста и сократили там на 60%, холодных промахов кеша стало на 20% меньше. Даже номера строк пошли под нож: их ставят у каждой десятой строки, а не у каждой, и это срезало 1,6% токенов, читаемых из кеша. Итог — минус 7% стоимости для пользователей «without reducing agent quality», по замеру самого Cursor. Ни один из этих рычагов не трогает модель.

Принцип старше обоих постов Cursor. Manus в 2025 году называла его восстановимым сжатием: «the content of a web page can be dropped from the context as long as the URL is preserved»16. Выбросить из окна можно всё, к чему остался путь назад. Файловая система в такой схеме работает внешней памятью без ограничения размера, и агент сам решает, что поднять обратно. Остальные приёмы сжатия разобраны в главе 2.

Anthropic довела ту же идею до архитектуры. В Managed Agents (пост от 8 апреля 2026 года) три виртуализированные части: сессия, то есть «the append-only log of everything that happened», харнесс, то есть цикл, который вызывает Claude и маршрутизирует вызовы инструментов, и песочница27. «The session is not Claude's context window»: журнал живёт вне окна, харнесс берёт из него срез через getEvents() и сам решает, что показать модели. Инструменты вызываются через execute(name, input) → string, а упавший харнесс поднимается вызовом wake(sessionId). После того как харнесс отделили от контейнера, задержка до первого токена упала примерно на 60% по медиане и больше чем на 90% в 95-м перцентиле. Токены доступа к git и к MCP в песочницу, где выполняется код Claude, при этом не попадают вообще.

Скиллы и их бюджет

Скиллы применяют тот же принцип к знаниям: в контексте постоянно лежит только короткое описание, тело грузится при вызове (формат и уровни загрузки — глава 6). Но и описания занимают место, и у Claude Code для них есть бюджет, о котором долго знали только из полевых отчётов. Теперь он описан в документации: «The listing always contains every skill name, but if you have many skills, Claude Code drops some descriptions to fit the listing's character budget… The budget scales at 1% of the model's context window. When the listing overflows, Claude Code drops descriptions starting with the skills you invoke least»21. Описание вместе с when_to_use обрезается на 1 536 символах. Бюджет настраивается ключом skillListingBudgetFraction и переменной SLASH_COMMAND_TOOL_CHAR_BUDGET, а /skill-doctor с версии 2.1.252 показывает, сколько контекста стоит каждый скилл8.

You can't create 10K skills, as that would eat your entire usable context.
— sermakarevich, Hacker News, июнь 2026

Тот же автор заметил, что редко вызываемые скиллы пропадают из фоновых сессий, и не нашёл этому объяснения в документации20. Теперь механизм описан: имя скилла остаётся в списке, а описание исчезает, и модели становится не по чему понять, что скилл подходит к задаче.

Рой агентов Cursor пришёл к тому же с другой стороны. Агенты сами ведут общую папку Field Guide, и её index.md автоматически подмешивается в каждого агента13. В контексте лежит индекс, всё остальное доступно по ссылке.

Открой /context в своём проекте и найди, что Claude Code держит в окне постоянно. Большие справочники из CLAUDE.md можно превратить в скиллы или файлы в docs/, а длинные логи — в файлы, которые агент грепает, а не читает целиком.

Когда окно кончается

Claude Code на моделях с родным окном в миллион токенов (Sonnet 5 и 5.5, Fable, Opus 4.7 и новее через API Anthropic) сжимает историю «at about 967K tokens by default»22. Размер окна, на котором срабатывает автокомпакция, настраивается от 100 тыс. до 1 млн командой /autocompact 500k, флагом --autocompact или переменной CLAUDE_CODE_AUTO_COMPACT_WINDOW. Старая переменная CLAUDE_AUTOCOMPACT_PCT_OVERRIDE, которую до сих пор советуют в блогах, «can't raise the threshold»: ею порог можно только опустить22.

Сжатие идёт в два приёма: сначала из истории вычищаются старые результаты инструментов, потом разговор суммаризируется2. По документации, сводка сохраняет запросы и намерения пользователя, ключевые технические решения, просмотренные и изменённые файлы с важными фрагментами кода, ошибки и их исправления, незаконченные задачи и текущую работу, а «full tool outputs and intermediate reasoning are gone»2. После сводки харнесс заново читает до пяти недавно изменённых файлов и возвращает тела вызванных скиллов: первые 5 000 токенов каждого, всего не больше 25 000, начиная с последнего вызванного21. CLAUDE.md и auto memory перечитываются с диска. Инструкции, которые ты давал только в чате, могут пропасть.

Если один результат инструмента так велик, что окно заполняется сразу после сжатия, Claude Code после нескольких попыток прекращает автокомпакцию и показывает ошибку, а не крутится вечно2. В самописном харнессе такого предохранителя нет, пока ты его не напишешь, и цикл «сжал, заполнил, сжал» сожжёт бюджет.

Сводкой можно управлять. Компактор ищет в CLAUDE.md раздел с инструкциями для суммаризации и «matches on intent», так что заголовок может быть любым6. Хук PreCompact срабатывает перед сжатием с полем trigger, равным manual или auto, и успевает сохранить полную расшифровку, а в потоке SDK на месте сжатия появляется SystemMessage с подтипом compact_boundary.

Три харнесса из этой главы сжимают историю тремя разными способами, четвёртый не сжимает вовсе, и разница видна, когда что-то пошло не так.

Для отладки удобнее всего Pi: сессия там дерево, и к любой точке до сжатия можно вернуться. Сводку Claude Code хотя бы можно прочитать и увидеть, что потерялось. Сводку Codex не видит никто, кроме модели, зато OpenAI обещает, что она сохраняет больше, чем текст. Если пишешь свой харнесс, делай как в Pi: сжимай то, что уходит в модель, но не выбрасывай оригинал.

Компакция — не единственный ответ на переполнение. Для Sonnet 4.5 Anthropic делала полный сброс контекста: новый агент с чистым окном и файлом передачи дел. У модели была «тревога контекста» (context anxiety): чувствуя приближение лимита, она сворачивала работу раньше времени29. На Opus 4.5 тревога «largely removed», и сбросы заменили автокомпакцией Agent SDK. Приём, без которого год назад было не обойтись, стал лишним грузом, как потом и спринты из раздела о длинных задачах.

Amp пошёл в обратную сторону и 23 октября 2025 года убрал компакцию совсем: по словам команды, она «encourages long, meandering threads… stacking summary on top of summary»28. Вместо неё пишешь цель, например «/handoff now implement this for teams as well», и Amp по текущей ветке готовит черновик промпта для новой, который можно поправить до отправки.

Больше 200к пихать в модель бессмысленно… Lost in the middle, 2023 год.
— Никита Пастухов, телеграм-канал fastnewsdev, сентябрь 2026

Миллионные окна практиков не убедили30. Многие режут работу на этапы, каждый в отдельной сессии до 100–200 тыс. токенов, и каждая сессия начинается с файла плана. При таком подходе автокомпакция почти не срабатывает, а её место занимает файл, который пишет сам агент.

Кто нажимает «да»

По внутренним данным Anthropic на март 2026 года, пользователи Claude Code одобряли 93% запросов на разрешение23. При такой доле кнопка «да» перестаёт быть проверкой и становится привычкой. Ответом стал auto mode, в котором решение принимает классификатор. 25 марта Anthropic подробно описала, как он устроен.

Вызов инструмента проходит три уровня. На первом стоят встроенный список безопасных инструментов и правила пользователя. При входе в auto mode широкие правила вроде разрешения на любой шелл или на интерпретаторы python* отбрасываются, чтобы опасные вызовы не проходили по ним в обход классификатора. На втором уровне пропускаются без классификатора правки файлов внутри проекта. Всё остальное уходит на третий уровень, к классификатору расшифровки. На март это Sonnet 4.6, и работает он в две стадии: быстрый фильтр отвечает «да» или «нет» одним токеном, а цепочку рассуждений запускает, только если первая стадия насторожилась.

Самое интересное здесь — чего классификатор не видит. Он «sees only user messages and the agent's tool calls; we strip out Claude's own messages and tool outputs». Рассуждения агента вырезаны, чтобы агент не мог уговорить судью. Вывод инструментов вырезан, чтобы до судьи не добралась инъекция из прочитанной страницы. Против инъекций работает отдельный слой на входе: серверный зонд сканирует результаты инструментов и дописывает предупреждение в контекст самого агента.

Anthropic опубликовала и неудобные цифры. Первая стадия на реальном трафике (10 тыс. вызовов) ложно тревожит в 8,5% случаев, весь конвейер — в 0,4%. Зато пропусков у полного конвейера больше: 17% на выборке из 52 реальных случаев, когда агент делал больше, чем просили, и 5,7% на тысяче синтетических попыток эксфильтрации. Вторая стадия убирает ложные тревоги ценой пропусков: «The 17% false-negative rate… is the honest number». Более поздний внешний замер auto mode против непрямых инъекций разобран в главе 16.

Несмотря на эти 17%, auto mode стал режимом по умолчанию, в несколько приёмов. 14 августа 2026 года — для новых сессий на тарифах Pro, Max и Team8. В версии 2.1.284 (28 сентября) — для интерактивных сессий в терминале и VS Code на всех тарифах и у всех провайдеров, а в 2.1.285 — для claude -p и Python Agent SDK у сторонних провайдеров8. Раз кнопку «да» жмёт классификатор, полезно знать, чем откатываться. Claude Code на каждом ходе снимает чекпойнт файлов, к которому возвращает /rewind; хранятся 100 последних, по умолчанию около 30 дней. Но чекпойнт видит только правки файловых инструментов: изменения через Bash (rm, mv, cp) и большинство правок сабагентов он не вернёт22. После rm спасёт только git.

Три вендора, одна схема

Cursor пришёл к тому же 11 июня 2026 года и сделал Auto-review режимом по умолчанию для новых пользователей31. Маленькая рассуждающая модель работает агентным классификатором в том же RPC-потоке, что и основной агент, и перед разрешением может сама открыть скрипт через ReadFile, Grep, Glob и ListDir. Отказ уходит не пользователю, а основному агенту как обратная связь. Блокируется около 4% проверенных действий, примерно в 7% чатов пользователя хоть раз отвлекают, а у некоторых корпоративных клиентов раньше блокировалось до 40% действий. Для оценки собрали 6 122 размеченные строки из примерно 12 часов внутренних сессий и синтетических атак и прогоняли их по нескольку раз, чтобы поймать «мигание» (flapping), то есть разные вердикты на одном и том же входе.

В Codex граница проведена жёстче18. Агент работает в песочнице read-only или workspace-write и просит одобрения, только когда ему нужно выйти за её пределы. С approvals_reviewer = "auto_review" такой запрос уходит отдельному агенту-ревьюеру, который возвращает решение с обоснованием. При отказе основной агент должен «find a materially safer path or stop and ask the user». По документации, «Auto-review is a reviewer swap, not a permission grant»: ревьюер не расширяет writable_roots, не включает сеть и не ослабляет защищённые пути.

Под всеми тремя классификаторами лежит песочница операционной системы, и классификатор её не заменяет. Claude Code на macOS использует Seatbelt, на Linux — bubblewrap. Писать можно в текущую папку, в папки из --add-dir и во временную, а читать по умолчанию можно почти всё, включая ~/.ssh и ~/.aws/credentials, если не закрыть их через sandbox.credentials. Сеть идёт через прокси вне песочницы, заранее разрешённых доменов нет. Настройки, хуки и .git/{HEAD,objects,refs} защищены, и никакое правило allow их не открывает22. Codex делит то же на режим песочницы (read-only, workspace-write, danger-full-access) и политику одобрений, на тех же Seatbelt и bwrap с seccomp, с защищёнными .git, .agents и .codex и выключенной по умолчанию сетью. Как устроены песочницы и что они не ловят, разбирает глава 16.

Классификатор решает, нужно ли спрашивать; песочница решает, что вообще физически возможно. При 17% пропусков первое без второго не работает.

Хуки и чужие полномочия

Детерминированный слой поверх всего этого — хуки. Хук PreToolUse видит вызов до выполнения и может запретить его, вернув JSON; код выхода 2 блокирует вызов независимо от вывода22. Обработчиком может быть шелл-команда, HTTP-эндпоинт, MCP-инструмент, одноразовый вопрос к модели или экспериментальный агент-проверяющий. Проектные хуки работают только в доверенной рабочей папке, пользовательские из ~/.claude — всегда.

Чем больше агентов, тем важнее, чьим голосом говорит сообщение. С версии 2.1.166 сообщения, которые другие сессии Claude присылают через SendMessage, «no longer carry user authority»: получатель отказывается выполнять пересланные просьбы о разрешениях, а auto mode их блокирует8. Промпты вызовов agent() внутри workflow с версии 2.1.277 размечаются как текст скрипта, чтобы классификатор не принял их за слова пользователя. Сами SendMessage и ListAgents для переписки между твоими сессиями появились в 2.1.224, в первую неделю августа8. В русскоязычных пересказах эту дату смешали с 14 августа, когда auto mode стал режимом по умолчанию, и вышло «входящие сообщения от других сессий принимаются автоматически»30. По чейнджлогу всё наоборот: пересланное сообщение полномочий пользователя не несёт.

Два разных Ральфа

Такой цикл называют Ralph loop, по имени Ральфа Виггама из «Симпсонов». Джеффри Хантли описал технику в июле 2025 года как while :; do cat PROMPT.md | claude-code; done33, а в январе 2026 года сформулировал её жёстче: «Ralph is monolithic. Ralph works autonomously in a single repository as a single process that performs one task per loop». Мультиагентные системы он противопоставляет этому прямо: если микросервисы сами недетерминированы, выходит «a red hot mess». Настраивают Ральфа правкой спецификации, а не протоколом между агентами, и сам Хантли советует его только для новых проектов: на старом коде недетерминированный поиск даёт ложные «этого ещё нет» и агент переписывает уже написанное.

Под одним названием живут два разных механизма, и путать их дорого.

Официальный плагин ralph-wiggum появился в репозитории Claude Code 16 ноября 2025 года34. Его Stop-хук перехватывает попытку закончить и подаёт «the SAME prompt back», причём «the loop happens inside your current session». Контекст при этом не сбрасывается. Если тебе нужна чистая голова на каждой итерации, плагин её не даст; нужен внешний цикл.

Та же идея встречается под другими именами. OpenAI просит Codex проверять свои изменения, запрашивать ревью у других агентов и отвечать на замечания «in a loop until all agent reviewers are satisfied (effectively this is a Ralph Wiggum Loop)»19. PreCompletionChecklistMiddleware в LangChain перехватывает выход агента и заставляет его пройти проверку, «similar to a Ralph Wiggum Loop»3.

Инициализатор и журнал смены

Anthropic в ноябре 2025 года описала проблему длинной работы так: каждая новая сессия начинается без памяти о прошлых, как смена инженеров, которые не помнят, что делала предыдущая29. Компакции для этого мало: сводка «doesn't always pass perfectly clear instructions to the next agent». Решением стали две роли с разными промптами. Агент-инициализатор работает один раз: пишет init.sh, который поднимает dev-сервер, журнал claude-progress.txt, список фич feature_list.json (в примере с клоном claude.ai — больше двухсот пунктов) и делает первый коммит. Агент-кодер в каждой следующей сессии читает всё это, делает одну фичу и оставляет репозиторий в чистом состоянии.

Формат выбран не случайно: «the model is less likely to inappropriately change or overwrite JSON files compared to Markdown files». Флаг passes кодер может перевернуть только после проверки от начала до конца, а в промпте сказано: «It is unacceptable to remove or edit tests because this could lead to missing or buggy functionality».

Схема закрывает конкретные сбои, и каждый из них описан в посте. Агент пытался сделать всё приложение за раз, кончалось окно, и следующая сессия гадала, что было недоделано. Следующая сессия видела часть работы и объявляла проект готовым. Фичи отмечались как готовые без проверки. Отдельно отмечено, что Claude не проверял поведение от начала до конца, пока его об этом прямо не попросили: браузерную автоматизацию через Puppeteer MCP пришлось вписывать в промпт.

Планировщик, исполнитель, оценщик

Через четыре месяца, 24 марта 2026 года, Anthropic опубликовала второе поколение схемы29. Главный враг теперь — самооценка: «agents tend to respond by confidently praising the work». Поэтому ролей стало три. Планировщик превращает одно-четыре предложения в спецификацию продукта, нарочно высокоуровневую. Исполнитель работает спринтами. Оценщик кликает по приложению через Playwright MCP и выставляет оценки с жёсткими порогами по каждому критерию. Перед каждым спринтом исполнитель и оценщик через файлы договариваются о контракте спринта, то есть о том, что будет считаться сделанным.

Это дорого. Игру-конструктор в ретростиле одиночный агент на Opus 4.5 сделал за 20 минут и $9, полный харнесс — за 6 часов и $200. С выходом Opus 4.6 харнесс начали упрощать, убирая компоненты по одному и проверяя, что сломается. Спринты ушли, оценщик стал делать один проход в конце. Цифровая звуковая рабочая станция (DAW) на упрощённом харнессе обошлась в $124,70 за 3 часа 50 минут, из которых $0,46 стоил планировщик, три раунда сборки — $71,08, $36,89 и $5,88, а три прохода оценщика — $3,24, $3,09 и $4,06. Главный вывод авторов переносится на любой харнесс: «every component in a harness encodes an assumption about what the model can't do on its own, and those assumptions are worth stress testing».

Каждый компонент харнесса — ставка на слабость текущей модели. Сбросы контекста, todo-инструмент и спринты были нужны, пока модель не справлялась без них, и стали лишним весом, когда справилась. Прогоняй свой харнесс без каждой детали при каждой смене модели.

Рои: двадцать агентов работают как три

Cursor в январе 2026 года попробовал другой масштаб и сначала провалился13. Агенты координировались сами через общий файл с блокировками, и «Twenty agents would slow down to the effective throughput of two or three». Оптимистичная конкурентность оказалась устойчивее, но агенты стали осторожничать. Заработала иерархия: планировщики, которые рекурсивно порождают подпланировщиков, исполнители и судья на каждом цикле. Так за неделю собрали браузер, больше миллиона строк в тысяче файлов. Вывод Уилсона Лина: «The harness and models matter, but the prompts matter more».

К июлю правила стали жёстче: планировщики никогда не пишут код, исполнители никогда не планируют. Git не выдерживал, и Cursor написал свою систему контроля версий примерно на 1 000 коммитов в секунду против примерно 1 000 в час у git. Появились нейтральный агент для слияний, отлов разросшихся файлов и та самая общая папка Field Guide. Старый рой за два часа делал 68 тыс. коммитов и больше 70 тыс. конфликтов, новый — меньше тысячи конфликтов. На задаче написать SQLite на Rust по руководству в 835 страниц новый харнесс за четыре часа проходил 73–85% отложенных тестов sqllogictest против 11–77% у старого. Разные сочетания моделей в итоге доходили до похожего качества, а вот цена отличалась почти в восемь раз: от $1 339 (Opus 4.8 планирует, Composer 2.5 исполняет) до $10 565 (GPT-5.5 везде), и на исполнителей уходило не меньше 69% токенов. Сами топологии роёв и их сбои разбирает глава 13.

OpenClaw: харнесс, который живёт в мессенджере

Раз в 30 минут OpenClaw будит своего агента без всякого сообщения от человека. Heartbeat — системная автоматизация, которая запускает обычный ход агента в главной сессии; если сказать нечего, модель отвечает NO_REPLY, и вывод глушится35. Для Anthropic через OAuth или через установленный Claude CLI интервал по умолчанию час. Пробуждения от событий ограничены: не чаще раза в 30 секунд и не больше пяти запусков за минуту.

Из чего собирается ход

В первый ход новой сессии рантайм подмешивает в системный промпт файлы из рабочей папки агента35:

ФайлНазначение
AGENTS.mdРабочие инструкции и «память»
SOUL.mdПерсона, границы, тон
IDENTITY.mdИмя агента, характер, эмодзи
USER.mdПрофиль владельца и как к нему обращаться
BOOTSTRAP.mdРазовый ритуал первого запуска, после него удаляется
MEMORY.mdКорневой файл долгой памяти, если он есть

По умолчанию на один файл отводится до 20 000 символов, на все вместе — до 60 000, у USER.md свой лимит в 4 000. MEMORY.md грузится только в главной личной сессии и не попадает в групповые чаты. Дневные журналы memory/YYYY-MM-DD.md достаются по запросу. Состояние живёт в SQLite, в ~/.openclaw/state/openclaw.sqlite, а JSONL-расшифровки остались от старых версий. Как такие файлы памяти пишутся и стареют, разбирает глава 11.

Во многих гайдах и в платных наборах конфигов heartbeat управляется файлом HEARTBEAT.md. В текущей документации сказано: «The runtime never reads HEARTBEAT.md». Команда openclaw doctor --fix переносит его содержимое в рабочую запись heartbeat-монитора в базе, а сам heartbeat теперь запускает общий планировщик автоматизаций.

Сообщения, которые приходят посреди работы, OpenClaw по умолчанию не ставит в очередь, а подмешивает в текущий прогон (steering). Проверка идёт перед запуском каждого ещё не начатого вызова инструмента, а пропущенные вызовы получают «synthetic paired results», чтобы у каждого tool_use остался свой результат и история не сломалась. Планировщик Gateway после сна запускает каждую просроченную задачу один раз, а не столько раз, сколько тиков пропущено.

Отдельная история — Pi. Долго считалось, что OpenClaw построен на ядре Pi, и в январе так и было: версия 2026.1.29-beta.1 зависела от pi-agent-core, pi-ai, pi-coding-agent и pi-tui. Начиная с 2026.5.28-beta.1 от Pi осталась одна @earendil-works/pi-tui7, а документация говорит: «OpenClaw ships one embedded agent runtime… The embedded agent runtime is OpenClaw-owned». Почему ушли от чужого ядра и переписали его или скопировали, в чейнджлоге не сказано. README по-прежнему благодарит Марио Цехнера «for pi».

Скиллы из чужих рук

Скиллы OpenClaw ищет по цепочке: skills/ в рабочей папке, .agents/skills, ~/.agents/skills, ~/.openclaw/skills, встроенные, затем папки из skills.load.extraDirs35. Ставят их из реестра ClawHub, и именно реестр стал первой большой проблемой. Аудит Snyk ToxicSkills 5 февраля 2026 года нашёл среди 3 984 скиллов из ClawHub и skills.sh 76 заведомо вредоносных, и 91% из них работали через промпт-инъекцию41. Полная статистика аудита и то, почему цифру «36%» из заголовков легко прочитать неверно, — в главе 6, там же разобран сам формат скиллов. Отдельная кампания, которую описал opensourcemalware, с 27 января по 2 февраля двумя волнами выложила 386 вредоносных скиллов (354 из них — от одного автора) под видом инструментов для криптотрейдинга с 500–700 строками правдоподобной документации; они собирали ключи бирж, связку ключей macOS, SSH-ключи и учётные данные git44.

Один клик до выполнения кода

CVE-2026-25253 описана в NVD одной фразой: «OpenClaw (aka clawdbot or Moltbot) before 2026.1.29 obtains a gatewayUrl value from a query string and automatically makes a WebSocket connection without prompting, sending a token value», CVSS 8.838. Мав Левин из depthfirst расписал, как из этого получается выполнение кода45.

Исправление добавило окно подтверждения при смене адреса Gateway. Уязвимость сидела не в песочнице и не в модели, а в управляющей плоскости: токен с правами администратора и одобрений, WebSocket-сервер без проверки Origin и настройка, которая молча принималась из адресной строки. Через два месяца пришла CVE-2026-33579: повышение привилегий через /pair approve, 9,4 по NVD и 9,9 по оценке CNA, исправлено в 2026.3.28.

Побегов из песочницы среди этих уязвимостей мало. Типичные названия: «Heartbeat context inheritance bypasses sandbox via senderIsOwner escalation» (31 марта), «Dreaming could widen restricted sender authority», «Skill tool dispatch could skip owner-only policy» (обе из сентябрьской пачки)38. Почти всё — путаница полномочий: чьим голосом пришло сообщение, от владельца или от постороннего в группе, какие права унаследовал ход, запущенный по расписанию, какой скоуп у сопряжённого устройства. README предупреждает «Treat inbound messages as untrusted input» и «Tools run on the host for the main session unless you configure sandboxing»35.

У кодового агента во входе один доверенный человек. У постоянно живущего агента — владелец, посторонние в чатах, расписание и чужие устройства, и главная работа его харнесса в том, чтобы помнить, кто из них сейчас говорит и что ему можно.

Подписка, которой нельзя пользоваться

Вторая часть истории OpenClaw — отношения с вендорами моделей. В феврале 2026 года Anthropic напомнила, что условия использования запрещают работать с подпиской через сторонние харнессы. С 4 апреля это превратилось в деньги: «Starting April 4, third-party tools will draw from extra usage instead of subscription limits». Борис Черный объяснил: «our subscriptions weren't built for the usage patterns of these third-party tools»43. 21 апреля документация OpenClaw сообщила, что снова можно пользоваться маршрутом через установленный Claude CLI, то есть вход Claude Code переиспользуется через исполняемый файл claude35. 13 мая Anthropic объявила отдельный ежемесячный кредит на Agent SDK, claude -p и сторонние инструменты, а 15 июня отложила изменение. В справке на 16 июня: «For now, nothing has changed: Claude Agent SDK, claude -p, and third-party app usage still draw from your subscription's usage limits»43. OpenCode ещё 19 февраля убрал вход через Claude Pro/Max коммитом с сообщением «anthropic legal requests»46.

За четыре месяца правила менялись четыре раза, и это отдельный риск для любого открытого харнесса поверх чужой подписки. Технически харнесс может работать с любой моделью, но условия, на которых он её получает, пишет не он.

TB 4.0 вышел в конце августа47. Из набора удалили 8 задач, по две за насыщенность, отказы моделей, публичные решения и проблемы качества или совместимости, ещё 19 починили; всем агентам дали единый таймаут в 8 часов, а версии стали семантическими. С TB 2.x цифры несравнимы, и число «за 90% на Terminal-Bench» в чужом пресс-релизе почти наверняка относится к частично насыщенному TB 2.1. Самый чистый эксперимент именно с харнессом поставила LangChain в феврале 2026 года3. Модель зафиксировали (gpt-5.2-codex), менялся только харнесс deepagents, и на Terminal-Bench 2.0 результат вырос с 52,8% до 66,5%, из тридцатки лидеров в пятёрку. Изменения были скучными. Одно middleware перехватывает попытку закончить и заставляет пройти чеклист проверки. Другое в начале работы раскладывает перед моделью текущую папку и доступные инструменты. Счётчик правок одного файла после нескольких правок подсказывает «consider reconsidering your approach». И предупреждения о том, сколько осталось времени.

Бывает, что исход решает харнесс самого бенчмарка. Transluce в феврале разбиралась, почему GPT-5.1-Codex на официальном лидерборде Terminal-Bench набрал 36,9% против 43,4% у предыдущей GPT-5-Codex49. Новая модель упиралась в таймаут в 49% прогонов против 29%. Она выбирала более длинные стратегии, а «Terminal-Bench's system prompt never mentions the time constraint». Если оставить только прогоны без таймаута, порядок меняется, и новая модель обгоняет старую примерно на 7 пунктов. Anthropic в том же месяце измерила шум инфраструктуры: та же модель в том же харнессе набирает на TB 2.0 на 6 пунктов больше, если снять ограничения ресурсов контейнера (p < 0,01), а доля инфраструктурных ошибок падает с 5,8% до 0,5%50. Проверь себя

Ты добавил в своего агента сабагента-исследователя, расход токенов вырос, а качество не изменилось. Почему так бывает и когда сабагент окупается?

Сабагент стартует с чистым окном и заново читает то, что родитель, возможно, уже знал; в замере Systima два сабагента подняли расход в 4,2 раза. Окупается он, когда прочитать нужно много, а родителю достаточно короткого итога: тогда тысячи токенов остаются в чужом окне. Если задача помещается в одно окно без мусора, дешевле обойтись без сабагента или взять форк.

По Чейзу todo-инструмент держал агента в колее. Почему Claude Code в августе 2026 года убрал его с новых моделей?

Инструмент ничего не исполнял и работал декламацией: модель пересказывала план, и он оказывался в конце контекста, в зоне свежего внимания. Новые модели держат многошаговую работу сами, а схемы инструментов и напоминания занимают контекст на каждом ходе. План переехал в режим планирования, /goal и файлы, которые проверяются снаружи.

Что случится, если посреди сессии Codex подключить ещё один MCP-сервер, и как внести изменение без потерь?

Набор инструментов стоит в самом начале запроса, поэтому префикс изменится и весь разговор под ним пойдёт мимо кеша, а Codex и так отправляет всю историю на каждом ходе. Изменения, которые можно выразить текстом, OpenAI советует дописывать новым сообщением в конец, а порядок инструментов держать стабильным.

Чем форк отличается от обычного сабагента и когда форк — плохой выбор?

Форк наследует всю историю родителя и его кеш префикса, поэтому дёшев на старте и сразу в курсе дела. Он не изолирует контекст: если смысл делегирования в том, чтобы не засорять окно, или история уже длинная и шумная, нужен обычный сабагент с чистым окном.

Классификатор auto mode не видит ни рассуждений агента, ни вывода инструментов. Зачем так сделано и чем за это платят?

Рассуждения убраны, чтобы агент не мог уговорить судью, вывод инструментов — чтобы до судьи не добралась инъекция из прочитанной страницы; вывод проверяет отдельный зонд. Цена — судья решает без части контекста, и полный конвейер пропускает 17% реальных превышений задачи. Поэтому под классификатором должна оставаться песочница.

Ты запустил /ralph-loop на 50 итераций в расчёте, что каждая начнёт с чистой головы. Что не так?

Плагин ralph-wiggum крутит цикл внутри той же сессии: Stop-хук не даёт ей закончиться и подаёт тот же промпт снова, контекст копится и сжимается компакцией. Свежее окно на каждой итерации даёт только внешний цикл в bash, который каждый раз запускает новый claude -p и хранит состояние в файлах и git.

Почему в схеме Anthropic список фич лежит в JSON, а не в Markdown, и что запрещено агенту-кодеру?

По наблюдению Anthropic, модель реже без спроса переписывает JSON, чем Markdown. Кодеру запрещено удалять и править тесты, а флаг passes он переворачивает только после проверки от начала до конца, иначе следующая сессия получит ложную картину готовности.

В CVE-2026-25253 песочницу никто не взламывал. Как тогда код выполнился на хосте?

Control UI принял адрес Gateway из параметра gatewayUrl и сам отправил туда токен владельца. Страница атакующего открыла из браузера жертвы WebSocket на localhost, потому что сервер не проверял Origin, и токеном с правами operator.admin и operator.approvals штатно выключила одобрения, перевела выполнение на хост и вызвала system.run.

Коллега предлагает перейти на харнесс X, потому что он «на 13 пунктов лучше на Terminal-Bench». Что спросить, прежде чем соглашаться?

Какая версия бенчмарка (TB 2.x и TB 4.0 несравнимы), одинаковы ли модель, effort, ресурсы контейнера и таймауты, и сколько стоит одна решённая задача. Один только effort у Claude Code с Opus 5 двигает TB 4.0 на 17 пунктов, ограничения ресурсов — на 6, а в замере aistack харнессы решали почти одинаково при двукратной разнице в цене.

После компакции Claude Code «забыл» договорённость из чата, но помнит правило из CLAUDE.md. Почему и что с этим делать?

CLAUDE.md после сжатия перечитывается с диска, а разговор превращается в сводку, которая может потерять инструкцию. Постоянные правила держи в файле, а для сводки опиши, что сохранять, в разделе с инструкциями для суммаризации или сохраняй расшифровку хуком PreCompact.

Почему уязвимости OpenClaw в основном про полномочия, а не про побег из песочницы?

У постоянно живущего агента много источников входа: владелец, посторонние в групповых чатах, расписание heartbeat и cron, сопряжённые устройства. Каждый ход надо запускать с правами того, кто его вызвал, и большинство advisories описывают случаи, когда харнесс путал, чьим голосом и с какими правами идёт ход.
