## Critical

### 1. `#fig-overhead` и три места в тексте: заявленная сумма токенов не сходится с её же слагаемыми

**Что не так.** Лид главы, первый абзац раздела `overhead` и пункт 1 чеклиста «В Claude Code сегодня
вечером» трижды называют общий расход Claude Code 2.1.207 числом **«32,8 тысячи»** (строки 22, 28,
866 `index.html`). Тут же, в этом самом абзаце, число раскладывается на слагаемые: «около 6,5 тыс.
приходится на системный промпт, около 24 тыс. на JSON-схемы... и 1,9 тыс. на системные
напоминания». 6 500 + 24 000 + 1 900 = **32 400**, а не 32 800. Разрыв — 400 токенов, и он не
объяснён (в отличие от OpenCode тремя строками ниже, где текст сам оговаривает пропущенное
слагаемое: «у OpenCode напоминания отдельно не выделены»). Диаграмма `#fig-overhead` (JSON-график
`stack`, строки 31-40) кодирует ровно эти три слагаемых и, соответственно, рендерится с итогом
**«всего 32 400 токенов»** — то есть рисунок прямо под текстом молча опровергает число из лида и из
самого этого абзаца.

**Доказательство.** Скриншот `_qa/12-deep-agents-code/fig-01-02.png`: подпись над столбиком Claude
Code — «всего 32 400 токенов» (сумма считается скриптом книги по `series` из JSON). Арифметика
6500+24000+1900=32400 проверена напрямую. Источник заметок (`research/gaps.md:458`) несёт ту же
неувязку в исходном виде: «Claude Code ~32,800 (system ~6,500 + 27 tool schemas ~24,000 + reminders
~1,900)» — заметка сама не сходится, и автор главы перенёс её как есть, не заметив.

**Как исправить.** Либо (а) сверить с первоисточником Systima, какое число верное — 32,4 или 32,8
тыс. — и привести к нему текст, лид, чеклист и `note` графика одновременно; либо (b), если 32,8 —
корректная измеренная сумма, а 6,5/24/1,9 — округления с разной точностью, явно написать это в
`note` графика (как уже сделано для OpenCode) и добавить недостающую сотню-другую токенов отдельным
сегментом, чтобы график и текст совпадали. Сейчас читатель, наложивший рисунок на текст в первом же
абзаце главы, видит два разных числа для одного и того же измерения.

## Minor

### 2. `data-title="Поток сообщений Agent SDK (из документации)"` — при вставке в отдельный файл не компилируется

Блок (Python, `index.html` строки 58-71) начинается с `async for message in query(...):` на
верхнем уровне модуля. `python3 -m py_compile` на вынесенном файле даёт
`SyntaxError: 'async for' outside async function`. Это не ошибка автора: фрагмент помечен в
заметках как VERBATIM и совпадает с `research/practice.md:67` слово в слово — так пример дан и в
самой документации Agent SDK (подразумевается, что он вставляется внутрь `async def main():` +
`asyncio.run(main())`). Автор ничего не выдумал и не обязан дописывать код за вендора. Стоит
только не считать этот блок «готовым к копипасте»: у читателя, который последует совету главы
проверять код `py_compile`, тот же результат, и небольшая оговорка («фрагмент, обёрточная
`async def main()` опущена, как в оригинале») сняла бы вопрос.

### 3. `data-title="Сохранённый workflow (из документации)"` — тот же случай для JS

Блок (`index.html` строки 305-316) заканчивается `return audits.filter(Boolean)` на верхнем уровне
файла; `node --check` на вынесенном файле — `SyntaxError: Illegal return statement`, потому что
top-level `return` вне функции недопустим в обычном JS-модуле. Проверено по `research/practice.md`
(строки 122-134) — тоже VERBATIM, слово в слово, значит и здесь фрагмент подразумевает, что рантайм
Claude Code исполняет тело сохранённого workflow-скрипта как тело функции (сам скрипт это нигде не
оборачивает). Не ошибка автора главы, тот же комментарий про отсутствие оговорки, что и в находке 2.
