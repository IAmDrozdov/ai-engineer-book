# Глава 05. MCP — план

Состояние на 30 сентября 2026. Текущая ревизия 2026-07-28 (stateless), черновик следующей пуст.
Главная линия: протокол пережил переписывание, и половина материалов в сети описывает первую эпоху.
Читатель должен уметь отличить эпохи на проводе, собрать сервер, увидеть цену и дыры.

Лид: сервер на `mcp` 2.2.0 отвечает на `initialize` заголовком `mcp-session-id` и SSE, а на запрос
ревизии 2026-07-28 — голым JSON без сессии. Две эпохи на одном эндпоинте (прогон демо-сервера).

## Разделы

1. `wire` «Что уходит серверу». Начало: `.mcp.json` из репозитория и POST, который Claude Code отправит
   по нему (нормативный пример с `Mcp-Method`). Главное: хост/клиент/сервер, клиент на сервер, сервер
   не видит разговор; два слоя; три вида сообщений JSON-RPC; N×M одним абзацем с цитатой 2024 года.
2. `stateless` «Рукопожатие, которого больше нет». Начало: цитата mcp-use про липкие сессии и
   rolling deploy. Главное: legacy-жизненный цикл (initialize, Mcp-Session-Id, 404 → заново);
   modern: `_meta` в каждом запросе, `server/discover`, -32022, зеркальные заголовки и -32020,
   `ttlMs`/`cacheScope`, состояние через хендлы; реальный обмен с демо-сервером; определение эпохи.
3. `transports` «stdio, Streamable HTTP и то, что осталось от SSE». Начало: правило «в stdout только
   MCP» и print() в прогоне. Главное: кадрирование stdio; HTTP modern (POST, GET → 405, без
   возобновления), `subscriptions/listen`; HTTP+SSE можно удалять; Origin/127.0.0.1; ws у Claude Code
   не из спецификации; выбор транспорта.
4. `primitives` «Шесть примитивов, из которых работают четыре». Начало: Уиллисон «Tools 95%+».
   Главное: tools/list и результат (content + structuredContent, isError против JSON-RPC-ошибки),
   аннотации — подсказки с опасными значениями по умолчанию; ресурсы, промпты; клиентские примитивы
   и их депрекация с миграцией.
5. `mrtr` «Сервер спрашивает, не отправляя запросов». Начало: текст ошибки FastMCP 4
   `ToolError: elicitation via server-initiated requests is unavailable…`. Главное: MRTR, новый id,
   `requestState` как вход атакующего (AEAD), form/URL, пример FastMCP 4; Tasks как расширение.
6. `revisions` «Пять ревизий: что добавляли и что забирали». Начало: batching добавили 26 марта 2025
   и убрали 18 июня 2025. Главное: хронология, таблица «добавили → судьба», политика жизненного
   цикла SEP-2596, часы депрекаций; ядро против расширений (Apps → гл. 9, Skills → гл. 6).
7. `governance` «Кто решает и где искать серверы». Начало: 37 730 серверов в официальном реестре
   против «10 000+» в декабре 2025. Главное: AAIF, мейнтейнеры и SEP, уровни SDK, реестр как
   метаданные (preview, v0.1), дорожная карта 22 августа.
8. `auth` «Авторизация: от 401 до токена для одного сервера». Начало: ответ 401 с
   `WWW-Authenticate`. Главное: PRM → AS → регистрация (pre-reg, CIMD, DCR) → PKCE + `resource` →
   `iss` → токен; почему DCR ушёл (четыре проблемы Карлтона); stdio берёт секреты из env;
   Enterprise-Managed Authorization (ID-JAG) на проводе. Реализация — гл. 15.
9. `python` «Сервер на Python за вечер». Начало: `pip install mcp` теперь ставит 2.x и ломает
   импорт `mcp.server.fastmcp`. Главное: демо-сервер (запущен), подключение к Claude Code,
   Inspector (эпоха по умолчанию legacy, CLI в CI, секреты открытым текстом), FastMCP 4 против SDK,
   загрузки пакетов.
10. `clients` «Четыре хоста — четыре разных MCP». Начало: Claude Code по умолчанию не предлагает
    stdio-серверам новую ревизию. Главное: Claude Code, Cursor, VS Code, ChatGPT/Codex, MCP-клиент
    внутри Messages API; таблица.
11. `context` «Сколько стоят описания инструментов». Начало: пять серверов Anthropic — 55 тыс.
    токенов до первого вопроса. Главное: цифры токенов, падение точности (оценка вендора, RAG-MCP,
    Copilot, MCPMark), tool search, прогрессивное обнаружение, code execution; поле: «жалоб на bloat
    нет уже квартал». Состав окна — гл. 2, дизайн тулов — гл. 3.
12. `security` «Слабые места протокола». Начало: отравленный `add` Invariant Labs. Главное:
    poisoning, shadowing, rug pull (Deadbugz), аннотации; confused deputy, token passthrough, SSRF,
    state handles (Terraform), локальный сервер (mcp-remote), песочница code mode (Check Point),
    скан Canopii; защиты нет на уровне протокола. Подробно — гл. 16.
13. `debate` «MCP или CLI со скиллами». Начало: HN «MCP was always a bad idea?» 20 сентября и ответ
    Уиллисона. Главное: Ронахер, Цехнер (цифры и его же совет), тред Manufact, разворот Earendil;
    вердикт с условиями.

## Рисунки (16)

1. fig-architecture — mermaid flowchart: хост, модель, клиенты, stdio- и HTTP-серверы, подписи.

3. fig-modern-routing — flowchart: шлюз читает `Mcp-Method`/`Mcp-Name`, любые реплики, ветка 400.

5. fig-primitives — HTML versus: кто управляет инструментами, ресурсами, промптами.
6. fig-mrtr — sequence: `input_required`, пользователь, повтор на другую реплику с `requestState`.
7. fig-tasks — stateDiagram: жизненный цикл задачи в расширении Tasks.
8. fig-deprecations — рукописный SVG: часы депрекаций HTTP+SSE, Roots/Sampling/Logging, DCR.
9. fig-registry-packages — hbar: типы пакетов в реестре (обход API 30.09.2026).
10. fig-oauth — sequence: 401 → PRM → AS → CIMD → PKCE+resource → code+iss → токен.
11. fig-sdk-downloads — hbar: загрузки mcp, fastmcp, @mcp/sdk, @mcp/server за 30 дней.
12. fig-tool-tokens — hbar: токены на описания по серверам (Anthropic, ноябрь 2025).
13. fig-selection — сгруппированный hbar: точность выбора без отбора и с отбором (три исследования).
14. fig-code-mode — flowchart: модель пишет код, песочница зовёт серверы, в контекст идёт вывод.
15. fig-poisoning — HTML versus: что видит пользователь и что читает модель.
16. fig-rugpull — stateDiagram: Deadbugz, подмена `tools/list` после третьего вызова.

## Самопроверка плана
- Анкета «что → зачем → как → плюсы/минусы» не повторяется: разделы открываются сбоем (2, 3, 5),
  проверкой расхожего утверждения (4, 6), числом (7, 11), сообщением на проводе (1, 8), спором (13).
- Первые фразы разделов не складываются в конспект: «цитата про rolling deploy», «print() в stdout»,
  «batching прожил 84 дня» — без контекста непонятны.
- Провал виден в середине главы: сессии (2), stdout (3), ошибка FastMCP (5), депрекации (6),
  Inspector по умолчанию на legacy (9), CVE и Deadbugz (12).
- Где риск провала: раздел 7 (управление) может стать справкой — держать коротким, открыть числом.
