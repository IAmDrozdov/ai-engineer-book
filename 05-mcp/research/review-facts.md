# Рецензия главы 05 «MCP: Model Context Protocol» — фактчек

Рецензент читал файл главы (`05-mcp/index.html`, 1071 строка), все четыре файла заметок
(`research/gaps.md`, `spec.md`, `practice.md`, `field.md`) и `_meta/AUTHORING.md`, затем сверил
глава-по-главе все проверяемые утверждения (версии/даты, поля и формы сообщений, числа и замеры,
цитаты, утверждения «сейчас X») с заметками, и отдельно проверил ~20 самых нагруженных пунктов по
живым первоисточникам (сегодняшняя дата в системе — 30 сентября 2026 года, поэтому спецификация
ревизии `2026-07-28` и упомянутые в главе блоги/посты оказались реальными живыми страницами, а не
вымыслом — WebFetch подтвердил это).

**Итог проверки живых источников: подавляющее большинство численных данных, цитат и цитируемых
фрагментов спецификации в главе оказались дословно точны** (RAG-MCP 13.62%/43.13%, Copilot
40→13/+2-5пп/-400мс/94.5%-69.0%, Cloudflare 2500+/1.17М/1000, обе цитаты Уиллисона (HN 49779718 и
49791197), цитата и цифры Ронахера, цитаты и цифры Цехнера, MCPMark 52.56%/33.86%/16.2/17.4, обе
CVE (49596 → 9.4, 6514 → 9.6), текст changelog ревизии 2026-07-28 включая диапазон кодов ошибок
-32020…-32099, цитаты Earendil, реестр SDK-тиров, версии FastMCP 4 и её пороги зависимостей).

## Находки (по убыванию важности)

### 1. [CRITICAL] Выдуманный Python API в примере кода сервера

**Цитата из главы** (раздел «Что сервер говорит о себе»):
> «Python SDK 2.2.0 по умолчанию ставит ноль и private, то есть «не кешируй». Если список тулов у
> тебя меняется раз в релиз, поставь час...»
```python
from mcp.server import CacheHint, MCPServer

mcp = MCPServer(
    "shop",
    cache_hints={"tools/list": CacheHint(ttl_ms=3_600_000, scope="public")},
)
```

**В чём ошибка.** Класса `CacheHint` и параметра `cache_hints` не существует ни в одном источнике,
который удалось найти. Официальный README `modelcontextprotocol/python-sdk` (ветка `main`,
30.09.2026) показывает единственный способ объявить тул — `from mcp.server import MCPServer` без
какого-либо упоминания `CacheHint` или `cache_hints`; ни в одном из четырёх файлов заметок
(`gaps.md`, `spec.md`, `practice.md`, `field.md`) это API тоже не встречается, хотя все три
подробно описывают сам протокольный механизм `ttlMs`/`cacheScope` (`CacheableResult`). Ни утверждение
про default `ttlMs=0`/`private`, ни сам код кода не сопровождены ссылкой на источник — по правилам
`AUTHORING.md` («каждое нетривиальное утверждение... должно быть в заметках», «код, который ты не
запускал, помечай так же [как набросок]») это требовало либо проверки, либо пометки
«Набросок: …» / «не запускался». Читатель, скопировавший этот код, получит `ImportError`.

**Как правильно.** Либо найти и процитировать настоящий способ задать `ttlMs`/`cacheScope` для
`tools/list` в `mcp` 2.2.0 (если он вообще предусмотрен в публичном API, а не только на уровне
проводного протокола), либо явно пометить пример как «Набросок» и снять категоричное утверждение о
поведении по умолчанию.

**Доказательство.** https://raw.githubusercontent.com/modelcontextprotocol/python-sdk/main/README.md
(получено 30.09.2026: класс `MCPServer` подтверждён, `CacheHint`/`cache_hints` — нет).

### 2. [MAJOR] Составной пример MRTR выдан за «пример из спецификации»

**Цитата из главы** (раздел «Сервер спрашивает, не отправляя запросов», вкладки «Ответ:
input_required» / «Повтор: inputResponses»): пример с `github_login`, тулом `get_weather` и
`requestState: "eyJsb2NhdGlvbiI6Ik5ldyBZb3JrIn0..."`, который автор затем сам декодирует как
`{"location":"New York"}`, чтобы показать, что состояние лежит открытым текстом.

**В чём ошибка.** Живая страница спецификации `basic/patterns/mrtr` (получена 30.09.2026)
действительно содержит пример с ключом `github_login` и `elicitation/create`, но в её версии
`requestState` — это `"AEAD-protected blob"`, а не base64 от читаемого JSON. Комбинации
`github_login` + инструмент `get_weather`/«New York» ни на странице `mrtr`, ни на странице
`docs/2026-07-28/learn/client-concepts` (где приведён единственный настоящий пример elicitation —
про бронирование в Барселоне) не существует. То есть глава сплавила настоящий фрагмент
(`github_login`) с инструментом `get_weather` из другого раздела спецификации и с придуманным
значением `requestState`, подписав это как «из спецификации» — и абзац после примера ссылается на
src-20 (страница `mrtr`), которая на самом деле именно этот пример не подтверждает.

**Как правильно.** Либо пометить блок как «Набросок: …», раз он составлен автором для
иллюстрации, либо использовать настоящий пример FastMCP (который в самой главе чуть ниже
приведён отдельно и действительно кладёт `request_state=f"dest={destination}"` открытым текстом —
там иллюстрация уже есть и без выдумки).

**Доказательство.**
https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/mrtr и
https://modelcontextprotocol.io/docs/2026-07-28/learn/client-concepts (обе получены 30.09.2026).

### 3. [MAJOR] Пример хендла `create_basket`/`add_item` не находится в источниках

**Цитата из главы** (раздел «Где теперь живёт состояние»): блок кода с подписью «Хендл вместо
сессии (пример из спецификации)», где `create_basket` возвращает `basket_id`, а `add_item`
принимает его аргументом.

**В чём ошибка.** Этого примера нет ни в одном из файлов заметок (`gaps.md`/`spec.md`/`practice.md`/
`field.md` описывают механизм «явных серверных хендлов» словами, без такого кода), и его не удалось
найти на живых страницах спецификации, которые получилось проверить (`basic/versioning`,
`basic/patterns/mrtr`, `basic/transports/stdio`, `docs/.../client-concepts`; отдельная страница про
хендлы/состояние по прямому URL не нашлась). Возможно, такой пример существует на неопознанной
странице спецификации, но подтвердить это не удалось.

**Как правильно.** Указать точный URL страницы, откуда взят пример, либо переименовать подпись в
«Набросок».

**Доказательство отсутствия.** Полнотекстовый просмотр `gaps.md`, `spec.md`, `practice.md`,
`field.md`; проверка `basic/versioning`, `basic/patterns/mrtr`, `basic/transports/stdio`,
`docs/2026-07-28/learn/client-concepts` (получены 30.09.2026) — примера нет ни в одной из них.

### 4. [MINOR] Неточная «дословная» цитата из блога Manufact

**Цитата из главы:** «The session tied a client to one replica. That led to sticky routing, shared
session storage, and gateways that had to understand more of the protocol than an HTTP gateway
should need to know».

**В чём ошибка.** Живой текст поста (https://manufact.com/blog/mcp-use-v2, получено 30.09.2026):
«Behind a load balancer, the session tied a client to one replica» и отдельно «…required sticky
routing, shared session storage, and gateways that had to understand more of the protocol than an
HTTP gateway should need to know». Глава выбросила «Behind a load balancer,» и заменила «required»
на «That led to», склеив два предложения в одно и подав их как один непрерывный дословный блок —
хотя AUTHORING.md требует цитаты приводить как есть. Вторая цитата в том же абзаце («A rolling
deployment could also kill…») дословна и верна.

**Как правильно.** Либо честно обозначить купюру многоточием и раздельные фразы кавычками, либо
дать точную цитату целиком.

**Доказательство.** https://manufact.com/blog/mcp-use-v2 (получено 30.09.2026).

### 5. [MINOR] Ссылка не подтверждает термин «платиновые участники»

**Цитата из главы:** «...фонду под Linux Foundation, который Anthropic основала вместе с Block и
OpenAI; платиновые участники — AWS, Anthropic, Block, Bloomberg, Cloudflare, Google, Microsoft и
OpenAI» — со ссылкой на src-28 (пост Anthropic от 9 декабря 2025 года).

**В чём проблема.** Живой текст именно этого поста Anthropic (получен 30.09.2026) описывает
перечисленные компании как «co-founded by Anthropic, Block and OpenAI, with support from Google,

Foundation/AAIF, а не из этого поста Anthropic. Ссылка src-28 не покрывает конкретно это слово.

**Как правильно.** Либо добавить вторую ссылку на пресс-релиз Linux Foundation рядом с этим
предложением, либо не привязывать термин «платиновые» к посту Anthropic.

**Доказательство.**
https://www.anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation

### 6. [MINOR] Непроверяемая цитата об отказе stdio-сервера

**Цитата из главы:** «...сервер на mcp 2.2.0, которому первым пришёл запрос новой эпохи, на
последующий initialize ответил отказом «connection is serving the 2026-07-28 protocol; the
initialize handshake is not accepted»».

**В чём проблема.** Живая страница `basic/transports/stdio` (получена 30.09.2026) подробно
описывает правила обратной совместимости для stdio, но не содержит такой точной строки ошибки, и
ни один файл заметок её не упоминает. Формулировка нигде не сопровождена ссылкой — либо это
собственное наблюдение автора при тестировании демо-сервера (тогда стоит сказать это явно, как
сделано в других местах главы с пометкой «запускался»/«не запускался»), либо она придумана.

**Как правильно.** Если сообщение действительно было получено при запуске демо-сервера — сказать
это прямо («при тестировании сервер ответил...»); если нет — убрать точную цитату или заменить
общим описанием поведения.

**Доказательство отсутствия.**
https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio (получено
30.09.2026) — раздел Backward Compatibility не содержит такой строки.
