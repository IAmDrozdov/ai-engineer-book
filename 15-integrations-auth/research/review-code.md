## Major

### 1. `validate_token_resource` в наброске `server.py` не существует в той версии SDK, на которую ссылается глава

**Где.** Раздел `#mcp-oauth`, блок кода `data-title="Набросок: server.py на основе примера MCP
Python SDK"` (строка 318 и далее), строка 350:

```python
mcp = MCPServer(
    "Notes",
    token_verifier=JwtVerifier(),
    auth=AuthSettings(
        issuer_url=AnyHttpUrl(ISSUER),
        resource_server_url=AnyHttpUrl(RESOURCE),
        required_scopes=["notes:read"],
        validate_token_resource=True,   # <-- этого поля нет в v2.0.0
    ),
)
```

Текст главы привязывает пример именно к этой версии: «В Python SDK v2 (с 28 июля 2026 года
`FastMCP` называется `MCPServer`) ресурсный сервер собирается из проверки токена и настроек...»,
источник 7 — `python-sdk/releases/tag/v2.0.0`.

**Доказательство.** Я скачал `src/mcp/server/auth/settings.py` из репозитория
`modelcontextprotocol/python-sdk` на двух ревизиях:

- тег `v2.0.0` (28 июля 2026, версия, на которую ссылается глава): класс `AuthSettings` содержит
  поля `issuer_url`, `service_documentation_url`, `client_registration_options`,
  `revocation_options`, `required_scopes`, `identity_assertion_enabled`, `resource_server_url` —
  поля `validate_token_resource` там **нет**.
- ветка `main` (текущая, соответствует v2.2.0 от 7 сентября 2026 — эту версию как актуальную
  называет и `research/gaps.md` [G19]): там `validate_token_resource: bool | None = Field(default=None, ...)`
  появляется, с комментарием, что оно «will default to `True` in 3.0» при заданном
  `resource_server_url`.

Импорты и остальные имена в этом же блоке (`MCPServer`, `TokenVerifier` как `Protocol` с
`async def verify_token(self, token: str) -> AccessToken | None`, поля `AccessToken(token, client_id,
scopes, expires_at, resource, subject, claims)`, `get_access_token()` из
`mcp.server.auth.middleware.auth_context`) я сверил с тем же тегом `v2.0.0` — они совпадают
дословно, проблема ровно в одном параметре.

**Почему это важно.** У pydantic-моделей по умолчанию лишние поля либо тихо игнорируются, либо (при
`extra="forbid"`) роняют валидацию — в обоих случаях читатель, который поставит именно `mcp==2.0.0`
(версию, названную в тексте и в источнике 7) и скопирует пример, либо получит ошибку на
неизвестный аргумент, либо получит код, который выглядит так, будто добавляет проверку `resource`,
а на самом деле ничего не проверяет. Сама защита от приёма чужого токена в этом примере на самом
деле обеспечивается строкой `audience=RESOURCE` внутри `JwtVerifier.verify_token` (это и говорит
следующий абзац: «Главная строка тут `audience=RESOURCE`») — она работает независимо от версии SDK,
так что реальная угроза не в дыре в безопасности, а в том, что набросок не собирается/не делает то,
что обещает, против заявленной версии.

**Как исправить.** Либо поменять источник 7 и текст на v2.2.0 (7 сентября 2026) и явно написать,
что `validate_token_resource` нужен `mcp>=2.2`, либо убрать эту строку из наброска и оставить
защиту только на `audience=RESOURCE` в `verify_token`, раз она и названа главной.

**Важность:** major, не critical — блок помечен как «Набросок» (не запускался), и настоящая защита
от чужого токена в примере не зависит от сломанной строки.

## Minor

### 2. Блок «ID-JAG: заголовок и claims» размечен как JSON, но не разбирается как JSON

**Где.** Раздел `#enterprise`, вкладка «ID-JAG» внутри `<div class="tabs">` (строка 483–500),
`data-lang="json"`:

```
{
  "typ": "oauth-id-jag+jwt"
}
.
{
  "jti": "9e43f81b64a33f20116179",
  ...
}
```

**Доказательство.** Ровно этот текст, сохранённый в файл и прогнанный через
`python3 -c "import json; json.load(open(f))"`, падает с `json.decoder.JSONDecodeError: Extra data:
line 4 column 1` — точка-разделитель после первого объекта делает блок не одним JSON-документом, а
двумя, склеенными как JWT `header.payload`. Все остальные 11 JSON-блоков главы (включая JSON внутри
`fig-probe`) я так же прогнал через `json.loads` — они разбираются без ошибок, проблема только в
этом одном. Проверил также, что это не сложившийся приём в книге: `grep -rn '^\.$' */index.html` по
всем 17 главам находит такую строку только здесь.

**Как исправить.** Это иллюстрация формата JWT (header.payload), а не JSON-документ, так что
честнее: либо разбить на две вкладки, как уже сделано для «Запрос/Ответ» в этом же разделе
(«Заголовок» и «Полезная нагрузка» отдельными блоками `data-lang="json"`), либо сменить разметку
всего блока на `data-lang="text"`, раз он не парсится как json.

**Важность:** minor — содержимое фактически верно (это реальный формат JWT из EMA/ID-JAG-спеки, я
сверил его с `research/gaps.md` [G4], где тот же пример приведён как VERBATIM), путаницы у читателя
не будет, но формально блок нарушает правило «JSON должен разбираться» из инструкции автора.

## Что проверено и в порядке

**Код.** Все 4 блока Python (обмен токена по RFC 8693 на httpx, набросок `server.py`, активность
Temporal с ключом идемпотентности, client credentials без секрета с JWT от платформы) компилируются
`python3 -m py_compile` без ошибок; все помечены «Набросок» там, где не запускались, как требует
инструкция. Остальные 11 JSON-блоков разбираются `json.loads` без ошибок: токен Auth0 после
OBO-обмена, запрос/ответ token-exchange из RFC 8693, PRM и метаданные AS Linear, `.mcp.json`,
документ CIMD, ответ ID-JAG, элемент `mcp_servers` для Claude API, набросок записи аудита,
`InputRequiredResult`, данные графика `fig-probe`.

**Сверка с документацией/спекой.** Выборочно (не сплошняком — глава большая) проверены дословные
цитаты и цифры, которых нет в заметках, против живых источников: PRM и метаданные AS `mcp.linear.app`
и scopes `mcp.sentry.dev` (`org:read, project:write, team:write, event:write, alerts:write`) —
сняты живым `curl` 30 сентября 2026, совпадают байт в байт с примерами в главе; все девять версий
Claude Code (2.1.229, 231, 243, 248, 265, 271, 274, 281, 284) и их OAuth/MCP-исправления — сверены с
`CHANGELOG.md` Anthropic, совпадают дословно; цитата «MCP authorization today is built around a
person approving access in a browser» — сверена с блогом дорожной карты MCP напрямую (в локальных
заметках дословно не зафиксирована, но подтверждена первоисточником). Все примеры, помеченные в
заметках как VERBATIM (CIMD-документ, токен Auth0 с `act`, конфиг Kong `ai-mcp-oauth2`, конфиг
agentgateway `backendAuth`, инструмент MCP Toolbox с `authServices`, пример AuthZEN,
`InputRequiredResult`, пример CIBA, пример Entra OBO с `AADSTS82014`/`AADSTS50013`), совпадают с
главой дословно.

**Рисунки.** `node tools/qa.mjs 15-integrations-auth --shots` — `ISSUES none`, все 16 рисунков
(12 mermaid, 3 HTML-схемы, 1 график) построились. Каждый скриншот
(`_qa/15-integrations-auth-code/*.png`) просмотрен: подписи не слипаются, схемы не сжаты, текст не
вылезает за рамки. По смыслу — участники, порядок сообщений и направления стрелок сверены с текстом
