## Critical

### 1. Подсветка строк (`data-hl`) стирает текст в примерах на Python и TypeScript

**Место:** минимум четыре блока кода — id="catalog" (`validate_a2ui.py`, index.html:187,
`data-hl="4,10"`; сниппет CVE `@a2ui/web_core`, index.html:250, `data-hl="3"`), id="mcp-apps"
(пример `sendRequest`, index.html:535, `data-hl="4,6,20"`), id="fastmcp" (`server.py`, index.html:587,
`data-hl="11,21-35"`), id="frontend" (`useFrontendTool`, index.html:790, `data-hl="6-10"`).

**Проблема.** На выделенных (`data-hl`) строках этих блоков пропадает почти весь код, кроме
строковых литералов и части ключевых слов. Проверено скриншотами (`node tools/qa.mjs --shots`,
плюс отдельные полноразмерные скриншоты секций 3, 5, 6, 8 без обрезки по высоте):

- `validate_a2ui.py`, строка 4 (`catalog = A2uiCatalog.from_config(BasicCatalog.get_config("0.9.1"), version="0.9.1")`) рендерится как `"0.9.1"        "0.9.1"` — всё, кроме двух строк в кавычках, исчезло.
- Та же строка 10 (`for err in catalog.validate_components(msg):`) рендерится как `for   in` — пропали `err` и `catalog.validate_components(msg):`.
- Сниппет CVE, строка 3 (`window.open(args.url, '_blank');`) — та самая строка, ради которой существует весь разбор CVE-2026-10032 — рендерится как `window open      url  '_blank'`: пропали точки, скобки, запятая, `args`, точка с запятой.
- Пример `sendRequest`, строка 4 (`window.parent.postMessage({ jsonrpc: "2.0", id, method, params }, '*');`) рендерится как `window parent postMessage    jsonrpc  "2.0"                              '*'`; строка 6 (`window.addEventListener('message', function listener(event) {`) — как `window addEventListener  'message'   function listener event`. Это ровно тот пример, под которым стоит `note warn` с текстом «в этом примере три ошибки» — то есть автор сам просит читателя всмотреться именно в эти строки.
- `server.py`, диапазон 21–35 (тело `team_directory`) — из `for office, count in Counter(m["office"] for m in members).items()` остаётся `for   in "office" for   in`; из `with Column(gap=4, css_class="p-6"):` остаётся `with   4   "p-6"`; аналогично для `Grid`, `PieChart`, `DataTable`, `DataTableColumn` — везде выживают только строки и числа.
- `useFrontendTool`, диапазон 6–10 (тело `render`) — то же самое: из `if (status === "inProgress" || status === "executing") return …` видно только `if   "inProgress"   "executing" return …`.

Не задета JSON-подсветка (там hljs оборачивает практически все токены в `<span>`, включая ключи и
значения) — поэтому в остальных ~18 блоках кода в главе (JSON, часть TypeScript без плотных
хайлайтов) текст цел, и первая проверка на глаз (скриншоты фигур/секций в пределах 3000 px)
ничего подозрительного не показывает.

**Причина (проверено по исходникам `assets/book.css` и `assets/book.js`).** Оверлей подсветки
строки — `<span class="hl-line">`, вставляется как **дочерний узел `<code>`**
(`assets/book.js:182`, `code.prepend(...)`) и стоит `position:absolute; z-index:0`
(`assets/book.css:277`). Соседнее правило `assets/book.css:278`
(`.code pre code > * { position: relative; z-index: 1; }`) поднимает над этим оверлеем только
*элементы* — прямых детей `<code>`. highlight.js оборачивает в `<span class="hljs-…">` далеко не
каждый символ: обычные идентификаторы, точки, скобки, запятые, точки с запятой остаются простым
текстовым узлом прямо внутри `<code>`. Такой текстовый узел не подходит под селектор `> *`, остаётся
без `position`, и по правилам CSS-порядка отрисовки красится *под* позиционированным
`z-index:0`-оверлеем — то есть закрашивается им. Токены, которые hljs всё-таки оборачивает
(`hljs-string`, отчасти `hljs-keyword`/`hljs-built_in`), получают `position:relative; z-index:1` и
остаются видимыми — отсюда ровно та картина, которая видна на скриншотах: «обломки» строк и
ключевых слов на месте, вся «сантехника» (идентификаторы, пунктуация) стёрта. Это системная вещь
в `assets/book.css`/`assets/book.js`, а не опечатка в этой главе, и почти наверняка задевает
`data-hl` на не-JSON коде в любой другой главе книги — но здесь это ломает ровно те строки, вокруг
которых построен методический смысл раздела (сама уязвимая строка CVE, строка с ошибкой каталога).

**Что с этим сделать.** Чинить нужно в `assets/book.css`/`assets/book.js`, не в тексте главы:
либо переместить вставку `.hl-line` за пределы `<code>` (сделать её сиблингом на уровне `<pre>` с
абсолютным позиционированием по `top`, чтобы `.code pre code > *` не пришлось отыгрывать), либо
дать самому оверлею отрицательный `z-index` в контексте, который уже выше текста, либо явно
проставлять `position:relative` всем текстовым узлам через обёртку. До фикса — не ставить `data-hl`
на строки Python/TypeScript, где выделяется больше, чем голая строка или одно ключевое слово, либо
после любой правки открывать скриншот именно этой строки (штатная проверка `qa.mjs --sections`
проходит мимо: `ISSUES none`, и часть задетых блоков лежит ниже среза в 3000 px).
