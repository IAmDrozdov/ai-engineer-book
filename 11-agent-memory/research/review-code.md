## MINOR

### 1. JSON-блок «Одна фича из списка» помечен `data-lang="json"`, но не парсится как JSON

- **Блок**: `<script type="text/plain" class="code" data-lang="json" data-title="Одна фича из списка (из поста Anthropic)" data-hl="5">`, строки 342–349 `index.html`.
- **Что не так**: содержимое —
  ```json
  {
      "category": "functional",
      "description": "New chat button creates a fresh conversation",
      "steps": [...],
      "passes": false
  }
  ```
  `"steps": [...]` — не валидный JSON (многоточие внутри массива не JSON-значение).
  `python3 -c "import json; json.load(open('j7.json'))"` даёт `json.decoder.JSONDecodeError:
  Expecting value: line 4 column 15`. По инструкции автора JSON с сокращениями/комментариями
  положено помечать `data-lang="jsonc"`; здесь стоит `"json"`, то есть блок обещает быть строгим
  JSON и не является им.
- **Доказательство**: `python3 -m json.tool` на скопированном тексте блока падает с
  `JSONDecodeError` (проверено в `/private/tmp/.../scratchpad/code_check/j7.json`).
- **Контекст, снимающий часть вины**: `research/practice.md:125-132` подтверждает, что это
  VERBATIM-цитата из реального поста Anthropic («Формат feature-файла (VERBATIM JSON)» с тем же
  `"steps": [...]`), то есть многоточие — часть иллюстрации в первоисточнике, а не выдумка автора
  главы. Это не фактическая ошибка и не вводит читателя в заблуждение по существу.
- **Как исправить**: сменить `data-lang="json"` на `data-lang="jsonc"` (раз это не строгий JSON),
  либо заменить `[...]` на реальный или явно фиктивный массив шагов (`["...шаги..."]` строкой,
  или `[]`), либо перевести блок в `data-lang="text"` как иллюстрацию формата. Любой из трёх
  вариантов убирает несоответствие между заявленным языком и содержимым.
