### 1. Таблица «Сколько тулов — слишком много»: строка AlphaSignal приписывает замеру методологию, которой нет в источнике

**Что не так.** В разделе `cost`, подраздел «Сколько тулов — слишком много», в таблице у строки «AlphaSignal, июль 2026» колонка «Условия» гласит: «данные одной компании: по 200 реальных ходов на каждое число тулов, наблюдение, а не эксперимент». Число «200 реальных ходов на каждое число тулов» не встречается ни в `gaps.md`, ни в `practice.md`, ни в `field.md`, ни в `spec.md` — нигде в исследовательских заметках. Единственное описание методологии этого замера, которое есть в заметках: `gaps.md:463` — «(practitioner, 15 production servers)». Это другое число и другая единица измерения (15 продакшен-серверов, а не 200 ходов на каждое число тулов). Похоже, что конкретную цифру «200» придумали при написании таблицы — возможно, спутав с методологией IBM-исследования в соседней строке той же таблицы («BFCL subset, 200 cases», `gaps.md:461`), где 200 — число тестовых случаев совсем другого замера.

### 2. Набросок strict-схемы для Responses API теряет `enum`, хотя абзацем выше глава учит обратному

**Что не так.** В разделе `parameters`, подраздел «Strict: что гарантирует схема и чего не гарантирует», вкладка «OpenAI» (`data-title="Набросок: тот же тул для Responses API"`) задаёт параметр `unit` как `{"type": ["string", "null"], "description": "celsius or fahrenheit, null for the local default"}` — без `enum`. Двумя абзацами выше та же глава учит ровно обратному на примере `toggle_light`: «Один параметр-перечисление `state: "on" | "off"`» исключает некорректный вызов — то есть учит заменять свободный текст перечислением. Пример-набросок сам нарушает этот принцип: `unit` — строка без ограничения на допустимые значения, poka-yoke пропадает. Настоящий пример strict-схемы в документации OpenAI для nullable-поля сохраняет `enum` вместе с `"type": ["string", "null"]` (это же делает пример в главе 1 этой книги, по независимой проверке из `review-completeness.md`, находка №8).

**Доказательство.**
- Чтение чанка: `index.html`, блок `data-title="Набросок: тот же тул для Responses API"` в разделе `parameters`.
- Свой же принцип чуть выше, раздел `parameters`: «Один параметр-перечисление `state: "on" | "off"` такой вызов исключает».
- `research/review-completeness.md:118` (независимая проверка, находка №8): «OpenAI в своём примере strict-схемы с null-типом enum сохраняет: developers.openai.com/…, строки 1078–1082, `"type": ["string", "null"], "enum": ["celsius", "fahrenheit"]`. Глава 1 этой книги тоже его сохраняет.» — то есть и первоисточник, и параллельный пример в этой же книге держат `enum` рядом с nullable-типом; только этот набросок в главе 3 его теряет.
- Блок явно маркирован как «Набросок» (черновой пример, не VERBATIM), так что дело не в точности цитаты, а в том, что сам набросок автора противоречит совету на той же странице.

**Как исправить.** Вернуть `enum`: `"unit": {"type": ["string", "null"], "enum": ["celsius", "fahrenheit"], "description": "…"}`.

### 3. VERBATIM-пример тула `bash` (SWE-bench) не парсится как JSON, хотя блок помечен `data-lang="json"`

**Что не так.** В разделе `descriptions`, блок `data-title="Тул bash агента для SWE-bench, январь 2025"` помечен `data-lang="json"`, но не проходит `json.loads`: `description` содержит и литеральные `\n`, и настоящие переводы строки внутри одного строкового значения JSON — это невалидный JSON-синтаксис (control character в строке). Причина — не ошибка автора главы: это дословная копия форматирования из самого поста Anthropic (подтверждено `research/gaps.md:108-128`, помечено там же как VERBATIM). То есть источник сам показывает JSON именно в таком, синтаксически невалидном виде. Раз блок не в `jsonc` (для которого по заданию проверка не требуется), а в `json`, читатель, скопировавший блок и попытавшийся его распарсить, получит `json.decoder.JSONDecodeError`.

**Доказательство.**
- `python3 -m py_compile` неприменим; `json.loads()` на блоке 13 (`block_13.json`, извлечён из `index.html`): `json.decoder.JSONDecodeError: Invalid control character at: line 4 column 50 (char 71)`.
- `research/gaps.md:108-128` — тот же текст один в один, отмечен как VERBATIM-копия из блога Anthropic (январь 2025, SWE-bench).

**Как исправить.** Ничего менять по существу не нужно — это подлинная цитата, а глава уже отдельно поясняет под примером, что это исторический документ. Если хочется, чтобы блок был runnable-JSON, можно поменять `data-lang` на `text` (как сделано для соседнего примера `str_replace_editor` в тех же заметках) или добавить перенос строк как `\n` без реальных line breaks — но тогда это перестанет быть дословной цитатой оригинального поста. Не критично, оставляю как замечание, а не как ошибку.

### 4. Пример скрипта для PTC использует `await` вне `async def` — не компилируется как самостоятельный Python-файл

**Что не так.** Блок `data-title="Скрипт, который Claude пишет для PTC, пример Anthropic"` (раздел `code-mode`) начинается с `team = await get_team_members("engineering")` на верхнем уровне модуля. `python3 -m py_compile` даёт `SyntaxError: 'await' outside function`. Это тоже не ошибка автора: пример дословно взят из статьи Anthropic (подтверждено `research/field.md:180-194`, помечено VERBATIM) и отражает то, что песочница PTC исполняет код Claude в контексте, поддерживающем top-level `await` (не ванильный `python3 -m py_compile`). Глава нигде не уточняет, что этот скрипт не предназначен для запуска обычным интерпретатором — читатель, скопировавший пример «попробовать», получит `SyntaxError`.

**Доказательство.**
- `python3 -m py_compile block_35.py` → `SyntaxError: 'await' outside function` на строке 1 (`team = await get_team_members(...)`).
- `research/field.md:180-194` — идентичный код, маркирован `[S3, VERBATIM]`.

**Как исправить.** Не обязательно (пример верен как цитата), но можно добавить одну фразу вида «код выполняется в асинхронной песочнице PTC, а не в обычном интерпретаторе» рядом с примером — это снимет потенциальную путаницу при копировании.
